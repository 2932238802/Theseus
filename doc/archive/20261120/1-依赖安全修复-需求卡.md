## CR-004 修复 cargo audit 阻断镜像发布的依赖漏洞

- **类型**：安全修复 / 技术债
- **问题与价值**：CI 的 `cargo audit` 报 7 个漏洞，`images` 任务不执行，GHCR 不发布 `3a5322a` 镜像，服务器 `./update.sh` 拉取失败。不修复则无法部署本次面经改版。
- **目标用户与场景**：运维/开发；恢复 CI 镜像发布与服务器增量更新。
- **成功指标**：
  - `cargo audit --ignore RUSTSEC-2023-0071 --ignore RUSTSEC-2026-0459` 退出 0
  - `lettre` 升级到 `>=0.11.24`
  - `libsqlite3-sys` 在当前依赖图中未被启用，并有 CI 守卫防止未来被启用
  - `cargo fmt/clippy/test` 全绿，镜像恢复发布
- **范围**：
  - `backend-rust/Cargo.lock`：`lettre 0.11.23 → 0.11.24`（含传递依赖 `email-encoding 0.4.3`）
  - `.github/workflows/ci.yml`：新增 SQLite 未启用守卫；`cargo audit` 增加 `--ignore RUSTSEC-2026-0459`
  - 文档同步：本卡、开发文档、STATUS
- **不在范围内**：
  - 不升级 `sqlx` 大版本（0.8 → 0.9），另立任务
  - 不处理 `chrono unmaintained` 警告（当前仅 warning，不导致失败）
  - 不改业务代码
- **NFR**：安全适用（消除 6 个 lettre 漏洞 + 书面豁免未启用的 SQLite）；兼容适用（lettre patch 版本，API 不变）；性能不适用；隐私不适用；可观测不适用；成本不适用。
- **约束与依赖**：
  - `libsqlite3-sys` 来自 `sqlx` 的可选 SQLite 后端；项目只用 PostgreSQL，`cargo tree --target all -i libsqlite3-sys` 为空
  - 不能单独把 `libsqlite3-sys` 升到 0.39（与 sqlx 0.8 的 `^0.30` 不兼容），只能证明未启用并豁免
- **风险**：
  - lettre patch 升级可能有细微行为变化，用现有测试与 CI 覆盖
  - 未来若启用 SQLite feature，守卫会失败，提醒重新评估
- **选项**：
  - **A. 升级 lettre + 守卫豁免 libsqlite3-sys（用户已选）**
  - B. 升级 sqlx 0.8 → 0.9（大改，另开任务）
  - C. 直接忽略全部漏洞（不接受）
- **用户选择（2026-11-20）**：确认问题并开始修复，采用 A
- **关联任务**：T-009
- **状态**：已确认（G0）
