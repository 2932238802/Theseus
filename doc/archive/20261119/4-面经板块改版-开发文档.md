## 1. 需求

### R-001 面经正文只保留题目（P0，v1）

- **来源**：CR-001
- **背景**：现有面经正文包含答案，读者先看到答案，评论区无人参与
- **描述**：面经正文只记录题目；存量面经删除后从 `doc/interview` 重新导入无答案版本；发布页提示不写答案；答案由评论区补充
- **成功指标**：重建后面经正文无答案段；发布页有提示；重建失败可中止并恢复
- **验收标准**：
  - `AC-001-1` 执行重建脚本并确认后，`board='interview'` 的帖子全部删除，再从 `doc/interview` 重新导入；最终帖子数等于导入成功数，且大于 0
  - `AC-001-2` 重建后的正文取自 `import_interview.sh --no-answers` 的结果：不再包含 `## 题目` 下的答案正文，只保留题号与题目
  - `AC-001-3` 未传 `--yes` 时脚本只打印计划与将要删除的数量，不修改数据库
  - `AC-001-4` 导入失败时脚本非零退出，打印 `deploy/scripts/restore.sh` 恢复提示；不静默留下空板块
  - `AC-001-5` 面经发布页显示「正文不要写答案 答案由评论区补充」提示；仍可自由编辑 Markdown 并发布
  - `AC-001-6` 面经详情页显示「只收录题目 答案由评论区补充」提示；评论、点赞、收藏功能不受影响
- **NFR 影响**：性能不适用（维护窗口执行）；安全适用（管理员、二次确认、日志）；隐私不适用；兼容适用（Markdown 渲染不变）；可观测适用（输出删除/导入数量）；成本不适用
- **影响面**：`backend-rust/scripts/rebuild_interview_posts.sh`（新增）、`import_interview.sh`、`ForumComposePage.vue`、`ForumPostPage.vue`
- **不在范围内**：答案归档、后台清理页、语义拆分、结构化题目强制录入
- **变更历史**：v1 2026-11-19 初始

### R-002 面经面试类型分类（P0，v1）

- **来源**：CR-002
- **背景**：技术面与 HR 面混在一起，读者无法按类型筛选，HR 模板也缺少入口
- **描述**：面经增加单选类型 `技术面 / HR 面 / 算法面 / 主管面`；列表可筛选；发帖必选；详情展示；导入时写入
- **成功指标**：筛选结果与标签一致；发帖缺类型被拒绝；重建后面经类型无空值
- **验收标准**：
  - `AC-002-1` `GET /api/forum/posts?board=interview&interview_type=hr` 只返回类型为 HR 面的帖子；总数与筛选后条数一致
  - `AC-002-2` 发布面经缺少 `interview_type` 或传未知值时，API 返回 400 与可读错误；前端在未选择类型时禁用发布
  - `AC-002-3` 面经详情返回并展示类型标签；非面经帖子不展示类型
  - `AC-002-4` 管理员修改面经类型后，列表与详情立即反映，并写审计日志
  - `AC-002-5` 重建导入时：frontmatter `type` 合法则使用；否则按 `round` / 标题 / 标签含 HR、人力、行为面推断为 `hr`；仍无法判断默认 `technical`
  - `AC-002-6` 综合板块帖子 `interview_type` 为 NULL，列表筛选与详情行为不变
- **NFR 影响**：性能适用（类型索引）；安全不适用；隐私不适用；兼容适用（新增可空字段）；可观测不适用；成本不适用
- **影响面**：迁移 `0048_forum_interview_type.sql`；`models/forum.rs`、`forum_handler.rs`、`forum_service.rs`；`ForumPage.vue`、`ForumComposePage.vue`、`ForumPostPage.vue`；`import_interview.sh`
- **不在范围内**：多选类型、管理员自定义类型、类型统计
- **变更历史**：v1 2026-11-19 初始

### R-003 HR 面模板 Wiki（P0，v1）

- **来源**：CR-003
- **背景**：HR 面问题重复度高，需要可复用模板与套路；管理员需要可持续维护的 Wiki
- **描述**：新增 HR 面模板页，左侧扁平列表、右侧 Markdown 正文；管理员可增删改查与拖拽排序；入口只在选择 HR 面后出现；不显示 VIP / Plus 升级字样
- **成功指标**：管理员保存后读者端立即可见；顺序刷新保持；Markdown 快捷键可用；入口只在 HR 面出现
- **验收标准**：
  - `AC-003-1` 管理员在 `/admin/interview-templates` 新建模板页（标题 + Markdown 正文），保存后读者端列表出现该页
  - `AC-003-2` 管理员编辑标题或正文并保存，读者端详情立即更新；标题 1–120 字、正文 1–20000 字，超限返回 400
  - `AC-003-3` 管理员删除模板页需二次确认；删除后读者端列表移除，并写审计日志
  - `AC-003-4` 管理员拖拽左侧条目调整顺序，松手保存；刷新后顺序保持；排序接口失败时恢复原顺序并提示
  - `AC-003-5` 编辑器中 `Ctrl/Cmd+B` 加粗、`Ctrl/Cmd+I` 斜体、`Ctrl/Cmd+K` 插入链接；工具栏的标题、列表、引用、代码按钮插入对应 Markdown
  - `AC-003-6` 预览使用现有 Markdown 渲染与清洗；`<script>`、`onerror`、`javascript:` 等被移除
  - `AC-003-7` 读者端模板页的权限与面经板块一致：非 Plus 用户按现有面经权限处理，未登录跳转登录
  - `AC-003-8` 面经列表只有在选中「HR 面」时显示模板入口；选择全部 / 技术面 / 算法面 / 主管面时不显示；发布页同理
  - `AC-003-9` 模板入口、模板页、管理页均不出现 VIP / Plus 专属 / 升级字样
  - `AC-003-10` 模板页不进入普通面经列表；面经列表、详情、评论接口行为不变
- **NFR 影响**：性能适用（小数据量按需加载）；安全适用（鉴权 + Markdown 清洗 + 防 XSS）；隐私不适用；兼容适用（新增页面与表）；可观测适用（写审计日志）；成本不适用
- **影响面**：迁移 `0049_interview_templates.sql`；新增 handler/service/model；`routes/mod.rs`；前端路由、`InterviewTemplatesPage.vue`、`AdminInterviewTemplatesPage.vue`、`MarkdownEditor.vue`；`NavBar` / 面经入口
- **不在范围内**：两级分组、草稿 / 发布状态、版本历史、协同编辑、模板评论、使用统计
- **变更历史**：v1 2026-11-19 初始

## 2. 设计

### 2.1 数据模型

**迁移 `0048_forum_interview_type.sql`**

```sql
ALTER TABLE forum_posts
    ADD COLUMN IF NOT EXISTS interview_type VARCHAR(20);

ALTER TABLE forum_posts
    ADD CONSTRAINT forum_posts_interview_type_check
    CHECK (
        interview_type IS NULL
        OR (board = 'interview' AND interview_type IN ('technical', 'hr', 'algorithm', 'manager'))
    );

CREATE INDEX IF NOT EXISTS idx_forum_posts_interview_type
    ON forum_posts (interview_type)
    WHERE board = 'interview';
```

- 入库用英文枚举，展示用中文：`technical` → 技术面，`hr` → HR 面，`algorithm` → 算法面，`manager` → 主管面
- `interview_type` 的 NULL 仅为重建前过渡态：迁移不强制面经非空，避免存量库升级失败；`rebuild_interview_posts.sh` 必须在导入成功后校验 `board='interview' AND interview_type IS NULL` 计数为 0，否则失败并提示 restore（G3 返工 R2）
- 综合板块保持 NULL

**迁移 `0049_interview_templates.sql`**

```sql
CREATE TABLE IF NOT EXISTS interview_templates (
    id BIGSERIAL PRIMARY KEY,
    title VARCHAR(120) NOT NULL,
    content_md TEXT NOT NULL,
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_by INTEGER REFERENCES users(id) ON DELETE SET NULL,
    updated_by INTEGER REFERENCES users(id) ON DELETE SET NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT interview_templates_title_len CHECK (char_length(title) BETWEEN 1 AND 120),
    CONSTRAINT interview_templates_content_len CHECK (char_length(content_md) BETWEEN 1 AND 20000)
);

CREATE INDEX IF NOT EXISTS idx_interview_templates_order
    ON interview_templates (sort_order, id);
```

- 不做软删除；删除即物理删除（开发版数据，可接受）
- 排序用 `sort_order`，拖拽后按数组下标重写

### 2.2 接口契约

**读者端（与面经同级权限）**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/forum/interview/templates` | 返回 `id / title / sort_order / updated_at`，按 `sort_order, id` 排序 |
| GET | `/api/forum/interview/templates/{id}` | 返回 `id / title / content_md / sort_order / updated_at` |

**管理端（`requiresAdmin`）**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/interview/templates` | 与读者端列表同结构，可含 `content_md` |
| POST | `/api/admin/interview/templates` | `{ title, content_md }`，返回 201 与新记录 |
| PUT | `/api/admin/interview/templates/{id}` | `{ title, content_md }`，返回更新后记录 |
| DELETE | `/api/admin/interview/templates/{id}` | 删除并写审计 |
| PUT | `/api/admin/interview/templates/order` | `{ ids: [1,2,3] }`，必须覆盖全部模板 ID，按数组顺序写 `sort_order` |

**面经类型**

- `GET /api/forum/posts` 新增可选查询参数 `interview_type`，仅当 `board=interview` 时生效
- `POST /api/forum/posts` / `PUT /api/forum/posts/{id}` 新增 `interview_type`；发面经时必填，综合板块忽略
- `2026-11-20` 用户确认保留 `PUT /api/forum/posts/{id}` 的 `board` 切换（G4 P2-2）：非 Plus 不能把综合帖改为面经，改为综合板块时 `interview_type` 置空
- `GET /api/forum/posts/{id}` 返回 `interview_type`
- 管理端新增 `PUT /api/admin/forum/posts/{id}/interview-type`，body `{ interview_type }`

**错误约定**

- 未知类型：`400`，错误信息「未知的面试类型」
- 非面经帖子传类型：`400`，错误信息「只有面经板块支持面试类型」
- 模板标题/正文超限：`400`，沿用现有校验错误格式
- 非 Plus 读模板：沿用面经板块现有 403 与提示

### 2.3 前端

- 读者端路由：`/interview/templates`（`[假设]`，待 G1 确认）
- 面经列表：类型筛选 chips；选中 `HR 面` 时显示「HR 面模板与套路」入口
- 发布页：类型选择；保留自由 Markdown；显示「正文不要写答案」提示；选中 HR 面时显示模板入口
- 详情页：类型标签；「只收录题目」提示；正文继续用 `MarkdownBody`
- 管理端路由：`/admin/interview-templates`
- 编辑器：新增 `MarkdownEditor.vue`，基于 textarea + 工具栏 + 预览；`Ctrl/Cmd+B` / `I` / `K`；工具栏至少包含加粗、斜体、标题、无序列表、有序列表、引用、行内代码、链接、预览
- 拖拽排序：沿用项目现有 Pointer Events 方案，失败回滚

### 2.4 重建脚本

新增 `backend-rust/scripts/rebuild_interview_posts.sh`：

1. 前置检查：`deploy/.env`、compose、管理员账号、`doc/interview` 至少一个 Markdown
2. 未传 `--yes`：打印将删除的帖子数量与将导入的文件数，退出 0
3. 传 `--yes`：默认自动执行 `deploy/scripts/backup.sh`，备份失败立即中止；`--no-backup` 可跳过；删除 `board='interview'` 全部帖子
4. 调用 `import_interview.sh --author <管理员> --no-answers`；默认非 Docker，`--docker` 时透传（删除后无同标题可更新，不需要 `--update`）
5. 校验：导入成功数 > 0 且等于可导入文件数；否则非零退出并打印 restore 命令
6. 可导入文件为 0 时，在备份与删除前退出 2，避免清空板块
7. 不写入 `update.sh`，避免每次部署重复删除
