## CR-001 面经正文只保留题目，答案交给评论区

- **类型**：交互优化 / 内容治理
- **问题与价值**：服务器上 `https://theseus.los-thesis.site/forum/12` 这类面经把答案写在正文里，读者先看到答案，评论区无人参与；也把题目固定成一篇标准答案。改成正文只收题目后，答案由评论区补充，面经更像题库，讨论也能沉淀。
- **目标用户与场景**：
  - 读者：打开面经只看到题目，想看答案去评论区，可点赞、可采纳最佳答案
  - 发布者：发帖时只记录问题和现场情况，不写答案
  - 管理员：在维护窗口执行一次重建，删除全部面经帖并从 `doc/interview` 重新导入无答案版本
- **成功指标**：
  - 存量面经重建后，正文不再包含答案段，只剩题目
  - 新发布的面经页有明确提示，正文由发布者自行保证只写题目
  - 重建脚本失败时中止并给出恢复步骤，不留下空板块
  - 可观察场景：执行重建后，面经列表数量与 `doc/interview` 中可导入文件数一致，随机抽查 5 篇正文无答案
- **范围**：
  - 一次性数据操作：删除 `board='interview'` 的全部帖子，再执行 `import_interview.sh --no-answers`
  - 新增独立脚本 `backend-rust/scripts/rebuild_interview_posts.sh`，带二次确认、失败中止与恢复提示
  - 面经发布页：保留自由 Markdown 正文，增加「正文不要写答案」提示
  - 面经详情页：保留现有 Markdown 渲染，增加「只收录题目 答案由评论区补充」提示
- **不在范围内**：
  - 不做后台批量清理页面（用户已确认不需要）
  - 不做答案归档（不保留原文）
  - 不做语义自动判题、不做 AI 拆分答案
  - 不强制结构化「一题一条」输入
  - 不改评论区、点赞、收藏的能力与权限
- **NFR**：
  - 性能：适用，重建在维护窗口执行，脚本串行导入，不要求在线
  - 安全：适用，仅管理员执行；脚本必须显式 `--yes` 才删除；操作写审计或至少写日志
  - 隐私：不适用，不新增用户数据
  - 兼容：适用，老帖正文仍按 Markdown 渲染；评论、点赞、收藏随帖子删除
  - 可观测：适用，输出删除数量、导入成功/失败数量
  - 成本：不适用
- **约束与依赖**：
  - 当前为开发版，面经帖子为测试数据，删除不涉及真实用户数据（用户 2026-11-19 说明）
  - 删除会级联删除评论、点赞、收藏；开发期可接受，正式环境执行前必须重新评估
  - 只能重建 `doc/interview` 中存在来源的帖子；界面手发且无来源的面经会永久丢失
  - `import_interview.sh` 已支持 `--no-answers`（`import_interview.sh:58`、`:200-213`）
  - `update.sh` 不会自动执行该脚本，需要手动运行或单独加参数
- **风险与未知**：
  - 中：当前为开发版且为测试数据，删除风险可控；正式环境上线后禁止直接复用该操作
  - 中：界面手发且不在 `doc/interview` 的面经无法重建
  - 中：重建脚本中途失败会留下空板块；必须做到「导入成功后再结束」，失败时提示 restore
  - 中：`--no-answers` 依赖 `## 题目` 结构，格式不符的源文件可能保留答案
- **选项**：
  - **A. 做（用户已选）**：删除全部面经帖，从 `doc/interview` 重新导入无答案版本；发布页加提示
  - **B. 拆小**：只做发布页提示，不动存量
  - **C. 先 spike**：先在本地库验证 `--no-answers` 输出与导入数量，再上线
  - **D. 缓办**
  - **E. 不做**
- **用户选择（2026-11-19）**：删除全部面经帖后重建；不保留旧正文与评论；不需要后台批量清理页
- **待确认决策**：
  - 重建脚本是否作为 `update.sh` 的显式参数（如 `--rebuild-interview`），还是完全独立手动执行
  - 重建前是否强制再备份一次（推荐是）
- **关联需求/任务**：R-001 / T-003（G1 回填）
- **状态**：已确认（G0）
