## 2. 脚本用法与关键逻辑

### 2.1 `import_interview.sh`

用法不变，新增类型写入：

```bash
./backend-rust/scripts/import_interview.sh --author admin --no-answers
./backend-rust/scripts/import_interview.sh --author admin --update
./backend-rust/scripts/import_interview.sh --author admin --docker --update
```

类型解析顺序：

1. frontmatter `type`，忽略大小写与内部空格：
   - `technical` / `技术面` / `技术` → `technical`
   - `hr` / `HR` / `HR面` / `人力` / `行为面` → `hr`
   - `algorithm` / `算法面` / `算法` → `algorithm`
   - `manager` / `主管面` / `主管` → `manager`
2. 缺失或无法识别：`round` + 标题 + `tags` 含 `HR`（按英文词边界匹配）、`人力`、`行为面` → `hr`
3. 其余 → `technical`

写入行为：

- INSERT 与 UPDATE 都写入 `interview_type`；`--update` 幂等覆盖类型
- 原有 `--no-answers`、`tags`、`company`、`role`、`interview_date` 逻辑未改
- 新增 `interview_type` 字段前置检查，缺失时返回退出码 3 并提示迁移 0048

### 2.2 `rebuild_interview_posts.sh`

```bash
# 只读预览：打印面经帖子数、可导入文件数、将执行的操作，退出 0，不写库
./backend-rust/scripts/rebuild_interview_posts.sh

# 确认执行：默认先备份，再删除 board='interview'，再导入无答案版本
./backend-rust/scripts/rebuild_interview_posts.sh --author admin --yes

# 服务器 Docker 模式
./backend-rust/scripts/rebuild_interview_posts.sh --docker --yes

# 跳过备份（不推荐）
./backend-rust/scripts/rebuild_interview_posts.sh --author admin --yes --no-backup

# 自定义目录
./backend-rust/scripts/rebuild_interview_posts.sh --dir /path/to/interview --yes
```

关键逻辑：

1. 未传 `--yes`：只执行 SELECT 统计并打印计划，不执行备份、删除或导入
2. 传 `--yes`：
   - 未传 `--no-backup` 时调用 `deploy/scripts/backup.sh`；失败立即退出 1，不删除
   - `DELETE FROM forum_posts WHERE board = 'interview' RETURNING id`，只删面经板块，评论/点赞/收藏由外键 `ON DELETE CASCADE` 清理
   - 调用 `import_interview.sh --no-answers --author <管理员> --dir <目录> [--docker]`
   - 校验：导入命令退出码为 0、成功数 > 0、成功数 = 可导入 Markdown 数、库内面经数 = 可导入数、综合板块数量不变
   - 失败时退出 1，并打印 `deploy/scripts/restore.sh <db dump> <uploads tar.gz>`
3. 未接入 `update.sh`

安全增强（相对文档步骤）：`--yes` 且可导入文件为 0 时，在备份和删除之前直接退出 2，避免清空板块。
