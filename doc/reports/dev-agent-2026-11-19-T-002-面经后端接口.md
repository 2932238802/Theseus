## 接口清单与示例

**读者端**

```text
GET /api/forum/posts?board=interview&interview_type=hr&size=50
-> 200 { "total": 1, "posts": [{ "id": 1, "interview_type": "hr", ... }] }
非法类型 -> 400 { "error": "请求参数无效: 未知的面试类型" }
board=general + 合法类型 -> 200，忽略该筛选
```

```text
POST /api/forum/posts
{ "board":"interview", "title":"HR面经A", "body_md":"题目A", "tags":["HR"], "interview_type":"hr" }
-> 201 { "id": 1, "status": "published" }
面经缺类型 -> 400 "请求参数无效: 面经必须选择面试类型"
综合板块带类型 -> 400 "请求参数无效: 只有面经板块支持面试类型"
```

```text
PUT /api/forum/posts/{id}
{ "board":"general", "title":"...", "body_md":"...", "tags":["general"] }
-> 200；board 改为 general 时 interview_type 置 NULL
{ "board":"interview", ..., "interview_type":"hr" } -> 200
面经缺类型 -> 400；未知板块 -> 400 "请求参数无效: 未知的板块"
```

```text
GET /api/forum/posts/{id} -> 200，摘要/详情含 interview_type（综合帖子为 null）
PUT /api/admin/forum/posts/{id}/interview-type
{ "interview_type":"manager" }
-> 200 { "id":1, "interview_type":"manager", "message":"面试类型已更新" }
非面经帖子 -> 400 "只有面经板块支持面试类型"；未知值 -> 400 "未知的面试类型"；不存在 -> 404
```

**模板读者端**

```text
GET /api/forum/interview/templates
-> 200 [ { "id":1, "title":"STAR 四步法", "sort_order":0, "updated_at":"..." } ]
GET /api/forum/interview/templates/{id}
-> 200 { "id":1, "title":"...", "content_md":"...", "sort_order":0, "created_at":"...", "updated_at":"..." }
未登录 401；非 Plus 403 "需要开通 Plus Theseus 才能查看面经"；不存在 404
```

**模板管理端**

```text
GET    /api/admin/interview/templates          -> 200，含 content_md，按 (sort_order,id)
POST   /api/admin/interview/templates          { "title","content_md" } -> 201 新记录，追加到末尾
PUT    /api/admin/interview/templates/{id}     { "title","content_md" } -> 200 更新后记录
DELETE /api/admin/interview/templates/{id}     -> 200 { "id", "message":"模板已删除" }
PUT    /api/admin/interview/templates/order    { "ids":[2,1] } -> 200 { "message":"模板顺序已更新" }
标题 1–120、正文 1–20000；空/超限 400；不存在 404；必须覆盖全部模板 ID
```

## 偏差与假设

- [偏差] `UpdatePostRequest` 新增可选 `board`：原模型没有该字段，但任务要求「更新时把 board 改为 general/interview」的语义；前端 `ForumPostPayload` 已传 board，属于向后兼容的新增入参。
- [假设] 非 Plus 用户把自己的综合帖改为面经时返回 403，避免借编辑绕过 Plus；已有面经作者仍可正常编辑自己的帖子。
- [假设] 列表 `interview_type` 为合法值但 `board=general` 时忽略筛选；未知值始终 400。
- [假设] 新模板追加到末尾（`MAX(sort_order)+1`），避免新页插到首位。
- [假设] 标题与正文保存前 trim；仅空白视为空并返回 400。
- [假设] 读者模板详情沿用 T-001 模型，额外返回 `created_at`；契约字段为超集。
- [假设] 审计只记录标题/排序/类型等元数据，不写 20k 正文，避免审计膨胀。
- [假设] 重排不更新 `updated_at`，保留内容编辑时间。
- [说明] 错误信息沿用现有 `AppError::BadRequest` 前缀「请求参数无效: 」，要求的文案作为子串出现。
