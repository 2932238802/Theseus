> 版本：v1.1  
> 日期：2026-10-31  
> 状态：已实现（2026-10-26），`npm run build` 通过；浏览器手工测试矩阵待执行  
> 当前实现基线：`0a00582` + 工作区教学模块未提交改动 + 草稿快捷保存（v1.1）  
> 关联文档：`frontend-vue/README.md`「界面文案规范」、`doc/2610259_班级与作业设计方案.md`  
> 范围：OJ 题目页代码编辑器的快捷键、自定义设置面板、快捷键手册；不涉及后端

> v1.1 变更：新增 `oj.save-draft`（默认 `Mod+S`），在题目页按 Ctrl/⌘+S 立即保存草稿到本地并同步云端，同时拦截浏览器「保存网页」默认行为；编辑器聚焦时由 Monaco 键位触发，页面其它焦点由 `window` 捕获监听触发，避免重复执行。

> 实现说明：注册表、持久化、弹窗、Monaco 动态键位和页面级监听已按本方案落地。Monaco 行为结论已从 0.57 源码确认：`addKeybindingRules` 以 `weight1: 1000` 追加在默认键位之后，解析时后加入的规则优先；`command: null` 会命中并吞掉该键的 Monaco 动作（不执行、不 `preventDefault`）。实际按键效果仍需在浏览器中走完第 9 节矩阵。

## 0. 结论速览

| 决策项 | 本期选择 |
|---|---|
| 编辑器 | Monaco 0.57，目前仅 OJ 题目页使用 |
| 自定义范围 | OJ 应用动作 + 精选编辑器动作；撤销/复制粘贴等系统键只读 |
| 默认运行键 | `Mod+Enter` |
| 默认提交键 | `Mod+Shift+Enter` |
| 默认保存草稿键 | `Mod+S`（同时拦截浏览器保存网页） |
| 保存方式 | 浏览器 `localStorage`，不新增后端表或接口 |
| 入口 | OJ 页内弹窗，分「设置」和「手册」两个标签 |
| 冲突策略 | 可自定义动作之间全局唯一；拒绝浏览器保留键和只读系统键 |
| 手册 | 与设置共用同一份注册表，修改后立即同步 |
| 作用域 | `editor`（编辑器聚焦）与 `oj`（题目页）两类 |
| 多键序列 | 不支持，如 `Ctrl+K Ctrl+S` |
| 账号同步 | 不支持，配置仅保存在当前浏览器 |
| 测试 | 前端暂无测试框架，使用构建 + 手工测试矩阵 |

**一句话总结：** 以一份集中式快捷键注册表同时驱动 Monaco 键位、OJ 页面动作、设置面板和手册，配置只存浏览器本地，做到「改一处，编辑器、按钮提示和手册同时生效」。

## 1. 目标与非目标

### 1.1 目标

1. 让运行、提交两个高频动作可以直接用键盘完成，不依赖鼠标。
2. 保留 Monaco 常用的编辑快捷键，并在手册中准确列出。
3. 允许用户修改应用动作和精选编辑器动作的键位。
4. 键位冲突、浏览器保留键、只读系统键在设置阶段就被拦截，而不是运行时静默失效。
5. 手册随自定义实时更新，并能区分默认键、自定义键和不可修改的系统键。
6. 不改变现有运行、提交、作业截止和权限判断逻辑，快捷键只做触发入口。
7. 不新增后端依赖；清空浏览器数据后恢复默认键位。

### 1.2 非目标

本轮明确不做：

- 全站导航快捷键，例如 `g p` 跳转题库、`g f` 跳转论坛；
- 多键序列快捷键；
- Vim / Emacs 键位模式；
- 账号级同步、导入导出；
- 自定义撤销、重做、复制、粘贴、剪切、全选、Tab 缩进等系统键；
- 鼠标手势或快捷键提示浮层；
- 后端存储用户偏好；
- 自动化前端测试框架。

## 2. 现状与约束

### 2.1 现有代码

| 位置 | 现状 |
|---|---|
| `frontend-vue/src/components/CodeEditor.vue` | 通过 `@monaco-editor/loader` 初始化 Monaco；只接收 `modelValue`、`language`、`fontSize`、`dark`；没有暴露实例或命令接口 |
| `frontend-vue/src/views/OjPage.vue` | 唯一使用 `CodeEditor` 的页面；已有 `submitCode`、`openRunDialog`、`startRun`、`resetCode`、`isOutputOpen` 等动作 |
| `frontend-vue/src/router/index.ts` | 题目页 `/problem/:id` 对所有用户开放 |
| `frontend-vue/src/style.css` | 已有 `modal-backdrop`、`run-dialog` 等弹窗样式 |
| `frontend-vue/src/utils/session.ts` | 已有 `localStorage` 访问封装；快捷键不必复用 session，避免和登录状态耦合 |

### 2.2 Monaco 默认行为

Monaco 当前版本为 `0.57.0`，已确认存在以下 API：

```ts
monaco.editor.addCommand({ id, run })
monaco.editor.addKeybindingRules(rules)
```

`addKeybindingRules` 是全局动态规则，`command: null` 表示解绑。规则的 `when` 使用上下文表达式，例如 `editorTextFocus`。

需要在实现时特别处理的默认键：

| 默认键 | Monaco 行为 | 本方案处理 |
|---|---|---|
| `Ctrl/Cmd+Enter` | 向下插入一行 | 默认覆盖为「运行代码」 |
| `Ctrl/Cmd+Shift+Enter` | 向上插入一行 | 默认覆盖为「提交代码」 |
| `Mod+F` | 查找 | 保留，允许改键 |
| `Mod+H` | 替换 | 保留，允许改键 |
| `Mod+/` | 行注释 | 保留，允许改键 |
| `Shift+Alt+F` | 格式化文档 | 保留，允许改键 |
| `Shift+Alt+Down` | 向下复制行 | 保留，允许改键 |
| `Alt+Up/Down` | 上移/下移行 | 保留，允许改键 |
| `Mod+Shift+K` | 删除行 | 保留，允许改键 |
| `Mod+D` | 选中下一个相同项 | 保留，允许改键 |

当应用动作改到其他键后，原 `Ctrl/Cmd+Enter` 的 Monaco 默认「插入行」行为应恢复，避免永久占用一个编辑键。也就是说，动态规则只在当前动作实际使用该键时注册。

### 2.3 约束

- 用户可能使用中文输入法，捕获键位时必须忽略 `isComposing`。
- 浏览器保留键无法可靠拦截，例如 `Mod+W`、`Mod+T`、`Mod+N`。
- Monaco 在编辑器聚焦时能拦截大多数浏览器按键，但页面级动作不能。
- 前端没有测试框架，`npm run build` 已包含 `vue-tsc` 类型检查。
- 界面文案遵守 `frontend-vue/README.md`：不写解释性副标题，保留校验、错误和空状态提示。

## 3. 交互模型

### 3.1 作用域

| 作用域 | 定义 | 触发方式 |
|---|---|---|
| `editor` | 仅在 Monaco 编辑器聚焦时生效 | Monaco 动态键位规则 |
| `oj` | 在 OJ 题目页任意位置生效，但不包括输入控件和弹窗 | 页面级 `window.keydown` |

`oj` 作用域覆盖范围更大，但编辑器聚焦时由 Monaco 优先处理。页面级监听器通过事件目标判断是否位于 `.monaco-editor` 内，避免同一按键触发两次。

### 3.2 触发流程

```text
按键按下
  ├─ 快捷键捕获状态？
  │    └─ 是：捕获并保存，阻止默认行为与冒泡
  ├─ 运行弹窗 / 快捷键弹窗打开？
  │    └─ 是：不触发页面动作
  ├─ 焦点在 Monaco 编辑器内？
  │    └─ 是：Monaco 动态命令处理 editor/oj 动作
  ├─ 焦点在 input / textarea / select / contenteditable？
  │    └─ 是：不触发页面动作
  └─ 匹配 oj 动作
       └─ 执行页面动作
```

### 3.3 忽略条件

页面级监听器在以下情况直接返回：

- `event.defaultPrevented`；
- `event.isComposing`；
- `event.repeat`（运行、提交、重置等动作不响应长按）；
- 弹窗打开（运行弹窗、快捷键弹窗）；
- 焦点在 `input`、`textarea`、`select`、`[contenteditable="true"]`；
- 焦点位于 `.monaco-editor` 内；
- 当前没有加载题目。

编辑器命令本身由 Monaco 管理，不重复判断输入控件。

### 3.4 动作可用性

快捷键不绕过现有业务判断，直接复用页面函数：

- 未登录运行/提交：跳转登录页并携带 `redirect`；
- 运行功能关闭、题目无运行配置：不执行；
- 运行中或评测中：不执行；
- 作业已截止、草稿、归档或当前角色不可提交：提交无效；
- 提交内容为空：不执行。

## 4. 默认键位

### 4.1 OJ 应用动作（可自定义）

| 动作 ID | 名称 | 默认键 | 行为 |
|---|---|---|---|
| `oj.run` | 运行代码 | `Mod+Enter` | 有公开用例时直接运行示例；没有公开用例时打开自定义输入弹窗 |
| `oj.submit` | 提交代码 | `Mod+Shift+Enter` | 复用 `submitCode` |
| `oj.save-draft` | 保存草稿 | `Mod+S` | 立即写入本机草稿并同步云端，同时阻止浏览器保存网页；未登录或比赛模式只保存到本机 |
| `oj.toggle-output` | 展开/收起结果 | `Mod+\`` | 切换 `isOutputOpen` |
| `oj.reset-code` | 重置代码 | 未绑定 | 复用 `resetCode` |
| `oj.open-shortcuts` | 快捷键面板 | 未绑定 | 打开设置/手册弹窗 |

运行动作与按钮的差异：按钮始终打开运行弹窗；快捷键优先直接运行公开示例，只有没有公开用例时才打开弹窗。这样避免每次 `Mod+Enter` 都要再点一次「运行」。

### 4.2 编辑器动作（可自定义）

| 动作 ID | 名称 | 默认键 | Monaco 命令 |
|---|---|---|---|
| `editor.find` | 查找 | `Mod+F` | `actions.find` |
| `editor.replace` | 替换 | `Mod+H` | `editor.action.startFindReplaceAction` |
| `editor.comment-line` | 切换行注释 | `Mod+/` | `editor.action.commentLine` |
| `editor.format-document` | 格式化文档 | `Shift+Alt+F` | `editor.action.formatDocument` |
| `editor.copy-line-down` | 向下复制行 | `Shift+Alt+↓` | `editor.action.copyLinesDownAction` |
| `editor.move-line-up` | 上移行 | `Alt+↑` | `editor.action.moveLinesUpAction` |
| `editor.move-line-down` | 下移行 | `Alt+↓` | `editor.action.moveLinesDownAction` |
| `editor.delete-line` | 删除行 | `Mod+Shift+K` | `editor.action.deleteLines` |
| `editor.select-next-occurrence` | 选中下一个相同项 | `Mod+D` | `editor.action.addSelectionToNextFindMatch` |

格式化只对 Monaco 已注册格式化器的语言生效；C++、Java 等语言没有内置格式化器时，快捷键不会产生效果，手册中注明这一点。

### 4.3 只读系统键

以下快捷键固定为 Monaco 默认，不出现在设置列表中，仅在手册中展示：

| 名称 | 键位 |
|---|---|
| 撤销 | `Mod+Z` |
| 重做 | `Mod+Shift+Z` / `Mod+Y` |
| 剪切 | `Mod+X` |
| 复制 | `Mod+C` |
| 粘贴 | `Mod+V` |
| 全选 | `Mod+A` |
| 减少缩进 | `Shift+Tab` |
| 增加缩进 | `Tab` |
| 命令面板 | `F1` |
| 跳转到行 | `Mod+G` |
| 添加上下光标 | `Mod+Alt+↑/↓` |
| 按词移动 | `Mod+←/→` |
| 行首/行尾 | `Home` / `End` |

这些键同时作为冲突校验的保留集合，不允许被自定义动作占用。

## 5. 自定义设置面板

### 5.1 入口与布局

- 入口：OJ 编辑器工具栏新增「快捷键」按钮，打开 `ShortcutDialog`。
- 弹窗复用现有 `modal-backdrop` 与 `run-dialog` 结构，增加两个标签：
  - **设置**：可修改的动作列表；
  - **手册**：完整键位说明。
- 默认打开「设置」；从工具栏打开时保留上次标签，或固定打开设置。本期固定打开设置，手册通过标签切换。

### 5.2 设置列表

按分组展示：

```text
运行与提交   运行代码、提交代码、展开/收起结果、重置代码、快捷键面板
保存         保存草稿
编辑         查找、替换、切换行注释、格式化文档、复制行、上移/下移行、删除行、选中下一个相同项
```

每行包含：

- 动作名称；
- 当前键位的 `<kbd>` 展示；
- 「修改」按钮；
- 已自定义时显示「重置」按钮。

底部提供「全部恢复默认」。

### 5.3 捕获流程

1. 点击「修改」进入捕获状态，该行显示「按下新的组合键…」。
2. 下一个 `keydown`：
   - `Escape`：取消捕获，保留原键位；
   - `Backspace` / `Delete`：清除绑定；
   - 其他组合：校验通过后立即保存并退出捕获。
3. 捕获期间阻止默认行为和事件冒泡，避免触发浏览器或 Monaco 动作。
4. 点击其他「修改」按钮或关闭弹窗时取消当前捕获。
5. 窗口失焦时取消捕获。

### 5.4 校验规则

保存前依次校验：

1. **可解析**：必须是允许的键位格式。
2. **含修饰键**：至少包含 `Mod` 或 `Alt`；单独字母、数字、`Shift+字母` 不允许。
3. **非修饰键本身**：不能只按 `Ctrl`、`Shift`、`Alt`、`Mod`。
4. **不与只读系统键冲突**：例如 `Mod+Z`、`Mod+C`、`Tab`。
5. **不与浏览器保留键冲突**：见 5.6。
6. **不与任何可自定义动作重复**：跨作用域也算冲突，例如 `oj.run` 不能绑定为 `Mod+F`。
7. **同作用域内唯一**：最终以全局唯一处理。

校验失败时停留在捕获状态或退出捕获，并在行内显示具体原因，例如：

```text
与「提交代码」冲突
该快捷键被浏览器占用
该快捷键不可修改
快捷键需要包含 Ctrl/⌘ 或 Alt
```

### 5.5 解除绑定

- 允许应用动作和编辑器动作解除绑定。
- 解除后动作仍可通过按钮或菜单使用。
- 解除编辑器动作时，需要同时解绑其默认键；否则默认键仍会触发 Monaco 原命令。
- 解除应用动作时，如果该键原本覆盖了 Monaco 默认行为，移除动态规则后默认行为恢复。

### 5.6 保留键

**浏览器保留键（拒绝）**

```text
Mod+W, Mod+Shift+W
Mod+T, Mod+Shift+T
Mod+N, Mod+Shift+N
Mod+R, Mod+Shift+R
Mod+L
Mod+O, Mod+Shift+O
Mod+S, Mod+Shift+S
Mod+P, Mod+Shift+P
Mod+Shift+I, Mod+Shift+J, Mod+Shift+C, Mod+Shift+K
F5, F11, F12
Alt+F4, Alt+Tab
Mod+Tab
Mod+1 ... Mod+9
```

**作用域差异**

- `oj` 作用域还会拒绝 `Mod+D`、`Mod+F`、`Mod+H`、`Mod+G` 等浏览器/编辑器常用键，避免页面级监听劫持。
- `editor` 作用域允许 `Mod+D`、`Mod+F` 等键，因为 Monaco 在聚焦时会拦截浏览器默认行为。
- 无论作用域，`Mod+W`、`Mod+T`、`Mod+N`、`F11`、`F12` 等无法可靠拦截的键都拒绝。

**只读系统键（拒绝）**

除 4.3 列表外，以下 Monaco 核心编辑键也视为保留：

```text
Mod+←/→        按词移动
Mod+Shift+←/→  按词选择
Mod+Home/End   文档首尾
Mod+Shift+Home/End
Shift+Home/End
PageUp/PageDown
Mod+Up/Down    文档首尾
```

保留集合集中维护在 `RESERVED_SHORTCUTS` 中，设置面板和手册共用。

### 5.7 持久化

存储键：

```text
theseus-shortcuts-v1
```

结构：

```json
{
  "version": 1,
  "bindings": {
    "oj.run": "Mod+Enter",
    "editor.comment-line": "Alt+C",
    "oj.reset-code": null
  }
}
```

规则：

- 只保存与默认值不同的覆盖项；
- `null` 表示用户主动解除绑定；
- 读取时逐项校验，非法项丢弃并回退默认值；
- `version` 不匹配时整体回退默认值，避免旧格式污染；
- 解析失败不抛出异常，直接使用默认键位；
- 「全部恢复默认」删除存储键并重置内存状态；
- 配置按浏览器保存，不按账号隔离；同一浏览器切换账号会共用同一套键位。

### 5.8 键位格式

内部统一使用规范字符串：

```text
Mod+Shift+Alt+Key
```

修饰键顺序固定为 `Mod` → `Shift` → `Alt` → 主键。展示时：

- Windows/Linux：`Mod` 显示为 `Ctrl`；
- macOS：`Mod` 显示为 `⌘`；
- 方向键显示为 `↑`、`↓`、`←`、`→`；
- `Enter`、`Escape`、`Space`、`Tab`、`Backspace`、`Delete` 等使用可读名称。

允许的主键：

```text
A-Z, 0-9
Enter, Escape, Tab, Space, Backspace, Delete, Home, End, PageUp, PageDown
ArrowUp, ArrowDown, ArrowLeft, ArrowRight
F2-F4, F6-F10
/, \, `, -, =, [, ], ;, ', ,, .
```

`F1`、`F5`、`F11`、`F12` 不作为可绑定键。

### 5.9 平台与输入法

- macOS 的 `Cmd` 和 Windows/Linux 的 `Ctrl` 都映射为 `Mod`，配置可跨平台复用。
- 捕获时忽略 `isComposing`、`Dead`、`Process`、`Unidentified`。
- 标点键按 US 布局映射到 Monaco `KeyCode`；非 US 布局可能在个别键上显示不一致，本期不专门适配。
- 同时按下 `Ctrl` 和 `Cmd` 时拒绝，视为无效组合。

## 6. 快捷键手册

### 6.1 内容结构

手册按以下分组展示：

```text
运行与提交
保存
编辑
查找与替换
视图
系统键（只读）
```

每条包含：

- 动作名称；
- 规范键位；
- 作用域标签（「编辑器」或「题目页」）；
- 自定义标记（若与默认值不同）；
- 只读标记（系统键）。

### 6.2 实时同步

- 手册与设置读取同一份 Pinia 状态和动作注册表。
- 修改键位后无需刷新，手册立即显示新键位。
- 解除绑定的动作显示「未绑定」。
- 手册不列未实现的动作，不写「即将支持」之类的占位文案。

### 6.3 展示细节

- 使用 `<kbd>` 标签渲染键位，连续键位用 `+` 分隔。
- 在 macOS 上显示 `⌘`，其他平台显示 `Ctrl`。
- 编辑器动作注明「仅编辑器聚焦」。
- 格式化文档注明「仅对支持格式化的语言生效」。
- 只读系统键不提供「修改」按钮。

辅助函数：

```ts
parseShortcut(value: string): ParsedShortcut | null
```

`ParsedShortcut` 至少包含：

```ts
interface ParsedShortcut {
  mod: boolean

}
```

### 7.3 Pinia Store

```ts
useShortcutStore()
  bindings: Record<string, string | null>   // 仅覆盖项
  resolved: ComputedRef<Record<string, string | null>>
  setBinding(actionId, key)
  resetBinding(actionId)
  resetAll()
  load()
```

- Store 初始化时读取 `localStorage`。
- `setBinding` 内部调用 `validateBinding`，失败时抛出或返回错误信息，由弹窗展示。
- Store 不做 Monaco 操作，保持纯状态和校验。
- `resolved` 将默认值与覆盖项合并，供设置面板、手册和页面监听共同使用。

### 7.4 Monaco 集成

`CodeEditor.vue` 新增：

- `defineExpose({ focus })`；
- 在 `loader.init()` 后保存 `monaco` 命名空间；
- 注册应用命令：

```ts
monaco.editor.addCommand({
  id: 'theseus.shortcut.run',
  run: () => emit('shortcut', 'oj.run'),
})
```

应用命令通过 `emit('shortcut', actionId)` 抛给 `OjPage`，避免把业务逻辑放进编辑器组件。

- 根据当前 `bindings` 注册动态键位：

```ts
const rules = []
if (runKey) rules.push({
  keybinding: toMonacoKeybinding(runKey),
  command: 'theseus.shortcut.run',
  when: 'editorTextFocus',
})
if (submitKey) rules.push({
  keybinding: toMonacoKeybinding(submitKey),
  command: 'theseus.shortcut.submit',
  when: 'editorTextFocus',
})
const disposable = monaco.editor.addKeybindingRules(rules)
```

- 每次绑定变化或组件卸载时先释放上一组规则，再注册新规则，保证不会叠加。
- 编辑器动作使用命令 ID 映射：

```ts
rules.push({
  keybinding: toMonacoKeybinding(newKey),
  command: action.monacoCommand,
  when: 'editorTextFocus',
})
if (newKey !== action.defaultKey) {
  rules.push({
    keybinding: toMonacoKeybinding(action.defaultKey),
    command: null,
    when: 'editorTextFocus',
  })
}
```

- 解除绑定时注册 `defaultKey -> null`，防止默认命令继续触发。
- 应用动作不再占用 `Mod+Enter` 时，不注册任何 `Mod+Enter -> null` 规则，让 Monaco 默认「向下插入一行」恢复。
- 静态应用命令在组件卸载时 dispose。

实现时需验证：

1. 动态规则是否优先于 Monaco 默认键；
2. `command: null` 是否能可靠解绑默认键；
3. 多条规则同时匹配时的执行顺序。

若 `addKeybindingRules` 在运行时不满足预期，退回到 `editor.addCommand(keybinding, handler)` 逐编辑器注册应用动作，编辑器动作仍使用动态规则。

### 7.5 OJ 页面接入

`OjPage.vue` 新增：

- `shortcutStore` 与 `ShortcutDialog` 状态；
- `handleShortcut(actionId)` 统一分发；
- `window.keydown` 监听器（`onMounted` 注册，`onBeforeUnmount` 清理）；
- 编辑器组件 `@shortcut` 事件。

分发逻辑：

```ts
const handleShortcut = (actionId: string): void => {
  if (actionId === 'oj.run') {
    void quickRun()
    return
  }
  if (actionId === 'oj.submit') {
    void submitCode()
    return
  }
  if (actionId === 'oj.save-draft') {
    void saveDraftNow()
    return
  }
  if (actionId === 'oj.toggle-output') {
    isOutputOpen.value = !isOutputOpen.value
    return
  }
  if (actionId === 'oj.reset-code') {
    resetCode()
    return
  }
  if (actionId === 'oj.open-shortcuts') {
    openShortcutDialog()
  }
}
```

`quickRun`：

```text
未登录 -> 跳登录
canRun 为 false -> 返回
runStore.isRunning -> 返回
有公开用例 -> 调用 runStore.run(..., 'examples')
无公开用例 -> 打开自定义输入弹窗
```

页面级监听器：

```ts
const onKeydown = (event: KeyboardEvent): void => {
  if (event.defaultPrevented || event.isComposing || event.repeat) return
  if (isDialogOpen.value || isShortcutDialogOpen.value) return
  if (isTypingTarget(event.target)) return
  if (isInsideMonaco(event.target)) return
  for (const [actionId, key] of Object.entries(shortcutStore.resolved)) {
    if (!key) continue
    if (matchesShortcut(event, key)) {
      event.preventDefault()
      handleShortcut(actionId)
      return
    }
  }
}
```

`isTypingTarget` 检查 `input`、`textarea`、`select`、`[contenteditable="true"]`；`isInsideMonaco` 检查 `closest('.monaco-editor')`。

### 7.6 ShortcutDialog

Props / emits：

```ts
defineProps<{ open: boolean }>()
```

内部状态：

捕获监听：

## 8. 边界与异常

| 场景 | 处理 |
|---|---|
| 本地存储损坏 | 回退默认键位，不阻塞页面 |
| 未知动作 ID | 忽略该覆盖项 |
| 动作被删除或改名 | 旧 ID 覆盖项在加载时丢弃 |
| 用户解除全部绑定 | 动作仍可通过按钮使用 |
| 捕获时按浏览器保留键 | 拒绝并提示 |
| 捕获时按输入法组合键 | 忽略，继续等待 |
| 弹窗打开时按运行键 | 不触发页面动作 |
| 运行弹窗输入框中按运行键 | 不触发页面动作 |
| 作业不可提交时按提交键 | 复用现有判断，静默不执行 |
| 运行/提交进行中重复按键 | `event.repeat` 与业务状态双重拦截 |
| 切换题目 | 页面监听器保持，动作读取新题目状态 |
| 离开题目页 | 清理监听器与弹窗状态 |
| 多标签页同时修改 | 各自保存，不监听 `storage` 事件；刷新后以最后写入为准 |
| macOS 与 Windows 共用配置 | `Mod` 抽象保证可复用 |
| 非 US 键盘布局 | 标点键可能显示不一致，本期不专门处理 |

## 10. 风险与备选

| 风险 | 影响 | 缓解 |
|---|---|---|
| `addKeybindingRules` 行为与预期不符 | 应用动作可能和 Monaco 默认命令同时触发 | 实现时先做最小验证；失败则改用 `editor.addCommand(keybinding, handler)` 注册应用动作 |
| `command: null` 无法完全解绑 | 改键后旧键仍触发 | 用 `addCommand` 覆盖旧键为空操作，并在手册中记录 |
| 浏览器保留键无法拦截 | 用户设置后按键无效 | 设置阶段直接拒绝 |
| 标点键跨布局不一致 | 部分键盘无法按出手册显示的键 | 文档注明 US 布局；优先使用字母和方向键 |
| localStorage 被清空 | 自定义丢失 | 手册与 README 说明；后续可考虑导入导出 |
| 页面级监听与 Monaco 重复触发 | 一次按键执行两次 | `closest('.monaco-editor')` 判断 + `event.defaultPrevented` |
| 手册与实际不一致 | 用户困惑 | 手册只渲染注册表；新增动作必须同时进注册表和实现 |

**后续可扩展但不进本期：**

- 账号同步与导入导出；
- 全站导航快捷键；
- 多键序列；
- 用户自定义主题联动；
- 快捷键使用频率统计。
