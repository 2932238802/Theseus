# 审计中心设计方案

> 日期：2026-10-30
> 状态：已完成（v1）
> 关联：`doc/总体设计.md` §2.3、§4.11、§7.6、`doc/backend_api.md`「审计日志接口」
> 迁移：`backend-rust/migrations/0026_audit_logs.sql`

## 1. 目标与范围

审计中心把平台敏感操作统一留痕，给管理员一个可筛选、可追溯、可导出的入口。v1 只做「写日志 + 管理员查询/导出」，不提供修改或删除审计记录的接口。

| 项目 | v1 行为 |
|---|---|
| 记录范围 | 登录、用户角色/状态/信誉分/删除、题目创建/投稿/审核/修改/删除、成绩修改与发布、通知广播、论坛审核与禁言、作弊复核与申诉、赛事与监考复核、审计导出 |
| 查询权限 | 仅 `admin` |
| 教师范围 | 设计上教师只能查看与自己组织相关的操作；v1 先不开放教师查询入口 |
| 教学数据 | 审计记录不保存完整题面、隐藏用例、源码、分数或评语 |
| 保留 | 只追加；建议至少保留 1 年，由运维按需归档 |
| 导出 | 当前筛选条件，CSV（UTF-8 BOM），最多 10,000 行 |

## 2. 数据模型

`audit_logs`：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `actor_id` | 操作者；用户被删除后置空 |
| `actor_username` / `actor_role` | 写入时快照，用户改名或删除后仍可追溯 |
| `action` | 动作标识，`domain.verb`，例如 `user.role_change` |
| `target_type` / `target_id` | 操作对象类型与 id |
| `summary` | 人类可读摘要 |
| `before` / `after` | 关键字段的前后快照（JSONB），只放可复核元数据 |
| `ip` | 取自 `X-Forwarded-For` 首个地址或 `X-Real-IP` |
| `user_agent` | 截断到 512 字符 |
| `created_at` | 写入时间 |

索引：`(created_at DESC, id DESC)` 默认分页；`(actor_id, created_at DESC)`；`(action, created_at DESC)`；`(target_type, target_id, created_at DESC)`。

审计日志不设数据库级 UPDATE/DELETE 触发器，避免阻塞运维归档与测试清理；应用层不暴露任何修改/删除路径。

## 3. 写入路径

`backend-rust/src/services/audit_service.rs` 提供两套写入：

- `record(pool, actor, context, entry)`：业务操作成功后尽力写入，失败只打 `warn` 日志，不影响主流程；
- `record_tx(&mut tx, actor, context, entry)`：与业务操作同事务提交，审计失败则整体回滚，用于信用/角色等强一致场景。

请求元数据由 `AuditContext::from_headers` 从请求头提取。`AuthUser` 新增 `username` 字段，使写入时无需额外查询即可保存操作者快照。

### 3.1 已接入动作

| `action` | 入口 | 目标 |
|---|---|---|
| `auth.login` | 登录成功 | `user` |
| `user.role_change` | 管理员变更角色 | `user` |
| `user.status_change` | 管理员启用/禁用 | `user` |
| `user.reputation_restore` | 管理员恢复信誉分 | `user` |
| `user.delete` | 管理员删除用户 | `user` |
| `problem.create` | 管理员创建官方题 | `problem` |
| `problem.submit` | 学生/教师个人出题 | `problem` |
| `problem.review` | 管理员审核通过/拒绝 | `problem` |
| `problem.update` / `problem.delete` | 管理员维护题目 | `problem` |
| `grade.problem_update` | 教师修改单题批改 | `assignment` |
| `grade.overall_update` | 教师修改整体评语 | `assignment` |
| `grade.publish` | 教师发布成绩 | `assignment` |
| `notification.send` | 教师/管理员发送通知 | `notification` |
| `forum.post_status` / `forum.comment_status` | 论坛隐藏/恢复 | `forum_post` / `forum_comment` |
| `forum.pin` | 置顶/取消置顶 | `forum_post` |
| `forum.report_decide` | 处理举报 | `forum_report` |
| `forum.mute` / `forum.unmute` | 禁言/解除禁言 | `user` |
| `anticheat.review` | 教师复核相似度报告 | `cheat_report` |
| `anticheat.appeal_submit` / `anticheat.appeal_resolve` | 学生申诉 / 处理人裁定 | `cheat_report` / `appeal` |
| `contest.proctor_review` | 管理员复核监考事件 | `contest` |
| `contest.event_create` / `contest.event_update` | 管理员创建/更新赛事 | `contest_event` |

成绩相关动作只记录「谁在何时改了哪份作业的哪名学生/题目」，不保存分数与评语，避免管理员借审计接口读取教学数据。

## 4. 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/admin/audit-logs` | 管理员 | 分页查询 |
| GET | `/api/admin/audit-logs/meta` | 管理员 | 动作与对象类型的去重计数，供筛选下拉 |
| GET | `/api/admin/audit-logs/export` | 管理员 | 导出当前筛选 CSV |

查询参数：

| 参数 | 说明 |
|---|---|
| `page` / `size` | 默认 1 / 20，`size` 上限 100 |
| `action` | 精确匹配动作 |
| `target_type` | 精确匹配对象类型 |
| `actor_id` | 精确匹配操作者 |
| `q` | 模糊匹配操作者、动作、摘要、IP |
| `from` / `to` | `YYYY-MM-DD` 或 RFC3339；日期按 UTC 整天处理 |

返回 `AuditLogListResponse { total, page, size, logs[] }`。导出列：时间、操作者、角色、动作、对象类型、对象ID、摘要、变更前、变更后、IP、User-Agent。

导出本身写一条 `audit.export`，摘要记录动作/对象/关键词筛选条件。

## 5. 前端

| 路由 | 页面 | 说明 |
|---|---|---|
| `/admin/audit` | 管理端「审计日志」 | 顶部「管理」菜单与页面搜索入口 |

页面沿用 `teaching-page`、`admin-panel`、`admin-content-filters`、`admin-users-table` 与手写 CSS：

- 关键词、动作、对象、起止日期筛选；
- 分页表格展示时间、操作者、动作、对象、摘要、IP；
- 「查看」弹窗展示操作者、User-Agent、摘要与变更前后 JSON；
- 「导出 CSV」按当前筛选下载，最多 10,000 行。

## 6. 测试

- 单元测试：日期边界解析、非法时间、CSV 转义、LIKE 通配符转义；
- 冒烟：`backend-rust/scripts/smoke_audit.sh`
  - 非管理员访问返回 403；
  - 管理员变更用户状态后能在审计列表中按动作 + 关键词筛选到记录；
  - 动作元数据包含 `user.status_change`；
  - 未来时间范围返回 0；
  - 导出返回 UTF-8 BOM CSV 且包含表头。

## 7. 已知限制与后续

- 未开放教师按组织范围查询；当前只给管理员；
- 未做日志归档、保留期清理与防篡改哈希链；
- 未覆盖组织、作业配置等全部写操作，后续按「管理端所有写操作审计」补齐；
- 未提供按操作者/IP 聚合的风险视图与告警；
- 登录审计会随登录量增长，生产环境应配合分区或归档。
