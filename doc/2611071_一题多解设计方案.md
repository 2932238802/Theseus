# 一题多解设计方案

> 日期：2026-11-07
> 状态：已实现（v1）
> 关联迁移：`0047_problem_solutions.sql`

## 1. 目标

同一用户在同一道题下可以保留多份独立解法，用于对比不同思路、语言与提交结果

每道题最多 5 份解法，至少保留 1 份

每份解法独立保存名称、语言、代码与最近一次提交状态

## 2. 数据模型

### 2.1 problem_solutions

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `user_id` | 所属用户，随用户删除级联清理 |
| `problem_id` | 所属题目，随题目删除级联清理 |
| `slot` | 1–5 的稳定排序位，同时用于并发占位 |
| `name` | 解法名称，默认「解法 N」，上限 60 字符 |
| `language` | `cpp` / `java` / `python` / `javascript` |
| `code` | 解法代码，默认空字符串，上限 256 KB |
| `created_at` / `updated_at` | 创建与更新时间 |

唯一约束 `(user_id, problem_id, slot)` 保证同一用户同一题最多 5 份

索引 `(user_id, problem_id, updated_at DESC)` 服务列表与首页继续学习

### 2.2 submissions.solution_id

`submissions` 新增可空 `solution_id`，外键指向 `problem_solutions`

删除解法时 `ON DELETE SET NULL`，提交历史与代码快照继续保留

提交列表与详情返回 `solution_id`，用于历史记录的解法标签与状态回填

### 2.3 旧草稿迁移

`0047` 把 `problem_drafts` 按 `(user_id, problem_id)` 折叠为解法

按 `updated_at DESC, language` 排序，最多迁移 5 份，名称写为「解法 N」

`problem_drafts` 标记为废弃，旧接口保留兼容

## 3. 后端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/problems/{id}/solutions?language=cpp` | 列出本人解法；首次进入自动创建空解法 1 |
| POST | `/api/problems/{id}/solutions` | 新建解法 `{name?,language,code?}` |
| PUT | `/api/problems/{id}/solutions/{solution_id}` | 更新 `{name?,language?,code?}` |
| DELETE | `/api/problems/{id}/solutions/{solution_id}` | 删除解法，至少保留 1 份 |

约束与错误

- 只对已审核题目开放，题目不存在返回 404
- 语言仅接受四种编辑器语言，否则返回参数错误
- 名称去除首尾空白后不能为空、不能包含控制字符、不超过 60 字符
- 代码超过 256 KB 返回参数错误
- 新建达到 5 份返回 409「最多保存 5 个解法」
- 删除最后一份返回 409「至少保留一个解法」
- 只能操作本人解法，越权按不存在处理

### 3.1 并发处理

新建使用 `INSERT ... ON CONFLICT (user_id, problem_id, slot) DO NOTHING RETURNING id`

从 slot 1 到 5 依次尝试，自然占位并避免并发重复

首次进入的懒创建在 slot 1 冲突时复用已有首位解法，不占用 slot 2

旧草稿接口的懒创建不复用其它语言解法，避免串语言

删除在事务中 `SELECT ... FOR UPDATE` 锁定本人该题全部解法后校验数量

## 4. 前端设计

### 4.1 状态

新增 `useSolutionStore`

- `solutions` / `activeId` / `max` / `mode` / `problemId`
- 登录且非竞赛使用 `server` 模式，其余使用 `local` 模式
- 本地模式写入 `theseus-solutions-{problemId}` 与 `theseus-active-solution-{problemId}`
- 首次本地加载会把旧 `theseus-draft-{problemId}-{language}` 迁移为多个解法
- 服务端不可用时自动退回本地模式，不阻塞继续作答

### 4.2 编辑与保存

工具栏切换器与当前解法绑定

编辑器代码变化立即更新内存中的当前解法，服务端保存延迟 900ms

切换解法、提交、离开页面与 `beforeunload` 前先冲刷待保存代码

语言切换同时写回当前解法的语言与代码

模板代码视为空内容写回，避免首页「继续学习」把未编辑题目当作草稿

程序性载入解法时用 `applyingSolution` 与 `nextTick` 跳过编辑侦听器

### 4.3 界面

- 编辑器工具栏新增解法切换器，展示状态点、名称与 `当前 / 上限`
- 题目页新增「我的解法」Tab，卡片展示状态、语言、用例、耗时、内存与更新时间
- 支持新建、重命名、删除与切换，达到上限时禁用新建并提示
- 删除需要二次确认，最后一份不可删除
- 提交记录按 `solution_id` 显示解法标签
- 通过后展示「再写一种解法」入口
- 竞赛模式禁用多解法，保持原单草稿行为

### 4.4 提交关联

提交请求新增可选 `solution_id`

提交前先把当前语言与代码写回解法，避免提交先于解法保存到达后端

后端校验解法归属与语言一致，不一致返回参数错误

提交结果返回后按 `solution_id` 更新对应解法的最近提交状态

## 5. 兼容与降级

旧接口 `GET/PUT /api/problems/{id}/draft` 继续可用

读取时返回该语言最近一份有内容的解法

写入时更新该语言最近使用的解法，没有则创建

未登录、服务端失败或竞赛模式使用本机多解法，不写服务端

游客本地解法在登录后首次加载服务端解法时自动合并

只有服务端该题还没有任何代码时才合并，避免覆盖其它设备的编辑

合并时先填充服务端懒创建的空解法，再按剩余名额新建

合并成功后清理本机解法与旧语言草稿副本，退出登录后不会重复合并

首页继续学习读取 `problem_solutions`，只考虑有代码且该题尚未通过的记录
