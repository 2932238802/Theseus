JSON-RPC 2.0 的基本格式

```json
{"jsonrpc":"2.0","method":"add","params":[1,2],"id":1}
```

成功响应

```json
{"jsonrpc":"2.0","result":3,"id":1}
```

```json
{"jsonrpc":"2.0","error":{"code":-32601,"message":"Method not found"},"id":1}
```

- 传输层用 TCP、HTTP 还是 WebSocket

### 3. 项目测试、gdb 与高并发

**怎么测试**

- 单元测试：序列化、反序列化、参数校验、错误码
- 集成测试：客户端到服务端的完整请求
- 协议测试：非法 JSON、缺字段、错误版本、未知方法
- 异常测试：超时、断连、半包、超大报文
- 并发测试：多客户端同时请求
- 压力测试：QPS、P99 延迟、连接数、内存
- 模糊测试：随机或畸形输入

**gdb**

如果熟悉，可以说

- `break` 设置断点
- `run`、`continue`、`next`、`step`
- `bt` 查看调用栈
- `print`、`watch` 查看变量
- `thread apply all bt` 查看所有线程
- `core` 文件分析崩溃
- 配合 ASan、TSan、Valgrind 定位内存和并发问题

不熟悉就如实说
不要硬编调试经历

**高并发怎么验证**

- 用压测工具或自己写多线程客户端
- 观察 QPS、平均延迟、P99、错误率
- 逐步增加并发，找拐点
- 看 CPU、内存、连接数、锁竞争
- 做长时间稳定性测试
- 如果没做过，说明为什么对设计有信心
  例如线程模型、无阻塞 IO、压测计划，而不是空口保证

### 7. Linux 命令

**find 基本用法**

```bash
find . -name "*.cpp"
find /var/log -type f -name "*.log"
```

**忽略大小写**

```bash
find . -iname "*.cpp"
```

`-iname` 和 `-name` 一样，只是不区分大小写

**常用组合**

```bash
# 最近 60 分钟修改的文件
find . -type f -mmin -60

# 最近 24 小时修改的文件
find . -type f -mtime -1

# 比某个文件新的文件
find . -type f -newer reference.txt

# 按修改时间排序，取最近 20 个
find . -type f -printf '%T@ %p\n' | sort -nr | head -20

# 排除目录
find . -path ./build -prune -o -type f -name "*.cpp" -print

# 对结果执行命令
find . -type f -name "*.tmp" -exec rm {} \;
```

**uname**

```bash
uname        # 内核名称
uname -a     # 全部信息
uname -r     # 内核版本
uname -m     # 硬件架构
uname -n     # 主机名
uname -s     # 内核名
uname -o     # 操作系统
```

**查看最近修改的所有文件**

- `find . -type f -mmin -10`
- `ls -lt` 按时间排序
- `find . -type f -printf '%T@ %p\n' | sort -nr`
- 需要精确时间用 `stat`

### 8. RAII

RAII 是 Resource Acquisition Is Initialization

核心思想

- 资源在对象构造时获取
- 资源在对象析构时释放
- 资源的生命周期绑定到对象生命周期
- 利用栈对象离开作用域自动析构
- 即使发生异常，栈展开也会调用析构函数

**例子**

- `std::unique_ptr` 管理堆内存
- `std::lock_guard` 管理互斥锁
- `std::fstream` 管理文件
- `std::vector` 管理动态数组
- 自定义 socket 包装类

```cpp
{
    std::lock_guard<std::mutex> lock(mutex_);
    // 离开作用域自动解锁
}
```

**好处**

- 避免忘记释放
- 异常安全
- 所有权清晰
- 减少资源泄漏

**注意**

- 析构函数尽量不要抛异常
- 拷贝语义要明确
  管理独占资源时通常禁止拷贝，允许移动
- 构造失败时，已构造的成员会按逆序析构
- RAII 不只用于内存，也用于锁、文件、连接、事务

### 9. 二分查找

**前提**

数组有序，或者问题具有单调性

**标准写法**

```cpp
int binarySearch(const vector<int>& nums, int target) {
    int left = 0;
    int right = static_cast<int>(nums.size()) - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;
        if (nums[mid] < target) left = mid + 1;
        else right = mid - 1;
    }

    return -1;
}
```

**边界变体**

- 第一个大于等于目标的位置
- 最后一个小于等于目标的位置
- 目标不存在时返回插入位置

```cpp
int lowerBound(const vector<int>& nums, int target) {
    int left = 0;
    int right = static_cast<int>(nums.size());

    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < target) left = mid + 1;
        else right = mid;
    }

    return left;
}
```

**注意**

- `mid = left + (right - left) / 2` 防止溢出
- 区间是左闭右闭还是左闭右开要统一
- 有重复元素时明确要找第一个还是最后一个
- 复杂度 `O(log n)`

### 10. 二叉搜索树

**定义**

- 左子树所有节点小于根
- 右子树所有节点大于根
- 左右子树也是二叉搜索树

**操作**

- 查找：沿路径比较，平均 `O(log n)`
- 插入：找到空位置插入
- 删除：分叶子、单孩子、双孩子
- 中序遍历得到有序序列

**退化**

如果插入有序数据，树会退化成链表
查找变成 `O(n)`

**平衡树**

- AVL：严格平衡，左右子树高度差不超过 1
  查找快，插入删除可能需要多次旋转
- 红黑树：近似平衡，通过颜色和旋转维持
  插入删除的旋转次数更少
  `std::map`、`std::set` 常用红黑树

**对比**

- AVL 更平衡，查询略快
- 红黑树调整成本更低，工程上更常用
- 哈希表平均查找 `O(1)`，但不支持有序遍历
- 需要范围查询和有序性时用平衡树
