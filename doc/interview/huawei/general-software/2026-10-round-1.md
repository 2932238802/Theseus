### 3. Agent 解决了什么痛点，怎么解决

**痛点**

- 原有流程依赖人工，重复且容易遗漏
- 信息分散，需要跨多个系统查询和汇总
- 规则明确，但执行步骤多，难以保证一致性

**解决**

- 把任务拆成可执行的步骤
- 用工具调用连接数据源和业务接口
- 加状态管理和失败重试
- 对关键动作加校验，避免模型直接操作高风险环节
- 用日志和评测集观察效果

回答时结合自己的实际项目
重点讲清楚「为什么需要 Agent」而不是「我用了 Agent」

### 6. `vector` 和 `list` 的区别

**底层结构**

- `vector` 是连续内存的动态数组
- `list` 是双向链表，每个节点单独分配

**访问**

- `vector` 支持随机访问，下标访问 `O(1)`
- `list` 只能顺序访问，找第 k 个元素是 `O(n)`

**插入和删除**

- `vector` 尾部插入均摊 `O(1)`
  中间插入或删除需要搬移元素，`O(n)`
- `list` 已知迭代器位置时插入和删除是 `O(1)`
  但定位到那个位置仍然要 `O(n)`

**内存**

- `vector` 连续存储，缓存友好
  会有容量冗余，扩容时通常按倍数增长
- `list` 节点分散，每个节点额外存前后指针
  内存开销更大，缓存局部性差

**迭代器失效**

- `vector` 扩容后所有迭代器、引用和指针都会失效
  `push_back` 也可能触发扩容
- `list` 插入不会影响其他节点
  删除只会让指向被删节点的迭代器失效

**常用场景**

- 默认优先用 `vector`
  连续遍历、批量计算、需要下标访问、对缓存敏感的场景
- `list` 适合频繁在中间插入删除，且已经持有位置
  例如 LRU 链表、稳定的迭代器、较大的对象
- 多数业务场景里，`deque` 或 `unordered_map` 可能比 `list` 更合适
  不要因为「中间插入快」就默认选 `list`

**可以补充**

- `list` 没有 `operator[]`，不能随机访问
- `list::sort` 是链表归并排序，不能直接用 `std::sort`
- `vector` 的 `reserve` 可以减少扩容
- `vector<bool>` 是特化版本，按位存储，行为和普通 `vector` 不完全一样

### 7. HTTP 的下一层与一次请求响应过程

**下一层**

HTTP 属于应用层
它的下一层是传输层，通常使用 TCP
HTTPS 则在 HTTP 和 TCP 之间多了 TLS

按 OSI 分层

```text
应用层 HTTP
传输层 TCP
网络层 IP
数据链路层
物理层
```

**一次请求和响应**

1. 解析 URL，得到协议、域名、端口和路径
2. DNS 解析域名，得到 IP 地址
3. 与服务器建立 TCP 连接，三次握手
4. 如果是 HTTPS，进行 TLS 握手，协商密钥
5. 客户端发送 HTTP 请求
   请求行、请求头、请求体
6. 请求数据经过 TCP 分段、IP 封装和链路层传输
7. 服务器接收后解析请求，执行业务逻辑
8. 服务器返回 HTTP 响应
   状态行、响应头、响应体
9. 客户端接收响应，按 `Content-Type` 解析内容
10. 根据 `Connection` 决定保持连接还是关闭
    HTTP/1.1 默认 keep-alive

**可以补充**

- HTTP/2 多路复用，多个请求共享一个 TCP 连接
- HTTP/3 基于 QUIC，使用 UDP
- TCP 负责可靠传输、顺序和重传
- 如果问「输入 URL 后发生了什么」，还要加上浏览器缓存、渲染和连接复用

### 8. 最大子数组和

LeetCode 53

**思路**

Kadane 算法

维护两个变量

- `cur`：以当前元素结尾的最大子数组和
- `best`：全局最大子数组和

转移

```text
cur = max(nums[i], cur + nums[i])
best = max(best, cur)
```

如果 `cur + nums[i]` 比 `nums[i]` 还小，说明前面的部分拖后腿，直接从当前元素重新开始

时间复杂度 `O(n)`，空间复杂度 `O(1)`

**代码**

```cpp
int maxSubArray(vector<int>& nums) {
    int best = nums[0];
    int cur = nums[0];

    for (size_t i = 1; i < nums.size(); ++i) {
        cur = max(nums[i], cur + nums[i]);
        best = max(best, cur);
    }

    return best;
}
```

**边界**

- 全是负数：答案是最大的那个负数，不能初始化成 0
- 空数组：题目通常保证非空，工程代码要单独处理
- 和可能溢出：元素很大时用 `long long`

**追问**

- 分治写法：左半、右半、跨中点，`O(n log n)`
- 如果要返回区间，记录起点和终点
- 如果要输出所有最大和子数组，需要额外处理重复
