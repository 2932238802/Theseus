### 2. CI/CD 管理平台与测试范围

**平台做什么**

CI/CD 管理平台通常负责

- 代码构建与流水线编排
- 制品管理
- 环境部署与发布
- 审批与权限控制
- 发布记录与审计
- 通知与回滚

**可以覆盖的测试**

- 功能测试：流水线创建、触发、构建、部署、回滚
- 流程测试：多阶段流水线、审批、失败中断、重试
- 接口测试：平台 API、构建任务回调、状态查询
- 集成测试：代码仓库、制品库、目标环境、通知系统
- 权限测试：不同角色的可见性和操作权限
- 异常测试：构建失败、部署失败、超时、网络中断
- 兼容性测试：不同浏览器、不同代码仓库类型
- 性能测试：并发构建、大量流水线、日志量
- 升级与回滚测试：平台自身升级、配置迁移

回答时结合自己实际做过的模块
不要把所有测试类型都说成自己做过

### 3. 怎么编写测试用例

**流程**

1. 读需求，确认目标和边界
2. 拆测试点
   按功能、流程、状态、异常、权限拆分
3. 设计用例
   正向、反向、边界、异常、并发
4. 写清前置条件和步骤
5. 明确预期结果
6. 标注优先级
7. 评审
8. 执行并维护

**一条用例包含**

- 用例标题
- 前置条件
- 操作步骤
- 测试数据
- 预期结果
- 优先级
- 关联需求

**方法**

- 等价类划分
- 边界值分析
- 场景法
- 状态迁移
- 错误推测
- 因果图

**注意**

- 一条用例只验证一个主要点
- 步骤要可执行，预期要可判断
- 覆盖异常和权限，不只写正向流程
- 用例要能回归，避免依赖临时数据

### 4. AI 写完测试用例后，人做什么

AI 可以生成草稿，但不能替代人的判断

**人要做的事**

- 定义测试范围和风险
- 给 AI 提供完整的需求、约束和业务背景
- 检查用例是否覆盖核心流程和异常分支
- 补充业务规则、权限、边界和兼容性
- 去掉重复、无效、不可执行的用例
- 核对预期结果是否正确
- 实际执行和探索性测试
- 维护用例与需求的对应关系
- 对最终质量负责

**人与 AI 的关系**

- AI 是提效工具，负责生成和整理
- 人是决策者，负责判断和兜底
- AI 容易漏掉业务上下文和隐含规则
- 需求模糊时，AI 会放大错误
- 越基础的能力越重要
  否则无法判断 AI 的输出是否正确

### 5. 等价类和边界值

**等价类**

把输入划分成若干类
同一类里的值对程序的行为应当等价

- 有效等价类：合法输入
- 无效等价类：非法输入

例子：年龄输入范围 18 到 60

- 有效等价类：18 到 60
- 无效等价类：小于 18、大于 60、非数字、空值

**边界值**

错误最容易出现在边界附近

对范围 `[18, 60]` 测试

- 17、18、19
- 59、60、61

对长度、数量、金额、时间窗口同样适用

**组合**

先用等价类减少用例数量
再对边界和关键组合补充用例
两者不是互斥的

### 9. bug 的状态

常见状态

- New：新建
- Assigned：已分配
- Open / In Progress：处理中
- Fixed：已修复
- Resolved：已解决
- Verified：已验证
- Closed：已关闭
- Reopened：重新打开
- Rejected：拒绝
- Duplicate：重复
- Deferred：延期处理

**流转**

```text
New → Assigned → In Progress → Fixed
→ Verified → Closed
```

验证不通过则 `Reopened`
不是缺陷则 `Rejected`
重复缺陷标记 `Duplicate`

不同公司流程可能不同
回答时说明自己实际使用的工具和流程

### 11. HashMap 是线程安全的吗

不是

**并发问题**

- 多线程同时 `put` 可能丢失更新
- 扩容时数据迁移不安全
- JDK 7 的头插法在并发扩容时可能形成环，导致死循环
- JDK 8 改为尾插法，仍有数据覆盖和计数错误
- 迭代时修改会触发 `fail-fast`

**线程安全的替代**

- `ConcurrentHashMap`
  JDK 8 使用 CAS + synchronized，锁粒度更细
- `Collections.synchronizedMap`
  给整个 map 加锁，性能一般
- `Hashtable`
  老实现，方法级同步，不推荐新代码使用

**注意**

- `ConcurrentHashMap` 也不允许 `null` 键和值
- 复合操作仍要用原子方法
  例如 `putIfAbsent`、`computeIfAbsent`

### 12. int 和 Integer 的区别

| 维度 | int | Integer |
|---|---|---|
| 类型 | 基本类型 | 包装类 |
| 默认值 | 0 | null |
| 存储 | 栈或对象字段 | 对象，通常在堆上 |
| 是否可为 null | 否 | 是 |
| 泛型 | 不能直接作为类型参数 | 可以 |
| 比较 | `==` 比较值 | `==` 比较引用，值比较用 `equals` |
| 性能 | 更轻量 | 有装箱拆箱开销 |

**自动装箱与拆箱**

```java
Integer a = 1;   // 装箱
int b = a;       // 拆箱
```

**缓存**

`Integer` 默认缓存 `-128` 到 `127`

```java
Integer a = 127;
Integer b = 127;
System.out.println(a == b);  // true

Integer c = 128;
Integer d = 128;
System.out.println(c == d);  // false
```

**常见问题**

- `Integer` 为 null 时拆箱会抛 `NullPointerException`
- 包装类型比较用 `equals`
- 集合中只能存包装类型

### 13. final 修饰类、方法、变量

**final 类**

不能被继承

```java
final class A {}
```

例如 `String` 就是 final 类

**final 方法**

不能被子类重写

```java
class A {
    final void foo() {}
}
```

`private` 方法隐式不能重写
`static` 方法属于类，不参与重写

**final 变量**

只能赋值一次

```java
final int x = 1;
// x = 2;  // 编译错误
```

- 基本类型：值不能变
- 引用类型：引用不能变，但对象内容可以变
- `static final` 常用于常量
- 局部变量、成员变量、方法参数都可以用 final
- final 不等于线程安全
  只保证引用或值不被重新赋值
