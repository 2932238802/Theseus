### 3. 正负数交替排列

**题目**

给定数组 `nums`，元素个数 `n` 为偶数，所有元素非零
设计一个复杂度尽可能低的方法
使数组变成「正数、负数、正数、负数……」的排列

**隐含条件**

要排成严格的「正、负、正、负」，正数和负数的个数必须各占一半
如果题目没有保证数量相等，需要先说明无法完成
如果允许从负数开始，则两类数量最多相差 1

**思路**

双指针，原地交换

- 偶数下标应该放正数
- 奇数下标应该放负数
- 从左到右扫描
- 当前位置符号不对时，向后找第一个符号正确的元素并交换
- 两个查找指针只向前移动，因此总时间复杂度是 `O(n)`
- 只使用常数个变量，空间复杂度是 `O(1)`

**代码**

```cpp
void alternate(vector<int>& nums) {
    int n = static_cast<int>(nums.size());
    int pos = 0;   // 找正数
    int neg = 1;   // 找负数

    for (int i = 0; i < n; ++i) {
        bool even = (i % 2 == 0);
        bool positive = nums[i] > 0;

        if (even == positive) continue;  // 当前位置已经正确

        if (even) {
            pos = max(pos, i + 1);
            while (pos < n && nums[pos] <= 0) ++pos;
            if (pos >= n) return;  // 数量不满足时无法完成
            swap(nums[i], nums[pos]);
        } else {
            neg = max(neg, i + 1);
            while (neg < n && nums[neg] >= 0) ++neg;
            if (neg >= n) return;
            swap(nums[i], nums[neg]);
        }
    }
}
```

**正确性**

每次处理完下标 `i`，`nums[i]` 的符号就正确了
后续交换只发生在 `i` 之后，不会破坏已经处理好的前缀
因此扫描结束时整个数组满足交替要求

**边界**

- 空数组
- 只有一个正数和一个负数
- 正负数数量不相等
  严格交替无法完成，要先和面试官确认题目是否保证
- 元素为 0
  题目保证非零，否则要先定义 0 算正数、负数还是单独处理

**追问**

- 能不能保持原有相对顺序
  原地交换不保序
  保序需要额外空间或更复杂的移动
- 如果要求从负数开始
  把偶数位和奇数位的目标符号对调

### 4. 智能指针

**`unique_ptr`**

- 独占所有权
- 不能拷贝，只能移动
- 离开作用域自动释放
- 大小通常和裸指针一样，没有引用计数开销
- 用 `std::make_unique` 创建
- 支持自定义删除器
- 管理数组时使用 `unique_ptr<T[]>`

```cpp
auto p = std::make_unique<int>(42);
auto q = std::move(p);  // 所有权转移，p 变为空
```

**`shared_ptr`**

- 共享所有权
- 内部有控制块，维护强引用计数和弱引用计数
- 拷贝时强引用计数加一，析构时减一
- 强引用计数归零时释放对象
- 引用计数操作是原子的，但对象本身的访问不是线程安全的
- 有额外内存和性能开销
- `std::make_shared` 通常只分配一次

```cpp
auto p = std::make_shared<int>(42);
auto q = p;  // 引用计数变为 2
```

**`weak_ptr`**

- 不拥有对象，不增加强引用计数
- 不能直接解引用
- 用 `lock()` 获取一个 `shared_ptr`
  对象已经释放时返回空
- 用来观察对象是否还活着

**为什么有了 `shared_ptr` 还要 `weak_ptr`**

主要是解决循环引用

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::shared_ptr<Node> prev;  // 循环引用，永远不会释放
};
```

如果两个对象互相持有 `shared_ptr`，强引用计数永远不会归零
把其中一个改成 `weak_ptr` 就能打破环

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;
};
```

其他用途

- 观察者模式，观察者不延长被观察者的生命周期
- 缓存，缓存项可以被回收
- 避免悬空指针，使用前 `lock()` 检查

**追问**

- `shared_ptr` 线程安全吗
  引用计数是原子操作
  但多个线程同时修改同一个对象仍然需要同步
- `make_shared` 和 `shared_ptr(new T)` 的区别
  `make_shared` 通常一次分配，异常安全更好
  但对象和控制块在一起，弱引用存在时内存释放会更晚
- 循环引用怎么排查
  看对象为什么没有析构，检查双向关系和回调

### 6. 左值、右值与右值引用

**左值**

- 有名字，有确定的存储位置
- 可以取地址
- 生命周期通常超过当前表达式
- 例如变量 `x`、数组元素、解引用的指针

```cpp
int x = 1;
int* p = &x;  // x 是左值
```

**右值**

- 临时值，没有持久身份
- 通常不能取地址
- 例如字面量、算术表达式结果、按值返回的临时对象

```cpp
int y = x + 1;  // x + 1 是右值
```

C++11 之后更准确地说

- lvalue：有身份，不可移动
- xvalue：有身份，可移动
- prvalue：无身份，可移动
- glvalue = lvalue + xvalue
- rvalue = xvalue + prvalue

**右值引用**

```cpp
T&&
```

它可以绑定临时对象
配合移动构造和移动赋值，把资源从临时对象「偷」过来

```cpp
class Buffer {
public:
    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;
        other.size_ = 0;
    }

private:
    char* data_ = nullptr;
    size_t size_ = 0;
};
```

**为什么需要右值**

- 避免不必要的深拷贝
  临时对象马上要销毁，直接接管它的资源更高效
- 支持移动语义
  `std::vector` 扩容、容器插入临时对象、`unique_ptr` 转移所有权
- 支持完美转发
  配合模板和 `std::forward` 保留参数的值类别
- 让「只可移动、不可拷贝」的类型成为可能
  例如 `unique_ptr`、`thread`、`fstream`

**`std::move` 是什么**

`std::move` 本身不移动任何东西
它只是把左值转换成右值引用，告诉编译器「这个对象可以被移动」
真正的移动发生在移动构造或移动赋值里

**为什么 `const T&` 不够**

`const T&` 可以绑定临时对象
但它是常量引用，不能修改，也不能接管资源
所以需要右值引用来区分「可以安全地偷」

**注意**

- 模板里的 `T&&` 不一定是右值引用
  可能是转发引用，需要结合类型推导判断
- 移动构造最好标记 `noexcept`
  否则 `vector` 扩容可能退回复制
- 被移动后的对象仍然有效，但状态未指定
  不要假设它一定为空
