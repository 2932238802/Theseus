> 版本：v1.1  
> 日期：2026-10-25  
> 状态：详细设计，待实施  
> 变更：v1.1 将角色改为 `student` / `teacher` / `admin` 三角色互斥，取消角色继承和教师以学生身份加入组织的设计。
> 当前实现基线：`0a00582` + 工作区论坛/题库种子变更  
> 关联文档：`doc/总体设计.md` §2、§4.6、§5.2、§9、§11.1

## 0. 结论速览

| 决策项 | 本期选择 |
|---|---|
| 角色模型 | `student` / `teacher` / `admin` 三角色互斥，无继承、无兼任 |
| 角色变更 | 注册默认 `student`；只有 `admin` 能提升/降低角色；角色变更立即生效 |
| 教师与学生关系 | 互斥：教师不加入组织、不提交作业；学生不能创建组织、不能批改 |
| 管理员与教学 | 互斥：管理员负责用户角色、论坛、题目和平台配置，不进入组织/作业/成绩数据 |
| 组织成员 | 第一版只区分 owner 教师和 student 成员，不做助教/协同教师 |
| 加入组织 | 仅 `student` 可通过邀请码加入；教师按用户名/邮箱添加的也必须是学生 |
| 练习提交 | 所有登录角色都可以做题库练习；练习提交不属于教学身份 |
| 作业状态 | `draft` / `published` / `archived`；进行中/已截止由时间计算 |
| 作业题目 | 只能选择已审核且有完整评测配置的题目 |
| 提交关联 | 复用 `submissions`，新增可空 `assignment_id`；作业提交仅 `student` |
| 迟交 | 截止后禁止；教师可延长截止时间 |
| 重交 | 不限次数 |
| 自动评分 | 有该作业下的 `accepted` 提交则该题得满分，否则 0 分 |
| 教师改分 | 组织 owner 教师可按题覆盖分数并写评语，也可写整体评语 |
| 成绩可见性 | 教师发布成绩前学生看不到分数和评语 |
| 通知 | 作业发布、成绩发布写站内通知；本轮不做邮件 |
| 数据保留 | 组织/已发布作业只归档不物理删除；题目被作业引用后禁止删除 |

**一句话总结：** 用一张可空的 `submissions.assignment_id` 把作业提交接回现有判题链路，用 `classes`、`class_members`、`assignments`、`assignment_problems`、`assignment_problem_grades`、`assignment_results` 六张表完成教学闭环；学生只学、教师只教、管理员只管平台，三方互不兼任。

## 1. 目标与非目标

### 1.1 目标

1. 管理员可以把学生提升为教师；教师只负责教学，不能以学生身份加入组织。
2. 学生可以通过邀请码加入组织，教师也可以直接按用户名或邮箱添加学生；被添加者必须是学生。
3. 教师可以创建作业、选择题目、设置分值和截止时间，并发布给组织。
4. 学生在截止前通过现有题目编辑器提交代码，判题链路保持不变。
5. 教师可以查看组织每个学生每道题的提交状态、代码和成绩。
6. 教师可以按题改分、写评语、写整体评语，并发布成绩。
7. 学生只能看到已发布的成绩和自己的提交详情。
8. 作业发布和成绩发布产生站内通知，复用现有通知中心。
9. 所有组织、作业、成绩接口都做服务端资源归属校验，防止 IDOR。
10. 三个角色互斥：学生不能创建组织/批改，教师不能加入组织/提交作业，管理员不能进入教学数据。

### 1.2 非目标

本轮明确不做：

- 教师以学生身份加入其他组织、单账号双角色；
- 管理员查看或操作组织、作业、提交、成绩（后续可加只读审计）；
- 教师以教师账号提交组织作业（只能用题目页“运行”预览）；
- 邮件通知、邮箱验证、SMTP 配置；
- 助教、协同教师、组织 owner 转让；
- CSV 批量导入学生；
- 迟交扣分、迟交标记、补交申请；
- 每题提交次数限制；
- 成绩申诉、成绩修改审计表；
- 个人出题入口（学生/教师）和管理员题目审核 UI；
- 防作弊相似度扫描、行为信号；
- 学期 `terms` 独立表（第一版用 `classes.term` 字符串）；
- 作业题目随机变体、题目版本和重判；
- 作业统计导出、组织数据看板；
- 多学校、多租户。

### 1.3 第一轮验收标准

- 管理员能在 `/admin/users` 把普通学生提升为教师。
- 教师能创建组织，系统生成唯一邀请码。
- 学生能用邀请码加入组织；教师能按用户名或邮箱添加学生。
- 同一用户重复加入同一组织不会产生重复成员。
- 教师能创建作业草稿、选择至少一道可评测题目、设置分值和截止时间。
- 教师能发布作业，组织 active 学生收到站内通知。
- 学生能在开始时间之后、截止时间之前提交，截止后提交被拒绝。
- 学生在作业页能看到自己的提交状态，但看不到未发布的分数和评语。
- 教师能在批改台看到学生 × 题目的状态矩阵，查看提交代码，按题改分和写评语。
- 教师发布成绩后，学生能看到分数和评语，并收到站内通知。
- 只有组织 owner 教师和 active 学生成员能读取组织作业和成绩；其他教师、非成员学生返回 404，管理员返回 403。
- 教师不能加入组织、不能提交作业；学生不能创建组织、不能批改；管理员不能进入组织/作业/成绩数据。
- 角色变更必须满足清理条件：学生升教师前没有 active 组织成员关系；教师降级前没有未归档的自有组织。
- 角色变更后立即生效，不依赖重新登录。

## 3. 角色、权限与数据边界

### 3.1 三个互斥角色

```text
student   |   teacher   |   admin
```

每个账号只有一个角色，能力不继承、不兼任：

- `student`：加入组织、提交作业、查看自己的成绩。
- `teacher`：创建和管理自己的组织、发布作业、批改和发布成绩。
- `admin`：管理用户角色、论坛、题库和平台配置；不进入组织、作业、提交、成绩数据。

补充：

- 题库练习提交（`assignment_id` 为空）对所有登录角色开放，它属于平台功能，不代表“学生身份”。
- 教师不能用教师账号加入组织，也不能提交组织作业；需要验证学生流程时使用题目页“运行”预览。
- 管理员不能用管理员账号创建组织、批改或提交作业；管理员如果确实需要教学，必须先转成教师角色。
- 一个账号不能同时是教师和学生。若某人既要授课又要学习，本轮不提供单账号双角色，后续可讨论“关联账号”。

### 3.2 角色迁移

当前约束：

```sql
role VARCHAR(20) NOT NULL DEFAULT 'user'
CHECK (role IN ('user', 'admin'))
```

迁移为：

```text
user    → student
student → student
teacher → teacher
admin   → admin
```

迁移 SQL 顺序：

```sql
ALTER TABLE users DROP CONSTRAINT IF EXISTS users_role_check;
UPDATE users SET role = 'student' WHERE role = 'user';
ALTER TABLE users ALTER COLUMN role SET DEFAULT 'student';
ALTER TABLE users ADD CONSTRAINT users_role_check
    CHECK (role IN ('student', 'teacher', 'admin'));

ALTER TABLE users
    ADD COLUMN IF NOT EXISTS role_changed_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP;
CREATE INDEX IF NOT EXISTS idx_users_role ON users (role);
```

认证策略：

- JWT 只用于确认身份；`AuthUser.role` 不再信任 token 中的旧角色，而是在认证时读取 `users.role`。
- JWT 中的 `role` 字段可以暂时保留以兼容旧前端，但服务端不再用它做授权判断。
- `authenticate` 改为异步并接收连接池；所有 handler 的调用点同步调整。
- 旧 JWT 中的 `role = 'user'` 不再需要特殊映射，数据库已经是 `student`。
- 角色变更立即生效；前端界面如果仍显示旧角色，刷新 `/me` 即可，不需要强制下线。
- 这样同时解决“降级后的旧 token 仍保留教师权限”的问题。

### 3.3 组织关系

```text
classes.owner_id  →  active 组织必须是 teacher
class_members     →  只能包含 student
```

规则：

- 教师创建组织时，`owner_id = 当前教师`；一个教师可以拥有多个组织。
- 归档组织在 owner 被降级后可以保留原 `owner_id`（此时该用户是 student），但组织已冻结，不再有管理入口；这是唯一允许的“历史 owner 非教师”情况。
- 学生可以加入多个组织；一个组织可以有多个学生。
- `class_members` 不存教师，也不存管理员；服务层在加入、添加成员时校验目标用户角色。
- 任何“教师成员”“管理员查看组织”的分支都不存在。
- 教师之间互相隔离：非 owner 教师读取组织资源返回 404，不暴露组织是否存在。
- 管理员访问教学接口返回 403：账号存在，但角色没有教学能力。

### 3.4 权限矩阵

| 操作 | student | owner teacher | 其他教师 | admin |
|---|---:|---:|---:|---:|
| 题库练习提交（`assignment_id` 为空） | ✅ | ✅ | ✅ | ✅ |
| 加入/退出组织 | ✅ | ❌ | ❌ | ❌ |
| 查看自己加入的组织、已发布作业 | ✅ | — | — | ❌ |
| 提交作业、查看自己的成绩 | ✅ | ❌ | ❌ | ❌ |
| 创建组织 | ❌ | ✅ | ✅（创建自己的组织） | ❌ |
| 修改组织、管理成员、轮换邀请码 | ❌ | ✅ | ❌ | ❌ |
| 创建/修改/发布/归档作业 | ❌ | ✅ | ❌ | ❌ |
| 查看本组织全部提交、批改、发布成绩 | ❌ | ✅ | ❌ | ❌ |
| 查看其他教师组织的教学数据 | ❌ | ❌ | ❌ | ❌ |
| 管理用户角色 | ❌ | ❌ | ❌ | ✅ |
| 论坛管理、题目管理 | ❌ | ❌ | ❌ | ✅ |

说明：

- “其他教师”指非该组织 owner 的教师，包括该教师自己创建的其他组织的 owner；跨组织访问一律 404。
- 管理员访问 `/api/classes/*`、`/api/assignments/*`、教学提交详情一律 403，不返回任何教学数据。
- owner 教师不能提交自己组织的作业；需要测试时使用题目页“运行”。
- 学生只能看到自己的提交状态和已发布成绩，不返回其他学生数据。
- 学生退出组织后，历史提交和成绩保留在数据库，但学生不再有读取权限；教师批改台可用“包含已移除成员”查看。

### 3.5 角色管理

管理员接口：

```text
GET /api/admin/users?q=&role=&page=&size=
PUT /api/admin/users/{id}/role
```

约束：

- 只能设置为 `student` / `teacher` / `admin`。
- 不能修改自己的角色，避免管理员误操作失去权限。
- 不能把最后一个管理员降级；角色变更必须在事务内加 advisory lock，避免并发降级后没有管理员。
- 角色变更立即生效，目标用户不需要重新登录；前端刷新 `/me` 即可更新导航。
- 角色管理页只对 `admin` 可见。

角色转换前置条件：

| 转换 | 前置条件 | 不满足时 |
|---|---|---|
| `student → teacher` | 没有 `active` 组织成员关系 | 409，提示先退出组织或被教师移除 |
| `teacher → student` | 没有未归档的自有组织 | 409；可在请求中带 `archive_owned_classes=true`，由管理员确认后归档再降级 |
| `student/teacher → admin` | 没有 active 成员关系、没有未归档组织 | 409，按上两行处理 |
| `admin → teacher/student` | 没有未归档组织、不是 active 成员 | 正常允许；归档组织保留历史 owner |
| 任意 → 自己 | 禁止 | 400 |
| 最后一个 admin → 其他 | 禁止 | 409 |

说明：

- 学生退出组织使用 `DELETE /api/classes/{id}/members/me`；教师也可以移除学生。
- 学生升教师前如果已有历史提交/成绩，数据保留，但升教师后不能再以学生视图访问；需要查看时只能由原组织 owner 教师查看。
- 教师降级时如果选择归档自有组织，归档与降级在同一个事务内完成；归档组织冻结，不再可管理。
- 已归档组织的 `owner_id` 保留历史值，即使 owner 后来被降级；第一版不提供恢复归档或 owner 转让。
- 角色变更记录 `role_changed_at`，后续可扩展为统一审计表。

### 3.6 教师验证学生流程

教师不能提交作业，这是有意的边界：

- 题目页“运行”可以验证代码和评测配置；
- 作业页可以查看题目、时间窗口和统计；
- 不能模拟学生提交，也不能用学生账号身份查看批改结果；
- 如果确实需要端到端验证，只能使用另一个邮箱注册独立学生账号，本轮不为这种场景提供快捷切换。

## 4. 领域模型与状态

### 4.1 组织生命周期

```text
active ──归档──▶ archived
```

- 创建后 `archived_at IS NULL`，组织 active。
- 归档后不能再加入、创建作业或提交；历史数据仍可由 owner 教师和 active 学生查看。
- 归档组织冻结：管理员也不能进入查看或操作；第一版不提供恢复归档。
- 第一版不物理删除组织，统一使用归档。

### 4.2 作业生命周期

```text
draft ──发布──▶ published ──归档──▶ archived
  │
  └──删除（仅 draft）
```

- `draft`：仅 owner 教师可见，可自由修改题目、分值、时间；管理员不可见。
- `published`：active 学生可见；题目和分值锁定，只能修改标题、描述、延长截止时间。
- `archived`：只读，owner 教师和 active 学生仍可查看历史；不能提交；管理员不可见。
- `due_at` 在草稿阶段可以为空，发布时必须填写。
- `start_at` 为空表示发布后立即开始。

作业展示状态由时间计算：

| 条件 | 展示状态 |
|---|---|
| `status = draft` | 草稿 |
| `status = archived` | 已归档 |
| `now < start_at` | 未开始 |
| `start_at <= now <= due_at` | 进行中 |
| `now > due_at` | 已截止 |

### 4.3 成绩可见性

```text
未发布：学生看到提交状态，看不到分数和评语
已发布：学生看到每题得分、总分、教师评语
```

- `assignments.grades_published_at` 是唯一可见性开关。
- 发布后 owner 教师继续改分，学生立即看到新分数；本轮不做成绩快照。
- 每次改分记录 `graded_by`、`graded_at`；`graded_by` 必须是该组织 owner 教师，管理员不能改分。
- 删除学生成员不删除其历史提交和成绩；学生被移除后不再有读取权限，教师可在批改台勾选“包含已移除成员”查看历史。
- 管理员不返回任何成绩数据。

### 4.4 作业提交状态

作业提交直接复用现有 `submissions.status`：

```text
pending → judging → accepted
                  → wrong_answer
                  → time_limit_exceeded
                  → memory_limit_exceeded
                  → runtime_error
                  → compile_error
                  → internal_error
```

不新增作业专用提交状态。

角色限制：

- 只有 `student` 可以创建带 `assignment_id` 的提交。
- `teacher` / `admin` 可以创建不带 `assignment_id` 的练习提交，但不能提交任何组织作业。
- 提交是否计入作业只由 `assignment_id` 决定，与全局做题状态无关。

## 5. 数据模型

### 5.1 ER 关系

```text
users(teacher) 1 ─── n classes (owner, 归档后可为历史 owner)
users(student) 1 ─── n class_members n ─── 1 classes
classes 1 ─── n assignments
assignments 1 ─── n assignment_problems n ─── 1 problems
assignments 1 ─── n submissions (assignment_id, 仅 student)
assignments 1 ─── n assignment_problem_grades (仅 owner teacher)
assignments 1 ─── n assignment_results (仅 owner teacher)
users(student) 1 ─── n submissions
users(student) 1 ─── n assignment_problem_grades
users(student) 1 ─── n assignment_results
```

说明：

- `classes.owner_id` 必须是 `teacher`，`class_members.user_id` 必须是 `student`，由服务层在写入时校验。
- 管理员不参与上述任何关系；管理员只出现在 `users.role = 'admin'` 和用户管理接口中。

### 5.2 迁移 SQL：`0005_teaching.sql`

```sql
-- 1. 角色互斥：user → student，新增 teacher
ALTER TABLE users DROP CONSTRAINT IF EXISTS users_role_check;
UPDATE users SET role = 'student' WHERE role = 'user';
ALTER TABLE users ALTER COLUMN role SET DEFAULT 'student';
ALTER TABLE users ADD CONSTRAINT users_role_check
    CHECK (role IN ('student', 'teacher', 'admin'));

ALTER TABLE users
    ADD COLUMN IF NOT EXISTS role_changed_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP;
CREATE INDEX IF NOT EXISTS idx_users_role ON users (role);

-- 2. 组织
CREATE TABLE IF NOT EXISTS classes (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    course_name VARCHAR(100),
    term VARCHAR(30),
    description TEXT,
    invite_code VARCHAR(12) NOT NULL UNIQUE,
    owner_id INTEGER NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
    archived_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CHECK (length(btrim(name)) > 0)
);

CREATE INDEX IF NOT EXISTS idx_classes_owner
    ON classes (owner_id, archived_at);

-- 3. 组织成员
CREATE TABLE IF NOT EXISTS class_members (
    id SERIAL PRIMARY KEY,
    class_id INTEGER NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    status VARCHAR(20) NOT NULL DEFAULT 'active'
        CHECK (status IN ('active', 'removed')),
    joined_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    removed_at TIMESTAMPTZ,
    UNIQUE (class_id, user_id)
);

CREATE INDEX IF NOT EXISTS idx_class_members_user
    ON class_members (user_id, status);
CREATE INDEX IF NOT EXISTS idx_class_members_class
    ON class_members (class_id, status);

COMMENT ON COLUMN classes.owner_id IS 'active 组织必须是 users.role = teacher；归档组织允许保留历史 owner';
COMMENT ON TABLE class_members IS '只包含 users.role = student，角色由服务层校验';

-- 4. 作业
CREATE TABLE IF NOT EXISTS assignments (
    id SERIAL PRIMARY KEY,
    class_id INTEGER NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
    title VARCHAR(200) NOT NULL,
    description TEXT,
    status VARCHAR(20) NOT NULL DEFAULT 'draft'
        CHECK (status IN ('draft', 'published', 'archived')),
    start_at TIMESTAMPTZ,
    due_at TIMESTAMPTZ,
    created_by INTEGER NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
    published_at TIMESTAMPTZ,
    grades_published_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CHECK (length(btrim(title)) > 0),
    CHECK (start_at IS NULL OR due_at IS NULL OR due_at > start_at)
);

CREATE INDEX IF NOT EXISTS idx_assignments_class
    ON assignments (class_id, status, due_at);

COMMENT ON COLUMN assignments.created_by IS '创建时等于 classes.owner_id，必须是 teacher';

-- 5. 作业题目
CREATE TABLE IF NOT EXISTS assignment_problems (
    assignment_id INTEGER NOT NULL
        REFERENCES assignments(id) ON DELETE CASCADE,
    problem_id INTEGER NOT NULL
        REFERENCES problems(id) ON DELETE RESTRICT,
    position INTEGER NOT NULL DEFAULT 0,
    points INTEGER NOT NULL DEFAULT 100
        CHECK (points > 0 AND points <= 1000),
    PRIMARY KEY (assignment_id, problem_id)
);

CREATE INDEX IF NOT EXISTS idx_assignment_problems_order
    ON assignment_problems (assignment_id, position, problem_id);
CREATE INDEX IF NOT EXISTS idx_assignment_problems_problem
    ON assignment_problems (problem_id);

-- 6. 按题批改
CREATE TABLE IF NOT EXISTS assignment_problem_grades (
    assignment_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    problem_id INTEGER NOT NULL,
    manual_score INTEGER
        CHECK (manual_score IS NULL OR (manual_score >= 0 AND manual_score <= 1000)),
    feedback TEXT,
    graded_by INTEGER REFERENCES users(id) ON DELETE SET NULL,
    graded_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (assignment_id, user_id, problem_id),
    FOREIGN KEY (assignment_id, problem_id)
        REFERENCES assignment_problems (assignment_id, problem_id)
        ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_assignment_problem_grades_user
    ON assignment_problem_grades (user_id, assignment_id);

-- 7. 整体评语
CREATE TABLE IF NOT EXISTS assignment_results (
    assignment_id INTEGER NOT NULL
        REFERENCES assignments(id) ON DELETE CASCADE,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    overall_feedback TEXT,
    graded_by INTEGER REFERENCES users(id) ON DELETE SET NULL,
    graded_at TIMESTAMPTZ,
    PRIMARY KEY (assignment_id, user_id)
);

CREATE INDEX IF NOT EXISTS idx_assignment_results_user
    ON assignment_results (user_id, assignment_id);

-- 8. 提交关联作业
ALTER TABLE submissions
    ADD COLUMN IF NOT EXISTS assignment_id INTEGER
    REFERENCES assignments(id) ON DELETE SET NULL;

CREATE INDEX IF NOT EXISTS idx_submissions_assignment
    ON submissions (assignment_id, user_id, problem_id, status)
    WHERE assignment_id IS NOT NULL;
```

说明：

- `classes.owner_id` 在 active 组织中必须是 `teacher`；`class_members.user_id` 必须是 `student`。数据库无法用普通 CHECK 跨表约束，服务层必须在创建组织、加入组织、添加成员时校验。
- 归档组织允许保留已被降级的历史 owner；组织已冻结，不参与任何权限判断。
- `assignments.created_by` 固定写入组织 owner，不允许管理员或其他教师代建。
- `assignment_problem_grades.graded_by` 必须是该组织 owner 教师；管理员不能写入改分记录。
- `assignment_problem_grades` 使用复合外键，保证被批改的题目一定属于该作业。
- `assignment_problem_grades.manual_score` 的上限由服务层校验，因为数据库 CHECK 无法直接引用 `assignment_problems.points`。
- `submissions.assignment_id` 使用 `ON DELETE SET NULL`，即使作业被删除也不丢失学生的历史提交；实际上已发布作业不允许删除。
- `assignment_problems.problem_id` 使用 `ON DELETE RESTRICT`，题目被作业引用时管理员删除题目会得到明确错误。

### 5.3 评分模型

```text
单题自动分 = assignment_problems.points  如果存在 accepted 提交
           = 0                           否则

单题最终分 = assignment_problem_grades.manual_score  （如果该行存在且非 NULL）
           = 单题自动分

作业总分   = sum(单题最终分)
```

规则：

- 只统计 `submissions.assignment_id = 当前作业` 且提交者是 `student` 的提交。
- 学生在普通题库页对同一道题的练习提交不计入作业成绩；教师和管理员的练习提交也不计入。
- 只有该组织 owner 教师可以写手动分；管理员不能改分。
- 教师手动分必须在 `0..points` 范围内。
- 教师可把 AC 的题改为 0 分，也可给未 AC 的题部分分。
- 总分实时计算，不缓存，避免缓存漂移。
- 成绩发布要求 `due_at <= NOW()`，避免发布后仍有新提交改变已发布总分；如需提前发布，后续再引入成绩快照。

### 5.4 约束与索引设计理由

| 约束/索引 | 目的 |
|---|---|
| `users.role` CHECK | 只允许三个互斥角色 |
| `users.role_changed_at` / `idx_users_role` | 角色变更审计和按角色筛选 |
| `classes.invite_code UNIQUE` | 邀请码唯一，冲突时重新生成 |
| `classes.owner_id` 索引 | 教师查看自己的组织 |
| `class_members UNIQUE(class_id, user_id)` | 重复加入幂等，支持 removed 后重新激活 |
| `assignments.class_id` 索引 | 组织作业列表 |
| `assignment_problems` 复合主键 | 同一作业不能重复添加同一题 |
| `assignment_problem_grades` 复合主键 | 每个学生每题只有一条改分记录 |
| `submissions` 部分索引 | 批改台按作业聚合提交时避免全表扫描 |
| `assignment_problems.problem_id` 索引 | 删除题目时快速检查引用 |

### 5.5 删除与保留策略

| 对象 | 策略 |
|---|---|
| 用户 | 现有 `ON DELETE CASCADE` 保留；本功能不删除用户 |
| 角色 | 只改 `users.role`，不删除账号；学生升教师前必须先退出所有组织；教师降级前必须没有未归档的自有组织 |
| 组织 | 只归档；不物理删除；归档后冻结，管理员也不可查看 |
| 组织成员 | 软删除 `status = removed`，保留历史；移除后学生失去读取权限 |
| 作业草稿 | 可物理删除，级联删除题目关联 |
| 已发布作业 | 只归档；不删除 |
| 题目 | 被作业引用时禁止删除 |
| 提交 | 不删除；作业删除时 `assignment_id` 置空 |
| 成绩 | 随作业删除级联；本轮不提供删除成绩接口 |

### 5.6 并发与幂等

**角色变更**

- 所有角色变更先 `pg_advisory_xact_lock(固定 namespace, 0)`，再锁定目标用户行并统计管理员数量。
- 降级最后一个管理员返回 409。
- `student → teacher` 前检查 `class_members.status = 'active'`；有则 409。
- `teacher → student/admin` 前检查未归档的自有组织；有则 409，除非请求带 `archive_owned_classes = true`，在同一事务内归档这些组织后再改角色。
- 更新 `users.role` 时同步写 `role_changed_at = NOW()`。

**组织与成员**

- 加入组织：仅 `student`；`INSERT ... ON CONFLICT (class_id, user_id) DO UPDATE SET status = 'active', removed_at = NULL`，重复加入幂等。
- 教师添加成员：目标必须是 `student`；同一用户重复添加返回成功或 200，不产生重复行。
- 学生退出：`UPDATE class_members SET status = 'removed', removed_at = NOW() WHERE class_id = $1 AND user_id = $2 AND status = 'active'`。
- 移除成员与提交并发：提交事务对成员行加 `FOR SHARE`；移除更新会等待。若移除先提交，提交返回 404；若提交先完成，该次提交计入作业。

**作业状态**

- 发布：`UPDATE assignments SET status = 'published', published_at = NOW() WHERE id = $1 AND status = 'draft' RETURNING ...`；0 行返回 409，不重复发通知。
- 归档：`UPDATE ... SET status = 'archived' WHERE id = $1 AND status = 'published'`；0 行返回 409。
- 删除草稿：`DELETE ... WHERE id = $1 AND status = 'draft' RETURNING id`；0 行返回 409。
- 修改已发布作业：条件更新 `WHERE status = 'published'`，只允许标题、描述和延长 `due_at`；题目、分值、`start_at` 不可变。
- 发布事务内用一条 `INSERT ... SELECT FROM class_members WHERE status = 'active'` 批量写通知，避免逐学生插入；通知写入只在状态迁移成功时执行。

**成绩发布**

- 要求 `due_at <= NOW()`，否则 409“作业尚未截止，不能发布成绩”。
- `UPDATE assignments SET grades_published_at = NOW() WHERE id = $1 AND status = 'published' AND grades_published_at IS NULL RETURNING ...`。
- 0 行且已发布：返回 200 幂等，不更新时间戳、不重复发通知；`draft/archived` 返回 409。
- 首次发布成功后，在同一事务内批量给 active 学生写通知。

**提交与改分**

- 带 `assignment_id` 的提交只有 `student` 可以发起；教师和管理员直接 403。
- 提交不做次数限制；仍受现有“每用户同时 1 个提交”并发锁和频率限制约束。
- 提交的最终校验与 INSERT 放在同一数据库事务中，对 class、assignment、class_members 依次 `FOR SHARE`，顺序固定为 class → assignment → membership，避免与归档/移除并发时出现死锁或“校验通过但状态已变”。
- 截止判断使用数据库 `NOW()`，不使用应用进程时间。
- 改分：主键 `ON CONFLICT` 更新，记录最后 `graded_by`、`graded_at`；服务层校验 `0 <= manual_score <= points` 且操作者是该组织 owner 教师。

## 6. API 设计

### 6.1 通用约定

- 所有接口使用现有统一 envelope：

```json
{
  "success": true,
  "data": {},
  "error": null
}
```

- 需要登录的接口使用 `Authorization: Bearer <token>`。
- 后端 JSON 字段使用 snake_case；前端 adapter 映射为 camelCase。
- 时间使用 ISO 8601 UTC，例如 `2026-10-30T12:00:00Z`。
- 分页参数统一 `page`、`size`，默认 `1`、`20`，最大 `50`。
- 权限错误统一规则：
  - 未登录：401；
  - 角色没有该能力（学生创建组织、教师加入组织、管理员访问教学接口）：403；
  - 资源对调用者不可见（非 owner 教师、非成员学生）：404，避免泄露组织/作业是否存在；
  - 资源可见但业务状态不允许（已截止、已发布、组织归档）：409。
- 管理员只访问 `/api/admin/*`、论坛管理和管理员题目接口；组织、作业、提交、成绩接口对管理员一律 403。

### 6.2 接口总览

### 6.4 修改角色

`PUT /api/admin/users/{id}/role`

请求：

```json
{
  "role": "teacher",
  "archive_owned_classes": false
}
```

- `archive_owned_classes` 仅在 `teacher → student/admin` 且目标仍拥有未归档组织时使用；为 `true` 时在同一事务内先归档这些组织。
- 其他转换忽略该字段。

响应：

```json
{
  "id": 7,
  "username": "alice",
  "role": "teacher",
  "message": "角色已更新，立即生效",
  "archived_class_count": 0
}
```

错误：

| 场景 | 状态码 |
|---|---:|
| 角色值非法 | 400 |
| 用户不存在 | 404 |
| 修改自己的角色 | 400 |
| 降级最后一个管理员 | 409 |
| 学生仍有 active 组织成员关系 | 409 |
| 教师仍有未归档组织且未确认归档 | 409 |
| 目标用户是当前事务锁定的管理员且并发冲突 | 409/重试 |

规则：

- 角色变更立即生效；前端刷新 `/me` 更新导航，不要求重新登录。
- 学生升教师前必须退出所有组织，或由教师移除；退出接口见 6.9。
- 教师降级前必须没有未归档的自有组织；管理员可选择归档后再降级。
- 管理员降级/提升同样受清理条件约束。
- 所有角色变更写 `role_changed_at`，并在服务端日志记录操作者、目标、前后角色。

### 6.6 创建组织

`POST /api/classes`，仅 `teacher`。管理员和学生返回 403。

请求：

```json
{
  "name": "2026 级算法 1 班",
  "course_name": "算法设计与分析",
  "term": "2026秋",
  "description": "每周三第 3-4 节"
}
```

响应：完整组织对象，包含 `invite_code`。

规则：

- 名称必填，最多 100 字符。
- 邀请码由后端生成 8 位大写字母和数字，排除易混淆字符。
- 生成冲突时重试最多 5 次。
- 创建者自动成为 owner，不写入 `class_members`。
- `owner_id` 必须是 `teacher`；服务层校验当前角色，不能靠前端隐藏按钮。

### 6.7 组织详情

`GET /api/classes/{id}`

访问规则：

- `student`：必须是该组织 `status = active` 的成员，否则 404。
- `teacher`：必须是该组织 owner，否则 404。
- `admin`：403。
- 学生成员响应包含组织基本信息、成员数、已发布作业列表摘要；不返回成员邮箱、邀请码和草稿。
- owner 教师响应额外包含邀请码、完整成员列表（用户名、邮箱、加入时间、状态）、草稿和归档作业、未发布成绩摘要。
- 不再存在“教师以学生成员身份查看”的视图。

### 6.8 加入组织

`POST /api/classes/join`

请求：

```json
{ "invite_code": "A7K2M9QX" }
```

规则：

- 仅 `student` 可以调用；`teacher` / `admin` 返回 403“只有学生账号可以加入组织”。
- 邀请码大小写不敏感，服务端统一转大写。
- 组织已归档返回 409。
- 已经是 active 成员：幂等成功。
- 曾经 removed：恢复为 active，更新 `joined_at` 和 `removed_at = NULL`。
- 组织 owner 是教师，不会出现在 `class_members`，因此不需要“owner 不能加入自己组织”的特殊分支。
- 建议对加入接口增加每用户 10 次/分钟限流，防止邀请码枚举（邀请码空间足够大，但限流成本低）。

### 6.9 教师添加/移除成员

`POST /api/classes/{id}/members`

请求：

```json
{ "identifier": "alice" }
```

`identifier` 可以是用户名或邮箱，服务端先按用户名精确匹配，再按邮箱不区分大小写匹配。

规则：

- 仅 owner 教师可调用；管理员 403。
- 用户不存在返回 404。
- 目标用户不是 `student`：返回 400“教师/管理员账号不能加入组织”。
- 目标学生已 active：幂等成功。
- removed 用户恢复 active。
- 不处理教师账号，也不把管理员作为成员加入。

`DELETE /api/classes/{id}/members/{user_id}`

- 仅 owner 教师可移除学生；管理员 403。
- 移除只更新 `status = removed`、`removed_at`，不删除提交和成绩。
- 不能移除 owner（owner 是教师，本就不在成员表）。

`DELETE /api/classes/{id}/members/me`

- 仅 `student` 可调用，退出自己加入的组织。
- 组织归档后仍允许退出（清理成员关系），但退出后不能再查看该组织。
- 退出后历史提交和成绩保留；重新加入需邀请码。

### 6.10 邀请码轮换

`POST /api/classes/{id}/invite-code/rotate`

- 仅 owner 教师可用；管理员 403。
- 轮换后旧邀请码立即失效。
- 返回新邀请码。
- 第一版不做邀请码过期时间。

`POST /api/classes/{id}/archive`

- 仅 owner 教师可用；管理员 403。
- 设置 `archived_at = NOW()`。
- 归档后不能加入、创建作业、发布作业或提交。
- 历史组织、作业、提交和成绩保留，owner 教师和 active 学生可只读查看；管理员不可见。
- 第一版不提供恢复归档接口。

### 6.11 创建作业

`POST /api/classes/{id}/assignments`

请求：

```json
{
  "title": "第一次作业：数组与哈希表",
  "description": "完成下列题目，提交前先运行样例。",
  "start_at": "2026-10-26T00:00:00Z",
  "due_at": "2026-11-02T15:59:00Z",
  "problems": [
    { "problem_id": 1101, "points": 100 },
    { "problem_id": 1102, "points": 100 }
  ]
}
```

规则：

- 仅组织 owner 教师可创建；管理员和其他教师 403/404。
- 组织已归档返回 409。
- 题目必须 `review_status = 'approved'`。
- 题目必须有 `run_config` 且 `judge_cases` 非空，否则不能用于自动评分。
- 同一作业不能重复添加同一题目。
- `points` 范围 `1..1000`。
- 题目数量上限 50。
- 创建后状态为 `draft`。
- `position` 按请求顺序从 0 递增。
- 草稿允许 0 道题；发布时至少 1 道。
- `created_by` 固定写入组织 owner，不能由管理员代建。

### 6.12 修改作业

`PUT /api/assignments/{id}`

- 仅 owner 教师可用；管理员 403，其他教师 404。
- 状态更新使用条件语句，避免与发布/归档并发时覆盖状态。

草稿阶段允许修改：

- 标题、描述、开始时间、截止时间、题目列表、分值。

已发布阶段允许修改：

- 标题、描述；
- 延长 `due_at`（只能晚于原截止时间）；
- 不允许增删题目、修改分值，避免已提交学生成绩口径变化。

已归档阶段只读。

`PUT /api/assignments/{id}/problems` 单独更新题目列表，便于前端拖拽排序；规则同上。

请求体为全量替换：

```json
{
  "problems": [
    { "problem_id": 1101, "points": 100 },
    { "problem_id": 1102, "points": 100 }
  ]
}
```

仅 `draft` 状态可用；已发布后返回 409。

### 6.13 发布作业

`POST /api/assignments/{id}/publish`

- 仅 owner 教师可用；管理员 403，其他教师 404。

校验：

- 状态必须是 `draft`；
- 至少 1 道题；
- `due_at` 非空，且 `start_at < due_at`；
- 所有题目仍为 approved 且可评测；
- 组织未归档。

事务内：

1. `UPDATE assignments SET status = 'published', published_at = NOW() WHERE id = $1 AND status = 'draft' RETURNING id`；
2. 0 行返回 409“作业已发布”，不重复发通知；
3. 用一条 `INSERT ... SELECT` 给组织 `status = 'active'` 的学生批量写站内通知；
4. 提交事务。

通知：

```json
{
  "type": "assignment_published",
  "title": "新作业：第一次作业：数组与哈希表",
  "body": "2026 级算法 1 班",
  "link": "/assignments/12",
  "related_type": "assignment",
  "related_id": 12
}
```

重复发布已发布作业：返回 409“作业已发布”，不重复发通知。通知受众只有 `class_members.status = 'active'` 的学生，不包含教师和管理员。

### 6.14 归档作业

`POST /api/assignments/{id}/archive`

- 仅 owner 教师可用；管理员 403，其他教师 404。
- 状态 `published` 可归档；`draft` 建议直接删除。
- `UPDATE ... WHERE status = 'published'`，0 行返回 409。
- 归档后学生（active 成员）只读，不能提交。
- 不发送通知。

### 6.15 删除草稿

`DELETE /api/assignments/{id}`

- 仅 `draft`、owner 教师可删除；管理员 403，其他教师 404。
- `DELETE ... WHERE id = $1 AND status = 'draft' RETURNING id`，0 行返回 409。
- 级联删除 `assignment_problems`。
- 已发布作业返回 409，提示使用归档。

### 6.16 作业详情

`GET /api/assignments/{id}`

访问规则：

- `student`：必须是该组织 active 成员；只能看到 `published` / `archived` 作业，`draft` 返回 404。
- `teacher`：必须是该组织 owner；可以看到全部状态。
- `admin`：403。
- 其他教师/非成员学生：404。

学生响应（成绩已发布示例）：

```json
{
  "id": 12,
  "class_id": 1,
  "class_name": "2026 级算法 1 班",

  "status": "published",
  "start_at": "...",
  "due_at": "...",
  "grades_published": true,
  "problems": [
    {
      "problem_id": 1101,

```

成绩未发布时：

- 不返回 `auto_score`、`manual_score`、`final_score`、`total_score`、`feedback`、`overall_feedback`；
- 仍返回 `attempts`、`accepted`、最近提交状态。

owner 教师响应额外包含：

- 组织学生总数；
- 已提交人数；
- 每题通过人数；
- 管理入口所需字段。

不存在“教师以学生成员身份加入后返回学生视图”的情况；非 owner 教师直接 404。

### 6.17 教师查看作业提交

`GET /api/assignments/{id}/submissions?user_id=&problem_id=&page=&size=`

- 仅 owner 教师可用；管理员 403，其他教师 404。
- 只返回 `assignment_id` 匹配该作业的提交。
- 返回 `SubmissionSummary` 列表，不返回隐藏用例内容。
- 用于批改台点击某个学生某道题时列出提交记录。

### 6.18 查看提交详情

现有 `GET /api/submissions/{id}` 扩展权限：

```text
允许访问：
1. 提交者本人（任何角色都可以查看自己的练习提交）
2. 该提交关联作业所在组织的 owner teacher
```

不允许：

- 管理员不能凭 admin 角色查看其他人的提交（包括教学提交和练习提交）；
- 非 owner 教师不能查看；
- 非成员学生不能查看。

实现方式：

- `SubmissionRow` 增加 `assignment_id`；
- `check_owner` 扩展为异步 `check_access(pool, ...)`：
  - `user.role == "admin"` 且 `row.user_id != user.id`：403；
  - `row.user_id == user.id` 直接允许；
  - `assignment_id` 非空时，查询该作业所属组织的 `owner_id`，只有 owner teacher 允许；
  - 其他情况返回 404（不暴露提交是否存在）。
- 这改变了现有“管理员可查看任意提交”的行为，需要在 README 和测试中明确。

配套修改：

- 现有 `GET /api/submissions?user_id=` 的 admin 越权分支必须移除，所有角色只能查询自己的提交列表；显式传其他 `user_id` 返回 403。
- 教师查看组织提交只能走 `GET /api/assignments/{id}/submissions`，不能借用通用提交列表接口。
- `submission_service.rs` 中两处状态查询（创建后的状态轮询、详情）都使用同一个 `check_access`。

### 6.23 提交接口扩展

`POST /api/submissions`

请求增加可空字段：

```json
{
  "problem_id": 1101,
  "language": "python",
  "code": "...",
  "assignment_id": 12
}
```

现有 `SubmissionRequest`：

```rust
pub struct SubmissionRequest {
    pub problem_id: i32,
    pub language: String,
    pub code: String,
    pub assignment_id: Option<i32>,
}
```

校验顺序：

1. 现有语言、代码长度、题目 approved、run_config、用例数量校验；
2. 若 `assignment_id` 为空：走原练习提交逻辑，所有登录角色都可以提交；
3. 若 `assignment_id` 有值：
   - 当前用户必须是 `student`，否则 403“教师/管理员不能提交组织作业”；
   - 查询作业所在组织；当前用户必须是该组织 `status = 'active'` 成员，否则 404（先做成员校验，避免向非成员泄露作业状态）；
   - 作业必须存在且不是 `draft`；`archived` 返回 409；
   - 组织未归档；
   - `now >= start_at`（若 start_at 非空）；
   - `now <= due_at`；
   - 题目在 `assignment_problems` 中；
4. 通过预校验后，执行现有 Redis worker 心跳、限流、每用户并发锁；
5. 在同一个数据库事务中做最终校验并 INSERT：
   - 对 class、assignment、class_members 依次 `FOR SHARE`；
   - 使用数据库 `NOW()` 重新判断截止时间；
   - 插入 `submissions.assignment_id`；
6. 后续队列、状态缓存保持原逻辑。

注意：不能按旧稿“先插入、后限流”；限流和并发锁必须在写库之前。最终校验必须在写库事务内，避免教师归档/移除成员与提交并发时状态失真。

错误映射：

| 场景 | 状态码 | 消息 |
|---|---:|---|
| 作业不存在/不可见/草稿 | 404 | 作业不存在 |
| 不是组织成员 | 404 | 作业不存在（避免泄露） |
| 作业已归档 | 409 | 作业已归档 |
| 未开始 | 409 | 作业尚未开始 |
| 已截止 | 409 | 作业已截止 |
| 组织已归档 | 409 | 组织已归档 |
| 题目不在作业中 | 400 | 题目不属于该作业 |
| 教师/管理员提交作业 | 403 | 教师/管理员不能提交组织作业 |
| 学生尝试加入非学生角色接口 | 403 | 当前角色无权执行该操作 |

### 6.24 作业列表

`GET /api/classes/{id}/assignments`

- 学生（必须是 active 成员）：只返回 `published` 和 `archived`，不返回 `draft`。
- owner 教师：返回全部，按 `created_at DESC`。
- 管理员：403；其他教师/非成员学生：404。
- 返回摘要：标题、状态、开始/截止时间、题目数、总分、是否已发布成绩、自己的完成数。
- 不返回其他学生成绩。

## 7. 关键流程

### 7.1 管理员提升教师

```text
管理员打开 /admin/users
  → 搜索用户
  → 查看 active_membership_count / owned_active_class_count
  → 选择角色 teacher
  → PUT /api/admin/users/{id}/role
  → 服务端校验：管理员、目标存在、不是自己、不是最后一个管理员
  → 若目标仍是 active 组织成员：409，提示先退出组织
  → 更新 users.role、role_changed_at
  → 角色立即生效；目标用户刷新 /me 后看到教师导航
```

### 7.2 教师创建组织

```text
teacher 打开 /classes
  → 点击“创建组织”
  → 填写名称/课程/学期/描述
  → POST /api/classes
  → 服务端 require_teacher（admin/student 403）
  → 生成 invite_code（冲突重试）
  → INSERT classes(owner_id = current_user)
  → 返回组织详情和邀请码
```

### 7.3 学生加入组织

```text
学生打开 /classes
  → 输入邀请码
  → POST /api/classes/join
  → 服务端 require_student（teacher/admin 403）
  → 查 invite_code、组织未归档
  → INSERT ... ON CONFLICT DO UPDATE status='active'
  → 返回组织摘要
```

教师添加：

```text
teacher 打开组织详情
  → 输入用户名或邮箱
  → POST /api/classes/{id}/members
  → 服务端校验 owner teacher
  → 查找用户，目标必须是 student
  → upsert class_members
```

学生退出：

```text
学生打开组织详情
  → 点击“退出组织”
  → DELETE /api/classes/{id}/members/me
  → UPDATE class_members SET status='removed'
  → 不再返回该组织
```

### 7.4 教师创建并发布作业

```text
teacher 打开组织详情
  → 创建作业
  → 填标题/描述/时间
  → 搜索并选择 approved + 可评测题目
  → 设置每题分值
  → 保存草稿
  → 检查无误后发布
  → 服务端校验题目、时间、组织状态
  → 条件更新 status=published（仅 draft → published）
  → 用 INSERT ... SELECT 批量写 active 学生站内通知
```

### 7.5 学生提交作业

```text
学生打开 /assignments/12
  → 看到题目列表、截止时间、自己的状态
  → 点击某题进入 /problem/1101?assignment_id=12
  → 编写代码
  → 提交
  → POST /api/submissions { ..., assignment_id: 12 }
  → 服务端校验 student 角色和作业上下文
  → 限流 + 每用户并发锁
  → 数据库事务内 FOR SHARE 最终校验并插入
  → 进入现有判题队列
  → 前端轮询提交状态
  → 返回作业页刷新该题状态
```

### 7.7 权限校验伪代码

```rust
fn require_role(user: &AuthUser, role: &str) -> Result<(), AppError> {
    if user.role == role {
        Ok(())
    } else {
        Err(AppError::Forbidden)
    }
}

fn require_student(user: &AuthUser) -> Result<(), AppError> {
    require_role(user, "student")
}

fn require_teacher(user: &AuthUser) -> Result<(), AppError> {
    require_role(user, "teacher")
}

fn is_class_owner(user: &AuthUser, class: &ClassRow) -> bool {
    user.role == "teacher" && class.owner_id == user.id
}

fn ensure_class_read(
    pool: &PgPool,
    user: &AuthUser,
    class: &ClassRow,
) -> Result<ClassView, AppError> {
    if is_class_owner(user, class) {
        return Ok(ClassView::Teacher);
    }
    if user.role == "student" {
        if is_active_member(pool, class.id, user.id).await? {
            return Ok(ClassView::Student);
        }
        return Err(AppError::NotFound("组织不存在".to_owned()));
    }
    // admin 或 teacher（非 owner）
    Err(if user.role == "admin" {
        AppError::Forbidden
    } else {
        AppError::NotFound("组织不存在".to_owned())
    })
}

fn ensure_class_manage(user: &AuthUser, class: &ClassRow) -> Result<(), AppError> {
    if is_class_owner(user, class) {
        return Ok(());
    }
    Err(if user.role == "admin" {
        AppError::Forbidden
    } else {
        AppError::NotFound("组织不存在".to_owned())
    })
}

fn ensure_assignment_read(
    pool: &PgPool,
    user: &AuthUser,
    assignment: &AssignmentRow,
    class: &ClassRow,
) -> Result<(), AppError> {
    if is_class_owner(user, class) {
        return Ok(());
    }
    if user.role == "student" && assignment.is_visible_to_student() {
        if is_active_member(pool, class.id, user.id).await? {
            return Ok(());
        }
    }
    Err(if user.role == "admin" {
        AppError::Forbidden
    } else {
        AppError::NotFound("作业不存在".to_owned())
    })
}

fn ensure_assignment_manage(
    user: &AuthUser,
    assignment: &AssignmentRow,
    class: &ClassRow,
) -> Result<(), AppError> {
    if is_class_owner(user, class) {
        return Ok(());
    }
    Err(if user.role == "admin" {
        AppError::Forbidden
    } else {
        AppError::NotFound("作业不存在".to_owned())
    })
}
```

注意：

- 学生非成员、非 owner 教师：404，不区分资源是否存在。
- 管理员访问教学接口：403，明确“角色没有教学能力”。
- owner 教师尝试提交作业：403，因为角色是 teacher，不是 student。
- 所有 handler 必须调用同一套 helper，不能各自写 `role == "admin"` 分支。

## 8. 前端设计

### 8.1 路由

```text
/classes                         组织列表，需要 student 或 teacher
/classes/:id                     组织详情，需要 student 或 teacher
/classes/:id/assignments/new     创建作业，需要 teacher
/assignments/:id                 作业详情，需要 student 或 teacher
/assignments/:id/edit            编辑作业，需要 teacher
/assignments/:id/grade           批改台，需要 teacher
/admin/users                     用户角色管理，需要 admin
```

路由 meta：

```ts
{ requiresAuth: true }
{ requiresAuth: true, requiresStudent: true }
{ requiresAuth: true, requiresTeacher: true }
{ requiresAuth: true, requiresAdmin: true }
```

守卫逻辑：

```ts
if (to.meta.requiresStudent && !authStore.isStudent) return { name: 'home' }
if (to.meta.requiresTeacher && !authStore.isTeacher) return { name: 'home' }
if (to.meta.requiresAdmin && !authStore.isAdmin) return { name: 'home' }
```

`authStore` 增加精确判断：

```ts
const isStudent = computed(() => user.value?.role === 'student')
const isTeacher = computed(() => user.value?.role === 'teacher')
const isAdmin = computed(() => user.value?.role === 'admin')
```

- `isTeacher` 不再包含 admin；`isAdmin` 不再包含教师能力。
- 兼容迁移期的本地缓存：`role === 'user'` 只在前端视为 `student`，后端以数据库为准。
- 管理员手动输入 `/classes` 时被守卫送回首页；教师输入 `/admin/users` 同样被送回。

### 8.2 导航栏

- 教师：题库、论坛、我的组织、通知、个人中心。
- 管理员：题库、论坛、管理、通知、个人中心。

- 管理员导航不出现“教学/我的组织”，避免误入教学区；“管理”包含论坛管理和用户管理两个入口。
- 教师导航不出现“管理”，管理员导航不出现“创建组织/批改”。

## 9. 安全、隐私与反滥用

### 9.1 越权与 IDOR

所有资源接口必须在服务端校验：

- 组织：owner 教师或 active 学生成员；管理员和其他教师不能访问；
- 作业：属于 owner 教师或 active 学生成员可访问的组织；
- 批改：仅 owner 教师；
- 提交详情：提交者本人，或该提交所属作业的 owner 教师；管理员不能凭 admin 角色查看；
- 角色修改：仅 admin；
- 练习提交：所有登录角色可用，但练习提交不进入任何组织成绩。

前端路由守卫只用于体验，不能作为权限边界。

### 9.2 邀请码

- 仅 `student` 可加入组织；教师和管理员调用返回 403。
- 8 位大写字母 + 数字，排除 `0/O/1/I` 等易混淆字符。
- 数据库唯一约束。
- 轮换后旧码立即失效。
- 加入接口限流，建议每用户 10 次/分钟。
- 邀请码不是秘密凭证，泄露只允许学生加入组织，不允许读取成绩或批改。

### 9.3 邮箱隐私

- owner 教师可以看到自己组织成员的邮箱，用于教学管理。
- 学生只能看到同学用户名，不返回邮箱。
- 管理员在用户管理列表可以看到账号邮箱，但看不到组织成员邮箱列表、作业、提交和成绩。
- 批改台只在 owner 教师响应中返回邮箱。

### 9.4 时间与截止

- 服务端时间是唯一权威，截止判断使用数据库 `NOW()`。
- 前端倒计时只做展示。
- 截止判断在写库事务内完成，避免预校验与 INSERT 之间跨过截止时间。
- 只有 `student` 能提交作业；教师和管理员只能运行预览。
- 教师延长截止时间后，学生可继续提交；不追溯已提交记录。
- 截止前提交、截止后判题完成的提交仍计入作业，以 `submitted_at` 为准。

### 9.5 成绩完整性

- 手动分范围 `0..points`。
- 只有 owner 教师能改分；管理员不能改分。
- 每次改分记录 `graded_by`、`graded_at`。
- 成绩发布要求作业已过截止时间，避免发布后仍有新提交改变总分。
- 成绩发布后修改立即生效，学生可见。
- 第一版不做完整审计表；P2 增加 `assignment_grade_audits`，记录改分前后值、原因、操作者。

### 9.6 XSS 与内容

- 作业标题、描述、评语都按纯文本存储。
- 描述和评语如果使用 Markdown 渲染，必须复用 `MarkdownBody` 的 `marked` + `DOMPurify` 白名单。
- 不在服务端拼接 HTML。
- 评语长度限制：单题 2000 字符，整体 5000 字符。

### 9.7 反滥用

- 创建组织：仅教师，建议每用户每天 20 个上限（可后续加）。
- 加入组织：仅学生，限流，防止邀请码枚举。
- 提交：仅学生可提交作业；练习提交复用现有频率与并发限制。
- 批改接口：只有 owner 教师，写操作频率低，暂不额外限流。
- 角色修改：仅管理员，记录操作者；涉及归档组织时必须显式确认。
- 管理员教学接口：服务端直接 403，不依赖前端隐藏。

### 9.8 审计

第一版记录：

- `classes.owner_id`；
- `assignments.created_by`；
- `assignment_problem_grades.graded_by` / `graded_at`；
- `assignment_results.graded_by` / `graded_at`；
- `users.role_changed_at`；
- 发布/归档时间。

角色变更同时写结构化日志：操作者、目标用户、前后角色、归档组织数量。后续增加统一 `audit_logs` 或 `assignment_grade_audits`。

### 9.9 角色边界

- 三个角色互斥，不存在 `is_teacher` 包含 admin 或 `is_admin` 包含教师的判断。
- 认证时读取数据库当前角色，JWT 中的旧角色不作为权限依据。
- 所有写操作同时校验角色和资源归属；角色正确但资源不属于自己，仍然拒绝。
- 角色转换必须满足清理条件；不能通过直接改数据库绕过，服务端和测试都要覆盖。
- 管理员只读审计教学数据不在本轮范围；如后续需要，新增独立只读接口和 `audit.teaching.read` 权限码，不复用教师权限。

## 12. 后续演进

> **当前实现（2026-10-27）：** 本文第 5、6 项“迟交策略”和“提交次数限制”已实现，并扩展为完整的作业策略：迟交宽限与扣分、每题次数、计分策略、成绩可见性、补交/免修、解析独立发布、匿名统计与策略审计。详细规则见 `doc/2610271_作业策略的实现.md`。

按优先级排列：

1. **成绩修改审计**：`assignment_grade_audits` 记录改分前后值、原因、操作者。
2. **组织 owner 转让与归档恢复**：教师离职或误归档时，由 owner 教师发起转让；管理员只做审批，不直接进入教学数据。
3. **管理员只读审计（后续）**：如确需，增加独立只读接口和 `audit.teaching.read` 权限码，仍需显式授权并留痕；不复用教师权限。第一版仍保持管理员不进入教学数据。
4. **关联账号/双角色**：如果确实需要同一个人既授课又学习，用关联账号而不是给单账号叠加角色。
5. **迟交策略**：`allow_late`、`late_penalty_percent`、迟交标记。
6. **提交次数限制**：`max_attempts`，并在提交事务中校验。
7. **协同教师（后续）**：新增独立的 `class_teachers` 关联表，只引用 `teacher`；不把教师放进 `class_members`，也不引入全局双角色。
8. **CSV 导入学生**：按学号/邮箱批量添加，返回失败清单。
9. **邮件通知**：SMTP、通知模板、发送失败重试、用户通知偏好。
10. **成绩申诉**：学生提交申诉，教师处理，记录状态。
11. **题目审核 UI**：学生或教师通过「个人出题」创建题目，管理员审核，复用现有 pending 接口。
12. **作业统计**：完成率、平均分、每题通过率、未提交名单、导出 CSV。
13. **防作弊**：按作业范围做代码相似度和行为信号，接入 `assignment_id`。
14. **学期表**：需要跨学期统计时，把 `classes.term` 升级为 `terms` 表。
15. **作业快照**：发布后冻结题目版本和分值，支持重判。

## 13. 风险与取舍

| 风险 | 影响 | 应对 |
|---|---|---|
| 认证额外读取数据库角色 | 每请求多一次主键查询 | 使用索引查询；如后续有性能压力再加短 TTL 缓存 |
| 前端缓存旧角色 | 导航短暂不一致 | 登录响应和 `/me` 返回当前角色；收到 403 时刷新角色 |
| 角色过于刚性 | 教师无法体验学生端 | 题目页“运行”预览；确需端到端验证时使用独立学生账号；后续评估关联账号 |
| 管理员看不到教学数据 | 客服/审计困难 | 本轮明确边界；后续增加独立只读接口和 `audit.teaching.read` 权限码，不复用教师权限 |
| 角色转换被组织阻塞 | 管理员操作失败 | 返回明确 409 和计数；教师降级支持确认归档；学生先退出组织 |
| 已发布作业题目被修改 | 成绩口径变化 | 发布后锁定题目和分值 |
| 题目被删除导致作业缺题 | 作业不完整 | `ON DELETE RESTRICT`，删除题目返回明确错误 |
| 成绩实时计算慢 | 大组织批改台卡顿 | 批量聚合查询；后续加缓存/快照 |
| 教师误改分 | 成绩争议 | 记录 `graded_by/at`；后续审计表 |
| 邀请码泄露 | 陌生人以学生身份加入组织 | 可轮换；加入限流；教师可移除 |
| 学生用教师账号代提交 | 成绩不可信 | 角色互斥降低风险；本轮不做防作弊；后续行为信号和相似度 |
| 邮件未做 | 学生错过通知 | 站内通知 + 导航未读数；邮件后续 |
| 管理员误操作 | 角色错误或误归档组织 | 不允许改自己；最后一个管理员保护；归档需显式确认；记录角色变更日志 |

## 14. 已确定与后续讨论

本轮已确定，不再作为阻塞项：

- 三个角色互斥，不做 `student ⊂ teacher ⊂ admin` 继承；
- 教师不能加入组织、不能提交作业；
- 管理员不能进入组织/作业/提交/成绩数据，也不能批改；
- 角色变更立即生效，认证以数据库角色为准；
- 学生升教师前必须退出所有组织；教师降级前必须没有未归档组织，或由管理员确认归档；
- 成绩发布要求作业已过截止时间。

后续再讨论：

- 是否增加管理员只读审计权限（`audit.teaching.read`）；
- 是否需要组织 owner 转让和归档恢复；
- 是否需要邀请码有效期；
- 是否需要作业发布后立即显示自动分（当前选择：不显示，发布成绩后统一显示）；
- 是否需要教师手动分支持小数（当前选择：整数）；
- 是否需要单账号关联学生/教师身份（当前选择：不做，使用独立账号）。
