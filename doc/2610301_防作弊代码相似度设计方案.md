# 防作弊 M2：代码相似度、复核与申诉

> 日期：2026-10-30
> 状态：已完成（作业提交 v1）
> 关联：`doc/总体设计.md` §4.7、`doc/backend_api.md`「防作弊复核与申诉接口」
> 迁移：`backend-rust/migrations/0025_anticheat.sql`

## 1. 目标与范围

本阶段把「检测 → 证据 → 人工复核 → 处罚 → 申诉 → 审计」闭合成可演示、可回归的链路，同时坚持**相似度只生成报告，不自动定罪**。

v1 的明确边界：

| 项目 | v1 行为 |
|---|---|
| 比对对象 | 仅带 `assignment_id` 的作业提交 |
| 比对范围 | 同一作业、同一题目、同一语言、最近 `ANTICHEAT_WINDOW_DAYS` 天 |
| 候选上限 | 单次最多 `ANTICHEAT_MAX_CANDIDATES` 份历史提交 |
| 排除项 | 同一学生的历史提交、`internal_error` 提交、token 数不足 `ANTICHEAT_MIN_TOKENS` 的代码 |
| 跨语言 | 不做；留待后续结构特征方案 |
| 自动处分 | 不做；教师确认后才可选择判零 |
| 申诉处理人 | 该报告的处理人（`cheat_reports.reviewer_id`）；v1 中即作业所属教师 |

## 2. 状态机

```text
cheat_reports
  open ──教师确认──> confirmed ──学生申诉──> appealed ──维持──> upheld
    │                    │                      └────撤销──> overturned
    └──教师排除──> dismissed

appeals
  pending ──处理人维持──> upheld
      └────处理人撤销──> overturned
```

- 每个 `submission_id` 最多一条报告；重复扫描不会重复生成。
- 只有 `open` 可以复核；只有 `confirmed` 可以申诉；只有 `pending` 申诉可以裁定。
- 确认后若选择判零，`penalty_applied_at` 非空，`penalty_before` 保存判零前的人工分快照。
- 申诉撤销时按 `penalty_before` 恢复成绩：此前无人工分则删除判零记录，此前有人工分则恢复原分数、评语与批改人。

## 3. 数据模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| `submission_signals` | `submission_id`, `signal_type`, `value JSONB`, `source` | `scan_completed` 每份提交唯一；`scan_attempt` 记录重投次数 |
| `similarity_pairs` | `submission_a`, `submission_b`, `problem_id`, `assignment_id`, `algorithm`, `score`, `detail` | `submission_a < submission_b` 保证同一对只存一次 |
| `cheat_reports` | `target_user_id`, `submission_id UNIQUE`, `assignment_id`, `problem_id`, `severity`, `score`, `matched_*`, `status`, `evidence`, `reviewer_id`, `decision_note`, `penalty_applied_at`, `penalty_before` | 超过报告阈值的提交 |
| `appeals` | `report_id UNIQUE`, `user_id`, `reason`, `status`, `handled_by`, `handle_note`, `handled_at` | 每份报告一次申诉 |
| `cheat_report_actions` | `report_id`, `actor_id`, `action`, `note`, `created_at` | `created/confirmed/dismissed/appealed/upheld/overturned/penalty_restored` 审计轨迹 |

`similarity_pairs.detail` 保存 `containment`、`jaccard`、指纹数量与匹配片段区间；不重复保存完整源码，源码仍只在 `submissions` 中。

## 4. 相似度算法

实现位于 `backend-rust/src/services/similarity.rs`，不引入 tree-sitter 等新依赖。

1. **词法归一化**：去掉行注释、块注释与字符串内容；标识符统一为 `ID`，数字统一为 `NUM`，字符串统一为 `STR`；保留语言关键字与标点。支持 `python`、`javascript`、`cpp`、`java`，其他语言按 C 风格词法处理。
2. **k-gram 指纹**：对归一化 token 序列取 `K=5` 的连续片段，用 FNV-1a 哈希；token 间加分隔符避免边界碰撞。
3. **winnowing**：滑动窗口 `W=4` 取每个窗口的最小哈希并去重，得到指纹集合。
4. **打分**：`score = max(containment, jaccard)`。`containment = 交集 / 较小指纹集合`，对「复制主体后少量加料」更稳定；短片段整体复制时 jaccard 易被稀释，因此取较大值。
5. **证据片段**：把匹配哈希映射回 token 下标，合并相邻区间，最多保留 40 段。

阈值分级：

| 分数 | 级别 | 行为 |
|---|---|---|
| `< ANTICHEAT_RECORD_THRESHOLD` | — | 不写 `similarity_pairs` |
| `>= record` 且 `< report` | `low` | 只保留比对记录，不生成报告 |
| `>= report` | `medium` | 生成 `open` 报告 |
| `>= high` | `high` | 生成 `open` 报告，前端优先展示 |

默认值：record `0.60`、report `0.80`、high `0.92`；启动时校验 `record <= report <= high`。

## 5. 扫描流程与队列

```text
judge_worker 判题落库成功（含编译错误）
  → XADD theseus:anticheat:scan submission_id <id>
  → anticheat_worker（独立二进制）
      1. 读取提交，跳过非作业/内部错误/代码过短
      2. 检查 scan_completed 信号，已扫描直接 ACK
      3. 查询同作业/同题/同语言/时间窗内的历史提交
      4. 逐个指纹比对，写入 similarity_pairs
      5. 达到报告阈值则写 cheat_reports + created 审计 + 通知作业教师
      6. 写 scan_completed 信号
```

幂等与重试：

- `submission_signals` 的部分唯一索引 `(submission_id) WHERE signal_type='scan_completed'` 保证只扫一次；
- `similarity_pairs (submission_a, submission_b, algorithm)` 唯一，重复写入改为更新；
- `cheat_reports.submission_id` 唯一，重复扫描不会重复通知；
- 消费组使用 `XREADGROUP`，崩溃消息由 `XAUTOCLAIM` 回收；
- 回收超过 `ANTICHEAT_MAX_DELIVERIES` 次后写入死信 Stream，并记录 `scan_completed: dead_letter`，避免毒消息阻塞队列；
- 扫描不依赖 Docker，`dev.sh` 单独启动 `anticheat_worker`，不要求 `sudo`。

## 6. 权限

| 接口 | 权限 |
|---|---|
| `GET /api/teacher/cheat-reports` | `teacher`，且只返回自己组织作业的报告 |
| `GET /api/teacher/cheat-reports/{id}` | 同上；非本人组织返回 404，避免泄露报告存在性 |
| `POST /api/teacher/cheat-reports/{id}/review` | 同上；只能处理 `open` |
| `GET /api/teacher/appeals` | 登录用户，只返回 `reviewer_id = 当前用户` 的待处理申诉 |
| `POST /api/teacher/appeals/{id}/resolve` | 只有该报告的处理人可裁定 |
| `GET /api/cheat-reports/mine` | 登录用户，只返回 `target_user_id = 当前用户` 且已确认/申诉中的报告 |
| `GET /api/cheat-reports/{id}` | 报告当事人；学生看不到比对对方的身份与代码 |
| `POST /api/cheat-reports/{id}/appeal` | 报告当事人，报告必须为 `confirmed` |

学生接口不返回 `matched_username`、对方提交代码或证据片段，避免二次传播；教师详情才展示双方代码。

## 7. 判零与恢复

- 确认对话框提供「同时将该题作业判 0 分」复选框，默认关闭；
- 勾选后 upsert `assignment_problem_grades.manual_score = 0`，评语标记为防作弊复核；
- 判零前读取并保存 `(manual_score, feedback, graded_by)` 到 `cheat_reports.penalty_before`；
- 申诉撤销且存在判零记录时，按快照恢复；快照为 `null` 表示此前没有人工分，直接删除该行；
- 不修改自动判题分、测试用例结果或提交状态，只影响该题作业成绩的计算。

## 8. 配置

`backend-rust/.env.example` 新增：

```text
ANTICHEAT_ENABLED=true
ANTICHEAT_STREAM=theseus:anticheat:scan
ANTICHEAT_CONSUMER_GROUP=anticheat-workers
ANTICHEAT_DEAD_STREAM=theseus:anticheat:scan:dead
ANTICHEAT_WORKER_NAME=anticheat-1
ANTICHEAT_WORKER_CONCURRENCY=1
ANTICHEAT_MAX_DELIVERIES=3
ANTICHEAT_CLAIM_INTERVAL_SECS=30
ANTICHEAT_WINDOW_DAYS=30
ANTICHEAT_MAX_CANDIDATES=200
ANTICHEAT_RECORD_THRESHOLD=0.60
ANTICHEAT_REPORT_THRESHOLD=0.80
ANTICHEAT_HIGH_THRESHOLD=0.92
ANTICHEAT_MIN_TOKENS=40
```

关闭 `ANTICHEAT_ENABLED` 后判题 worker 不入队，`anticheat_worker` 启动后直接退出。

## 11. 已知限制与后续

- 只有 token 级词法指纹，变量重命名与空行调整较稳，但结构性改写、跨语言抄袭识别有限；
- 同题同作业范围避免跨作业误报，也意味着换作业复制暂不检测；
- 行为信号（粘贴、切屏）仍只用于竞赛监考，尚未并入作业报告；
- 未提供报告导出、批量复核、赛季/组织维度相似度图；
- 阈值需用真实作业样本校准，建议先保持「只记录/报告、不自动处分」。
