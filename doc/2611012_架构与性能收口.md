# 架构与性能收口设计方案

> 日期：2026-11-01
> 状态：v1 已实现
> 关联：`2610305_服务器部署方案.md`、`backend_api.md`、`AGENTS.md`

## 1. 目标

功能线基本铺满后，先补齐三处会随功能继续增长而变差的基础设施：

- 前端首屏体积：所有页面在路由入口同步 import，打包成单个大文件
- 后端可观测性：没有指标接口，队列积压与 Worker 掉线只能靠日志
- 工程护栏：格式化、静态检查、类型检查与构建全靠手动执行

三处都是低风险改动，不改变任何业务行为。

## 2. 前端路由懒加载

`frontend-vue/src/router/index.ts` 只保留首页与登录页的静态 import，其余 41 个页面改为
`const Page = () => import('../views/Page.vue')`，路由表本身不用改。

- 首包从 752 KB（单文件）降到约 141 KB，gzip 47.7 KB，构建不再有 chunk 超限警告
- 题目页、论坛详情等高依赖页面按需加载，首屏不下载
- Monaco 仍由 `public/monaco` 自托管静态资源提供，运行期由 loader 拉取，不进入 JS 包

## 3. 后端 `/metrics`

新增 `GET /metrics`，输出 Prometheus 0.0.4 文本格式。实现分两层：

- `src/utils/metrics.rs`：只用标准库原子计数，记录 HTTP 指标，不新增依赖
- `src/handlers/metrics_handler.rs`：追加抓取时现读的队列、连接池与 Worker 指标

| 指标 | 类型 | 标签 | 说明 |
|---|---|---|---|
| `theseus_http_requests_total` | counter | `method`、`route`、`status` | `route` 取 `MatchedPath` 模板，`status` 按 1xx–5xx 归类 |
| `theseus_http_request_duration_seconds` | histogram | `method`、`route` | 桶 5ms、10ms、25ms、50ms、100ms、250ms、500ms、1s、2.5s、5s、+Inf |
| `theseus_http_requests_in_flight` | gauge | 无 | 正在处理的请求，包含 WebSocket 长连接 |
| `theseus_db_pool_connections` | gauge | `state`=size / idle / max | 连接池水位 |
| `theseus_judge_enabled` | gauge | 无 | 是否配置了 Redis 判题队列 |
| `theseus_judge_stream_length` | gauge | `queue`=run / submit / anticheat | Stream 长度，含未确认 |
| `theseus_judge_stream_pending` | gauge | `queue` | 消费组已投递未确认数 |
| `theseus_judge_dead_letters` | gauge | `queue` | 死信 Stream 长度 |
| `theseus_judge_worker_up` | gauge | `kind`=run / submit / anticheat | 是否存在存活心跳键 |
| `theseus_build_info` | gauge | `version` | 常量 1，用于版本对齐 |

实现要点：

- 采集层用 `Router::route_layer` 而不是 `Router::layer`：只有路由匹配之后 `MatchedPath` 才写入请求扩展，放在 `layer` 上只能拿到真实路径，会把 `/problem/1`、`/problem/2` 拆成无数条时间序列
- 未匹配路由的 404 不进入统计，避免扫描流量制造基数
- 队列指标只读 `XLEN` / `XINFO GROUPS` / 心跳键，不修改任何队列状态
- Redis 或队列读取失败时跳过对应样本，抓取本身仍返回 200，不影响健康检查
- 指标接口与 `/healthz`、`/readyz` 一样不带鉴权，只暴露计数、连接数与队列长度，不含用户数据

推荐告警项：队列长度持续增长、死信数大于 0、`theseus_judge_worker_up == 0` 超过 1 分钟、5xx 比例超过 1%。

## 4. CI

新增 `.github/workflows/ci.yml`，三个并行任务：

| 任务 | 内容 |
|---|---|
| backend | `cargo fmt --all --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test --all-targets` |
| frontend | `npm ci`、`npm run build`（`vue-tsc` 类型检查 + Vite 构建） |
| scripts | 对根目录、`deploy/scripts`、`backend-rust/scripts` 下全部脚本执行 `bash -n` |

CI 不依赖数据库：项目未使用 `sqlx` 编译期宏，单元测试不连库，迁移检查留给 `update.sh` 的启动流程。

## 5. 验证
