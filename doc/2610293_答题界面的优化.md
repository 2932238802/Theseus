# 答题界面的优化

## 背景

当前答题页默认语言为 JavaScript，与以算法竞赛为主的使用场景不一致。切换到 C++ 时，编辑器需要等待 Monaco 初始化或切换模型，用户会感知到明显延迟。题面以纯文本段落展示，Markdown 图片被过滤，二维数组、岛屿问题等题目缺少直观的图示表达。

## 目标

1. 新打开题目时默认使用 C++，并保留用户在本地的语言选择。
2. 语言切换立即反馈，编辑器不因切换出现空白或重复初始化。
3. 题面支持安全的 Markdown 图片，并适配图片题、二维网格题和移动端阅读。
4. 保留现有提交、运行、草稿和快捷键行为。

## 交互设计

### 语言选择

- 首次使用默认选择 `C++`；已有用户偏好时使用偏好值。
- 语言选择器放在编辑器工具栏左侧，切换后立即更新语法高亮、代码模板和草稿。
- 切换语言时保留每种语言独立草稿，不覆盖另一语言的代码。
- 编辑器切换期间保持当前代码区域尺寸，显示轻量的“正在切换”状态；不显示全屏 loading。
- 选择结果写入 `localStorage`，键名建议为 `theseus-preferred-language`。
- C++ 模板使用题目提供的 `codeTemplate.cpp`，没有模板时显示可运行的空模板并允许编辑。

### 切换性能

- Monaco 只初始化一次；语言变化使用已有 model 的 `setModelLanguage`，禁止重新挂载 `CodeEditor`。
- 在页面首次加载时并行准备编辑器和题目数据；语言切换只更新模型、草稿和模板。
- 切换操作需在 100ms 内更新选择器和编辑器状态，目标是在已完成 Monaco 初始化后 300ms 内完成高亮切换。
- 连续快速切换时只处理最后一次选择，避免旧异步任务覆盖新语言。
- 切换失败时恢复上一次可用语言，并给出非阻塞错误提示。

### 题面图片

- 题目描述继续使用 Markdown，支持 `![说明](https://...)` 图片语法。
- 图片白名单仅允许 `https`（开发环境可允许 `http`），禁止 `data:`、脚本协议和内联事件属性。
- 图片加载失败显示替代文本，不影响题面其余内容。
- 图片默认 `max-width: 100%`，保持比例；点击图片可打开大图预览，预览层支持关闭和 Esc 返回。
- 图片应带有可读的 alt 文本；后台题目编辑器在保存前提示缺少 alt 文本。
- 二维数组题建议使用“题面图 + 文本矩阵”双表达：图片帮助理解，文本示例保证可复制和无障碍访问。
- 移动端图片不超出题面容器；大图预览禁止页面横向滚动。

## 技术方案

### 前端

- `OjPage.vue` 将 `language` 初始值改为读取本地偏好，缺省值为 `cpp`。
- 语言切换时先保存当前草稿，再读取目标语言草稿或模板；不要用统一的 `code` 值覆盖各语言草稿。
- `CodeEditor.vue` 保持单一 Monaco 实例，缓存 `monacoApi`，直接调用 `setModelLanguage`；为语言切换增加请求序号或取消旧 Promise。
- `MarkdownBody.vue` 将 `img` 加入允许标签，允许 `src`、`alt`、`title`，并通过 DOMPurify 的 URI 校验限制协议和域名；移除对 `img` 的禁止规则。
- 为图片增加统一样式和预览组件，预览状态使用 Teleport，关闭后恢复题面焦点。

### 数据与安全

- 题目描述字段继续存储 Markdown，不新增图片专用字段；后续如需上传图片，再增加对象存储 URL 和媒体审核流程。
- 服务端若存在 Markdown 清洗，也必须采用同等或更严格的协议白名单，不能只依赖前端过滤。
- 外链图片默认不发送 referrer（可在预览容器设置 `referrerpolicy="no-referrer"`）。

## 验收标准

- 新用户进入任意题目，语言选择器显示 C++，编辑器显示 C++ 模板。
- 刷新页面后仍使用用户上次选择的语言；切换语言后各语言草稿互不覆盖。
- C++、Java、Python、JavaScript 连续切换 10 次无空白编辑器、无旧语言覆盖和控制台未处理异常。
- 含图片的题面能显示、缩放、预览和关闭；恶意协议、脚本和事件属性不会被渲染。
- 岛屿问题等二维网格题同时支持图片与文本矩阵，桌面和移动端均无横向溢出。
- 运行、提交、重置代码、快捷键和历史草稿行为保持正常。

## 实施顺序

1. 默认语言、本地偏好和按语言草稿。
2. Monaco 单实例切换与切换状态。
3. Markdown 图片清洗、样式和预览。
4. 题目编辑器的图片说明校验及二维网格题示例补充。
5. 执行上述验收用例并补充回归测试。
