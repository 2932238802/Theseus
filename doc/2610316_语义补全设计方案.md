# 题目编辑器语义补全（LSP）设计方案

> 日期：2026-10-31
> 状态：v1 已实现（C++ / Python）
> 关联：`2610305_服务器部署方案.md`、`2610295_实时推送设计方案.md`

## 1. 目标

- 用真正的语言服务器替换前端静态补全，提供补全、诊断与悬停
- v1 只支持 C++ 与 Python；切换到其它语言时「语义补全」按钮置灰
- 比赛模式下不可开启；默认关闭，用户选择写入 localStorage
- 语言服务运行在服务端，浏览器无需下载 WASM 或额外运行时

## 2. 架构

```text
浏览器 CodeEditor
  └─ Monaco provider（补全 / 悬停 / 诊断）
       └─ WebSocket /api/lsp/ws?ticket=...
            └─ lsp_gateway（Rust，默认 3001）
                 └─ stdio JSON-RPC
                      └─ clangd（C++） / pyright-langserver（Python）
```

- 票据：`POST /api/lsp/ticket` 需要登录 JWT，返回 60 秒有效的短期票据；票据是独立签名的 JWT，包含 `sub`、`purpose=lsp`、`lang`，网关无需访问数据库
- 网关：`backend-rust/src/bin/lsp_gateway.rs`，校验票据后为每个 WebSocket 连接启动一个语言服务器子进程，并在 `/tmp` 下创建独立工作区
- 代理：生产由前端 Nginx 反代 `/api/lsp/ws` 到 `lsp:3001`；开发由 Vite 代理到 `127.0.0.1:3001`
- 并发：`LSP_MAX_SESSIONS` 控制同时运行的语言服务数量，超限直接返回 503

## 3. 会话流程

1. 前端用登录 JWT 换取票据
2. 建立 WebSocket；网关先发送 `theseus/ready`，其中 `rootUri` 指向本次会话的临时工作区
3. 前端发送 `initialize`：声明补全、悬停、诊断能力，C++ 附带 `fallbackFlags: ["-std=c++17"]`（与判题参数一致）
4. 发送 `initialized` 与 `textDocument/didOpen`，文档路径为 `<rootUri>/main.cpp` 或 `main.py`
5. 编辑时发送增量 `textDocument/didChange`；Monaco 的变更范围基于变更前文档，按 `rangeOffset` 降序发送可保证顺序应用
6. 语言服务器返回 `textDocument/publishDiagnostics`；前端用 `monaco.editor.setModelMarkers` 展示
7. 关闭页面或关闭开关时断开 WebSocket，网关关闭 stdin、结束子进程并删除临时目录

语言服务器主动发起的请求统一由前端应答：

| 请求 | 响应 |
| --- | --- |
| `workspace/configuration` | 与 `items` 等长的 `null` 数组 |
| `workspace/workspaceFolders` | 当前会话工作区 |
| `workspace/applyEdit` | `{applied: false}` |
| 其它 | `null` |

## 4. 前端实现

- `src/api/lsp.ts`：换取票据，解析 `ticket`、`expires_in_seconds`、`language` 与 `path`
- `src/utils/lspClient.ts`：轻量 JSON-RPC 客户端，负责初始化、增量同步、补全/悬停映射、诊断标记与清理；不引入 `monaco-languageclient`，避免改动现有自托管 AMD Monaco 加载方式
- `CodeEditor.vue`：新增 `lspEnabled` 属性与 `lsp-status` 事件；仅在开关开启且语言受支持时创建会话，切换语言或开关时销毁重建
- `OjPage.vue`：按钮文案为「语义补全」；`contestId !== null` 或语言不在 `cpp` / `python` 时置灰；工具栏显示「连接中」「连接失败」
- 关闭补全时同时禁用 Ctrl+Space 并关闭 Monaco 自带单词补全，避免出现与语言服务无关的零散建议

## 5. 部署

- `backend-rust/Dockerfile` 新增 `lsp` 阶段：`node:22-bookworm-slim` + `clangd` + `g++` + `python3` + `python-is-python3` + `pyright@1.1.414`，以非 root 用户运行
- `deploy/compose.yaml` 新增 `lsp` 服务，不发布端口，`/tmp` 使用 tmpfs，健康检查访问 `/healthz`
- `dev.sh` 同时编译并启动 `lsp_gateway`；本地需自行安装 `clangd` 与 `pyright`，并确保存在 `python` 命令（如 `python-is-python3`）
- 相关环境变量：`LSP_ENABLED`（API 是否签发票据）、`LSP_BIND_ADDRESS`、`LSP_MAX_SESSIONS`、`LSP_CPP_COMMAND` / `LSP_CPP_ARGS`、`LSP_PYTHON_COMMAND` / `LSP_PYTHON_ARGS`

## 6. 限制

- 每个会话只有一个空工作区与一个源文件，没有工程级跨文件上下文与第三方头文件索引
- 语言服务直接解析用户代码，未放入 runsc 沙箱；镜像以非 root 运行并限制并发
- 票据在 60 秒内可重放，网关不记录已用票据
- 暂不支持 Java 与 JavaScript
- 比赛模式禁用在 UI 层实现，票据接口本身不校验用户是否正在比赛
- 同时开启语义补全的用户数受 `LSP_MAX_SESSIONS` 限制，超出时前端显示「连接失败」
