## 0. 结论速览

| 决策项 | 本期选择 |
|---|---|
| 策略配置粒度 | 逐作业配置；提交次数支持题目级覆盖 |
| 迟交 | 默认禁止；开启后 `due_at + late_grace_hours` 内可交 |
| 迟交判定 | `due_at` 之后即算迟交，不足一天按一天计 |
| 迟交扣分 | 默认 10%/天，封顶 50%；按单题分值扣，向上取整 |
| 迟交窗口 | 固定宽限时长；超过窗口直接拒绝 |
| 延期追溯 | 不追溯；`is_late/late_days` 在提交时冻结 |
| 提交次数 | 默认不限；作业级 `max_attempts`，题目可覆盖 |
| 次数计数 | 所有提交都计；`internal_error` 等系统错误不计 |
| 计分策略 | 逐作业可选 `highest` / `last` / `first_ac`，默认 `highest` |
| 手动分 | 教师手动分优先级最高，可覆盖自动分和迟交扣分 |
| 成绩可见性 | 默认教师发布后可见；另支持截止后自动可见、进行中可见 |
| 教师评语 | 无论何种可见性，始终在教师发布成绩后才可见 |
| 答案/解析 | 教师按题填写，独立发布；要求作业已截止 |
| 补交 | 教师按“学生+题目”设置；默认视为准点不扣分，可选仍扣迟交 |
| 免修 | 教师按“学生+题目”设置；可选计满分或从总分分母排除 |
| 组织统计 | 默认关闭；开启后学生只看匿名聚合和分位区间 |
| 他人代码 | 默认关闭；开启后只看已发布成绩同学的 AC 代码 |
| 策略变更 | 发布后锁定；只允许延期、补交、免修，全部写审计和通知 |
| 实施方式 | 分两期：P1 策略核心，P2 例外与学习能力 |

**一句话总结：** 把作业从“只有截止时间”升级为“可配置的教学策略”，用类型化字段保存策略，用学生例外表处理补交/免修，用统一计算模块保证详情页、批改台和提交校验口径一致。

## 1. 目标与非目标

### 1.1 目标

1. 教师创建或编辑作业时，可以配置迟交、提交次数、计分和可见性策略。
2. 学生在提交前能看到自己的有效截止时间、剩余次数和迟交预估，减少误操作。
3. 迟交、次数上限和免修在提交事务内强制校验，不能靠前端隐藏按钮。
4. 批改台、学生作业详情和提交记录使用同一套分数计算规则。
5. 教师可以按“学生+题目”补交或免修，并记录原因、操作者和时间。
6. 教师可以独立发布答案解析，且只能在作业截止后发布。
7. 学生可见的成绩、统计和他人代码都遵循作业级开关，不泄露未发布数据。
8. 所有发布后策略变更、补交、免修和解析发布都有审计记录。
9. 默认值兼容现有行为：禁止迟交、不限次数、取最高、发布成绩后可见。

### 1.2 非目标

本轮明确不做：

- 学生发起补交/免修申请与教师审批流；
- 迟交申诉、成绩申诉；
- 邮件通知（继续使用站内通知）；
- 按作业导出 CSV 成绩单；
- 题目级随机变体、重判和成绩快照；
- 学生之间的代码评论、点赞；
- 组织/作业排行榜的实名公开；
- 管理员进入教学数据查看或修改；
- 学生级提交次数例外（次数只支持作业默认 + 题目覆盖）；
- 自动识别“系统错误”之外的作弊或异常行为。

## 3. 策略语义

### 3.1 迟交

作业级字段：

| 字段 | 默认 | 范围 | 说明 |
|---|---:|---:|---|
| `late_policy` | `forbid` | `forbid` / `allow` | 是否允许迟交 |
| `late_grace_hours` | 0 | 0..720 | 截止后的允许提交窗口 |
| `late_penalty_per_day` | 10 | 0..100 | 每迟交一天扣单题分值的百分比 |
| `late_penalty_cap` | 50 | 0..100 | 迟交总扣分上限百分比 |

规则：

1. 只有 `late_policy = 'allow'` 时，`due_at` 之后仍可提交。
2. 提交窗口结束时间 = 有效截止时间 + `late_grace_hours`。
3. 有效截止时间 = `max(assignment.due_at, override.makeup_due_at)`；没有补交时等于作业截止时间。
4. `due_at` 之后即算迟交，宽限期内同样扣分；宽限期只决定“还能不能交”。
5. 迟交天数 = `ceil((计分提交时间 - assignment.due_at) / 24h)`，不足一天按一天计。
6. 延期不追溯：提交时冻结原始 `is_late` 和 `late_days`，教师后来延长 `due_at` 不改变历史提交；补交例外在计分时另行应用，不改写原始快照。
7. 超过提交窗口后在事务内拒绝，返回 409“作业已截止”。

### 3.2 提交次数

作业级字段：

| 字段 | 默认 | 说明 |
|---|---|---|
| `assignments.max_attempts` | `NULL` | `NULL` 表示不限；正整数表示每题默认上限 |
| `assignment_problems.max_attempts` | `NULL` | `NULL` 表示继承作业默认；非空则覆盖 |

规则：

1. 次数按“学生 × 题目”独立计算，不共享整个作业的额度。
2. 有效上限 = `COALESCE(assignment_problems.max_attempts, assignments.max_attempts)`；两者都为 `NULL` 表示不限。
3. 计数口径：该学生在该作业该题目下的所有提交，`status = 'internal_error'` 除外。
4. `pending`、`judging`、编译错误、答案错误、超时、运行时错误都计一次。
5. 判题重试产生的 `submissions.attempt_count` 是 Worker 重试次数，不是学生提交次数，不参与本规则。
6. 达到上限后，该题拒绝新提交，返回 409“该题提交次数已用完”。
7. 学生可以在提交前看到 `attempts_used`、`attempts_limit` 和 `attempts_left`。

### 3.3 计分策略

作业级字段：

| 值 | 含义 |
|---|---|
| `highest`（默认） | 只要存在 `accepted`，该题自动分即为满分；迟交按最早 AC 提交计算 |
| `last` | 以最后一次非系统错误提交为准；最后一次不是 `accepted` 则自动分 0；迟交按最后提交计算 |
| `first_ac` | 以首次 `accepted` 提交为准；之后提交不改变自动分；迟交按首次 AC 计算 |

说明：

- 当前判题为二值分数，`highest` 和 `first_ac` 的自动分结果相同；区别在迟交判定和后续扩展部分分时的语义。
- 自动分先按分值计算，再扣迟交。
- 教师手动分完全覆盖自动分和迟交扣分。
- 免修规则优先于自动分，但低于手动分。
- 总分 = 各题最终分之和；被免修排除的题不计入分母。

固定优先级（从高到低）：

```text
1. 教师手动分
2. 免修 full_score：该题计满分
3. 免修 excluded：该题从总分分子和分母排除
4. 自动分 - 迟交扣分
5. 系统错误提交不参与计分和次数统计
```

其中 `full_score` 与 `excluded` 互斥；只要教师写了手动分，就以手动分为准。

### 3.4 成绩可见性

作业级字段 `score_visibility`：

| 值 | 学生何时可见分数 |
|---|---|
| `after_publish`（默认） | `grades_published_at IS NOT NULL` 后 |
| `after_due` | `now >= due_at` 后 |
| `during` | 作业发布后立即可见 |

规则：

1. 该字段只控制“分数”可见性，包括单题得分和总分。
2. 教师评语、整体评语始终只在 `grades_published_at` 之后可见，避免学生提前看到未定稿评语。
3. 教师发布成绩仍要求作业已截止，保持现有成绩稳定性。
4. 成绩发布后教师继续改分，学生立即看到新分数，本轮不做成绩快照。
5. 未到可见时机时，学生仍可看到提交状态、尝试次数、是否 AC、迟交标记，但不返回分数。

### 3.5 答案与解析

- 解析保存在 `assignment_problems.solution_md`，由教师在组题时按题填写。
- 发布动作独立于成绩发布，使用 `assignments.solutions_published_at`。
- 发布前置条件：作业 `published`、组织未归档、`due_at <= NOW()`。
- 发布后学生可见对应题目的解析；未发布时接口不返回 `solution_md`。
- 补交学生在解析发布后仍可提交，但无法再获得“未泄露答案”的保证；这是教师主动发布的结果。
- 发布解析发送站内通知；重复发布幂等，不重复通知。

### 3.6 补交与免修

学生例外表按“学生 + 题目”存储：

| 字段 | 说明 |
|---|---|
| `makeup_due_at` | 补交截止时间；必须晚于作业 `due_at` |
| `waive_late_penalty` | 补交是否免迟交扣分，默认 `true` |
| `exempt` | 是否免修该题 |
| `exemption_mode` | `full_score` 或 `excluded` |
| `reason` | 教师填写的原因，最多 2000 字符 |

规则：

1. 只有组织 owner 教师可以设置或撤销例外。
2. 目标学生必须是组织 active 成员；`removed` 学生只能查看历史，不能新增例外。
3. 题目必须属于该作业。
4. `makeup_due_at` 只延长、不缩短；有效截止时间取与作业 `due_at` 的较大值。
5. 补交窗口内提交默认视为准点，不扣迟交；教师可取消 `waive_late_penalty`，此时仍按原 `due_at` 计算迟交。
6. 免修题不再接受新提交，提交返回 409“该题已免修”。
7. 免修 `full_score`：该题最终分为满分，总分分母包含该题分值。
8. 免修 `excluded`：该题从总分分子和分母中同时排除，成绩单显示“免修（不计分）”。
9. 手动分可以覆盖免修结果；教师显式给分时以手动分为准。
10. 例外变更写审计，并通知对应学生。

### 3.7 组织统计与他人代码

作业级字段：

| 字段 | 默认 | 说明 |
|---|---|---|
| `show_class_stats` | `false` | 学生是否可见组织统计 |
| `allow_peer_code` | `false` | 学生是否可见同学 AC 代码 |

组织统计只返回：

- 组织平均分；
- 每题通过率；
- 学生自己的总分；
- 学生自己的分位区间：`top10` / `top25` / `top50` / `rest`；
- 不返回同学姓名、邮箱、具体分数或排名列表。

他人代码规则：

- 只在 `allow_peer_code = true` 且学生已可见成绩时开放；
- 只返回 active 成员的 `accepted` 提交代码；
- 返回用户名、语言、提交时间、代码；
- 不返回邮箱、用户 id、提交 id、隐藏用例和判题输出。

### 3.8 默认值与发布后修改

新作业默认值：

```text
late_policy             = forbid
late_grace_hours        = 0
late_penalty_per_day    = 10
late_penalty_cap        = 50
max_attempts            = NULL
scoring_policy          = highest
score_visibility        = after_publish
allow_peer_code         = false
show_class_stats        = false
solutions_published_at  = NULL
```

发布后修改规则：

| 状态 | 允许修改 |
|---|---|
| `draft` | 全部策略、题目、分值、时间 |
| `published` | 只能延长 `due_at`；其余策略字段锁定 |
| `published` | 允许补交、免修、发布解析 |
| `archived` | 全部只读 |

- 发布后尝试修改锁定字段返回 409“作业已发布，策略不可修改”。
- 延长截止时间写审计；是否通知学生由实现统一选择“发送”，避免学生错过变更。
- 补交、免修、解析发布均写审计和站内通知。

## 4. 数据模型

### 4.1 ER 关系


### 4.2 迁移 SQL：`0009_assignment_policies.sql`

```sql
-- 1. 作业策略字段
ALTER TABLE assignments
    ADD COLUMN IF NOT EXISTS late_policy VARCHAR(20) NOT NULL DEFAULT 'forbid',
    ADD COLUMN IF NOT EXISTS late_grace_hours INTEGER NOT NULL DEFAULT 0,
    ADD COLUMN IF NOT EXISTS late_penalty_per_day INTEGER NOT NULL DEFAULT 10,
    ADD COLUMN IF NOT EXISTS late_penalty_cap INTEGER NOT NULL DEFAULT 50,
    ADD COLUMN IF NOT EXISTS max_attempts INTEGER,
    ADD COLUMN IF NOT EXISTS scoring_policy VARCHAR(20) NOT NULL DEFAULT 'highest',
    ADD COLUMN IF NOT EXISTS score_visibility VARCHAR(20) NOT NULL DEFAULT 'after_publish',
    ADD COLUMN IF NOT EXISTS solutions_published_at TIMESTAMPTZ,
    ADD COLUMN IF NOT EXISTS allow_peer_code BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN IF NOT EXISTS show_class_stats BOOLEAN NOT NULL DEFAULT FALSE;

ALTER TABLE assignments
    ADD CONSTRAINT assignments_late_policy_check
        CHECK (late_policy IN ('forbid', 'allow')),
    ADD CONSTRAINT assignments_late_grace_hours_check
        CHECK (late_grace_hours >= 0 AND late_grace_hours <= 720),
    ADD CONSTRAINT assignments_late_penalty_per_day_check
        CHECK (late_penalty_per_day >= 0 AND late_penalty_per_day <= 100),
    ADD CONSTRAINT assignments_late_penalty_cap_check
        CHECK (late_penalty_cap >= 0 AND late_penalty_cap <= 100),
    ADD CONSTRAINT assignments_max_attempts_check
        CHECK (max_attempts IS NULL OR (max_attempts > 0 AND max_attempts <= 1000)),
    ADD CONSTRAINT assignments_scoring_policy_check
        CHECK (scoring_policy IN ('highest', 'last', 'first_ac')),
    ADD CONSTRAINT assignments_score_visibility_check
        CHECK (score_visibility IN ('after_publish', 'after_due', 'during'));

-- 2. 题目解析与次数覆盖
ALTER TABLE assignment_problems
    ADD COLUMN IF NOT EXISTS solution_md TEXT,
    ADD COLUMN IF NOT EXISTS max_attempts INTEGER;

ALTER TABLE assignment_problems
    ADD CONSTRAINT assignment_problems_max_attempts_check
        CHECK (max_attempts IS NULL OR (max_attempts > 0 AND max_attempts <= 1000));

-- 3. 提交迟交快照
ALTER TABLE submissions
    ADD COLUMN IF NOT EXISTS is_late BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN IF NOT EXISTS late_days INTEGER NOT NULL DEFAULT 0;

ALTER TABLE submissions
    ADD CONSTRAINT submissions_late_days_check
        CHECK (late_days >= 0);

-- 4. 学生例外：补交与免修
CREATE TABLE IF NOT EXISTS assignment_student_overrides (
    id SERIAL PRIMARY KEY,
    assignment_id INTEGER NOT NULL REFERENCES assignments(id) ON DELETE CASCADE,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    problem_id INTEGER NOT NULL,
    makeup_due_at TIMESTAMPTZ,
    waive_late_penalty BOOLEAN NOT NULL DEFAULT TRUE,
    exempt BOOLEAN NOT NULL DEFAULT FALSE,
    exemption_mode VARCHAR(20),
    reason TEXT,
    created_by INTEGER REFERENCES users(id) ON DELETE SET NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE (assignment_id, user_id, problem_id),
    FOREIGN KEY (assignment_id, problem_id)
        REFERENCES assignment_problems (assignment_id, problem_id)
        ON DELETE CASCADE,
    CHECK (exempt OR makeup_due_at IS NOT NULL),
    CHECK (
        (exempt = FALSE AND exemption_mode IS NULL)
        OR (exempt = TRUE AND exemption_mode IN ('full_score', 'excluded'))
    ),
    CHECK (reason IS NULL OR length(reason) <= 2000)
);

CREATE INDEX IF NOT EXISTS idx_assignment_overrides_assignment
    ON assignment_student_overrides (assignment_id, user_id);

-- 5. 策略审计
CREATE TABLE IF NOT EXISTS assignment_policy_audits (
    id SERIAL PRIMARY KEY,
    assignment_id INTEGER NOT NULL REFERENCES assignments(id) ON DELETE CASCADE,
    actor_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
    action VARCHAR(40) NOT NULL,
    before_data JSONB,
    after_data JSONB,
    reason TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

ALTER TABLE assignment_policy_audits
    ADD CONSTRAINT assignment_policy_audits_action_check
        CHECK (action IN (
            'policy_update',
            'due_extended',
            'override_set',
            'override_revoked',
            'solutions_published'
        )),
    ADD CONSTRAINT assignment_policy_audits_reason_check
        CHECK (reason IS NULL OR length(reason) <= 2000);

CREATE INDEX IF NOT EXISTS idx_assignment_policy_audits_assignment
    ON assignment_policy_audits (assignment_id, created_at DESC);

-- 6. 次数统计索引
CREATE INDEX IF NOT EXISTS idx_submissions_assignment_attempts
    ON submissions (assignment_id, user_id, problem_id, submitted_at)
    WHERE assignment_id IS NOT NULL;
```

说明：

- 现有作业全部回填为默认策略，保持原行为。
- 现有提交回填为 `is_late = FALSE`、`late_days = 0`。
- `assignment_student_overrides` 使用复合外键，确保题目一定属于该作业。
- 删除草稿作业时，例外和审计级联删除；已发布作业只归档、不物理删除。
- `users.role` 仍由服务层校验；例外表不存教师，`user_id` 必须是学生。

### 4.3 计分公式

```text
计分提交：
  highest   -> 最早的 accepted 提交
  first_ac  -> 首次 accepted 提交（与 highest 当前同分，迟交判定更稳定）
  last      -> 最后一次非 internal_error 提交

迟交天数：
  raw_days = ceil((submitted_at - assignment.due_at) / 1 day)
  若存在 override 且 waive_late_penalty = true
     且 submitted_at <= override.makeup_due_at
  -> effective_days = 0
  否则 effective_days = max(raw_days, 0)

迟交扣分：
  percent = min(effective_days * late_penalty_per_day, late_penalty_cap)
  deduction = ceil(points * percent / 100)

自动分：
  计分提交存在且 accepted -> points - deduction
  否则 -> 0

最终分：
  手动分存在 -> 手动分
  否则免修 full_score -> points
  否则免修 excluded -> 该题从总分分子和分母排除
  否则 -> 自动分
```

补充：

- 教师手动分范围仍是 `0..points`。
- 迟交结果为负时截断到 0。
- 总分只累加未排除题目。
- 分数实时计算，不缓存，避免策略变更后缓存漂移。

## 5. API 设计

### 5.1 通用约定

- 继续使用现有 envelope：`{ success, data, error }`。
- 后端 JSON 字段使用 snake_case，前端 adapter 映射 camelCase。
- 权限错误规则不变：

```sql
SET solutions_published_at = NOW(), updated_at = NOW()

  AND status = 'published'
```

9. 次数上限；

## 6. 后端实现要点

### 6.1 统一策略模块

新增 `backend-rust/src/services/assignment_policy.rs`，提供纯函数：

```text
effective_deadline(assignment, override)
submission_window_end(assignment, override)
raw_late_days(submitted_at, due_at)
effective_late_days(raw_days, override, submitted_at)
late_deduction(points, days, per_day, cap)
is_score_visible(assignment, now)
is_solution_visible(assignment, now)
select_scoring_submission(policy, submissions)
compute_problem_grade(points, submissions, manual_score, override, policy)
```

要求：

- 不访问数据库，输入输出明确，便于单元测试。
- 详情页、批改台、统计接口都调用同一模块。
- 避免在 SQL 中复制迟交公式，SQL 只负责取原始提交和例外。

### 6.2 提交校验

- `precheck_assignment` 做快速失败，返回更早的错误。
- `persist_submission` 在事务内重新查询并锁定：
  - 顺序固定：class → assignment → membership → override；
  - override 使用 `FOR SHARE`；
  - 次数统计与 INSERT 在同一事务。
- 沿用现有每用户提交锁，避免同一用户并发提交绕过次数限制。
- 系统错误不计次数：统计时排除 `status = 'internal_error'`。

### 6.3 分数计算

- `gradebook` 一次聚合查询取每学生每题提交，再在 Rust 中按策略模块计算。
- 禁止在学生循环中逐条查提交，避免 N+1。
- `detail` 用同样的聚合查询，只取当前学生数据。
- 统计接口使用聚合 SQL 计算平均分和通过率，再用策略模块处理免修和迟交。

### 6.4 通知

新增通知类型：

```text
assignment_override_granted      补交/免修设置或撤销
assignment_solutions_published   解析发布
assignment_due_extended          发布后延长截止
```

- 补交/免修通知只发给目标学生。
- 解析发布和延期通知发给 `class_members.status = 'active'` 的学生。
- 通知写入与主操作在同一事务；批量通知使用 `INSERT ... SELECT`。
- 站内通知链接统一为 `/assignments/{id}`。

### 6.5 兼容性

- 现有前端不传新字段时，使用数据库默认值，行为与当前一致。
- 现有 `AssignmentDetail` 字段保持不变，只新增字段。
- 现有 `grades_published_at` 继续存在，`after_publish` 模式直接复用。
- 现有提交接口无需新增必填参数。

## 8. 并发、安全与边界

### 8.1 并发

- 次数上限依赖现有“每用户同时 1 个提交”锁；多实例部署时 Redis 锁仍生效。
- 提交事务内重新校验，避免预检查通过后策略或成员状态变化。
- 补交/免修 upsert 在事务内执行，先锁 assignment，再写例外和审计。
- 解析发布使用条件更新，重复请求幂等。

### 8.2 安全

- 所有例外、审计、统计和他人代码接口都做资源归属校验。
- 管理员不能访问任何教学接口。
- 非 owner 教师返回 404，避免泄露作业是否存在。
- 学生只能看到自己的例外、自己的成绩、自己的统计位置。
- 他人代码只返回 AC 代码和用户名，不返回邮箱、用户 id、提交 id。
- 解析 Markdown 必须复用 DOMPurify 清洗。
- 审计中的 `before_data/after_data` 不写入代码、隐藏用例或个人信息。

### 8.3 数据一致性

- 分数不缓存，策略变更后立即生效。
- 延期不追溯历史迟交，避免已出成绩漂移。
- 补交/免修是显式教师例外，可以影响历史提交的最终分。
- 删除草稿作业级联删除例外和审计；已发布作业只归档。
- 已发布作业的计分、次数、迟交规则不可修改。

## 11. 风险与取舍

| 风险 | 影响 | 应对 |
|---|---|---|
| 策略字段较多 | 表单复杂、迁移面大 | 全部给默认值；策略区折叠；分两期实施 |
| 迟交公式分散 | 详情、批改台、统计不一致 | 统一 `assignment_policy` 纯函数模块 |
| 次数并发绕过 | 学生超限提交 | 事务内计数 + 沿用每用户提交锁 |
| 延期追溯争议 | 历史分数变化 | 提交时冻结迟交，延期不追溯 |
| 补交导致分数变化 | 已出成绩反复变化 | 例外写审计并通知，教师自行控制 |
| 统计泄露隐私 | 同学分数暴露 | 只返回聚合值和分位区间，不返回姓名和具体分 |
| 他人代码助长抄袭 | 学术诚信风险 | 默认关闭，教师显式开启，只给 AC 代码 |
| 解析提前泄露 | 截止前看到答案 | 后端强制 `due_at <= NOW()` 才能发布 |
| 系统错误误扣次数 | 学生被平台故障影响 | `internal_error` 不计次数、不作为计分提交 |
| 已发布作业改策略 | 成绩口径漂移 | 发布后锁定，仅允许延期、补交、免修 |

## 12. 已确定与后续讨论

已确定，不再作为阻塞项：

- 逐作业配置策略，提交次数支持题目覆盖；
- 迟交默认禁止，允许后按天扣分，默认 10%/天、封顶 50%；
- 宽限期计入迟交，宽限期只决定能否提交；
- 延期不追溯历史迟交；
- 次数按学生 × 题目独立计算，系统错误不计；
- 默认取最高分，教师手动分最高优先级；
- 成绩默认教师发布后可见，评语始终发布后可见；
- 解析独立发布，必须作业已截止；
- 补交/免修按学生 + 题目设置，教师直接操作并通知；
- 组织统计匿名，他人代码默认关闭；
- 发布后锁定策略，只允许延期、补交、免修并写审计。

后续可讨论：

- 学生发起补交/免修申请；
- 成绩申诉与改分审计合并；
- 作业成绩 CSV 导出；
- 邮件通知；
- 成绩快照与重判；
- 题目级选做/必做与部分分。
