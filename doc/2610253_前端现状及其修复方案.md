## 1. 现状一：左右分栏不能拖动

### 1.1 现状确认（代码层面）

布局是固定的两列 Grid，两个 `<section>` 直接相邻，中间没有任何分隔条：

`src/style.css:1017`

```css
.oj-page {
  display: grid;
  height: calc(100vh - 64px);
  min-height: 600px;
  grid-template-columns: minmax(0, 1fr) minmax(420px, 1fr);
  background: var(--color-surface);
}
```

`src/style.css:1043`

```css
.problem-pane {
  min-width: 0;
  overflow-y: auto;
  border-right: 1px solid var(--color-border);   /* ← 用户看到的「分割线」 */
}
```

`src/views/OjPage.vue:232` / `:241`

```html
<section class="problem-pane"> ... </section>
<section class="editor-pane"> ... </section>
```

结论：

- 用户看到的线就是 `border-right`，它不是独立元素，不接收鼠标事件；
- 没有 `cursor: col-resize`，没有 `pointerdown/pointermove` 处理；
- 列宽由 `grid-template-columns` 写死，无法通过状态改变。

`@media (max-width: 768px)` 下布局会变成单列（`style.css:1970` 一带），此时本来也不需要拖动。

### 1.2 修复方案

#### 目标

- 鼠标按住分隔条左右拖动，实时改变左栏宽度；
- 左右都有最小宽度（左 ≥ 320px，右 ≥ 420px，与现有 `minmax(420px, 1fr)` 对齐），窗口变窄时自动收敛；
- 拖动结束后记住宽度（`localStorage`），刷新不丢；
- 双击分隔条恢复 50 / 50；
- 键盘可用：`role="separator"` + 左右方向键，便于无障碍；
- ≤ 768px 单列布局时不显示分隔条。

#### 结构改动

在 `OjPage.vue` 两个 `<section>` 之间插入分隔条，`main.oj-page` 由两列变三列：

```html
<div
  class="pane-resizer"
  role="separator"
  aria-orientation="vertical"
  aria-label="调整题目与编辑器宽度"
  :aria-valuenow="Math.round(problemWidth)"
  :aria-valuemin="MIN_PROBLEM_WIDTH"
  :aria-valuemax="maxProblemWidth"
  tabindex="0"
  @pointerdown="startResize"
  @dblclick="resetSplit"
  @keydown.left.prevent="nudgeSplit(-24)"
  @keydown.right.prevent="nudgeSplit(24)"
></div>
```

#### 状态与逻辑（`<script setup>`）

```ts
const MIN_PROBLEM_WIDTH = 320
const MIN_EDITOR_WIDTH = 420
const SPLIT_STORAGE_KEY = 'theseus-oj-split'
const pageRef = ref<HTMLElement | null>(null)
const problemWidth = ref(Number(localStorage.getItem(SPLIT_STORAGE_KEY)) || 0)

const maxProblemWidth = computed(() => {
  const total = pageRef.value?.clientWidth ?? window.innerWidth
  return Math.max(MIN_PROBLEM_WIDTH, total - MIN_EDITOR_WIDTH - 8)
})

const clampWidth = (width: number): number =>
  Math.min(Math.max(width, MIN_PROBLEM_WIDTH), maxProblemWidth.value)

const applyWidth = (): void => {
  if (!pageRef.value) return
  const width = problemWidth.value || pageRef.value.clientWidth / 2
  pageRef.value.style.setProperty('--problem-width', `${clampWidth(width)}px`)
}
```

拖动用 Pointer Events，并在拖动期间禁止选中文本：

```ts
let dragging = false

const startResize = (event: PointerEvent): void => {
  dragging = true
  ;(event.target as HTMLElement).setPointerCapture(event.pointerId)
  document.body.classList.add('is-resizing')
  event.preventDefault()
}

const onPointerMove = (event: PointerEvent): void => {
  if (!dragging || !pageRef.value) return
  const left = pageRef.value.getBoundingClientRect().left
  problemWidth.value = clampWidth(event.clientX - left)
  applyWidth()
}

const stopResize = (event: PointerEvent): void => {
  if (!dragging) return
  dragging = false
  ;(event.target as HTMLElement).releasePointerCapture(event.pointerId)
  document.body.classList.remove('is-resizing')
  localStorage.setItem(SPLIT_STORAGE_KEY, String(Math.round(problemWidth.value)))
}

const resetSplit = (): void => {
  problemWidth.value = 0
  applyWidth()
  localStorage.removeItem(SPLIT_STORAGE_KEY)
}

const nudgeSplit = (delta: number): void => {
  if (!pageRef.value) return
  problemWidth.value = clampWidth((problemWidth.value || pageRef.value.clientWidth / 2) + delta)
  applyWidth()
  localStorage.setItem(SPLIT_STORAGE_KEY, String(Math.round(problemWidth.value)))
}
```

挂载时应用宽度并在窗口缩放时重新收敛；`onBeforeUnmount` 移除监听：

```ts
const onWindowResize = (): void => applyWidth()

onMounted(() => {
  applyWidth()
  window.addEventListener('resize', onWindowResize)
  window.addEventListener('pointermove', onPointerMove)
  window.addEventListener('pointerup', stopResize)
  window.addEventListener('pointercancel', stopResize)
})

onBeforeUnmount(() => {
  window.removeEventListener('resize', onWindowResize)
  window.removeEventListener('pointermove', onPointerMove)
  window.removeEventListener('pointerup', stopResize)
  window.removeEventListener('pointercancel', stopResize)
})
```

> 注意：`OjPage.vue` 里已有 `onMounted(() => { void loadPage() })` 和 `onBeforeUnmount(...)`，新增逻辑合并进去即可，不要重复注册。
> `--problem-width` 未设置时由 CSS 的默认值兜底，初始仍是 50 / 50。

#### 兼容性说明

- 编辑器用 Monaco，`CodeEditor.vue` 已经有 `ResizeObserver` 监听容器尺寸并调用 `layout()`（`CodeEditor.vue:42`），拖动后编辑器会自动重排，无需额外处理；
- `localStorage` 里存的是像素值，窗口变窄时由 `clampWidth` 收敛，不会把左栏挤到 0；
- 拖动期间给 `body` 加 `is-resizing`，避免选中文本和光标闪烁。

## 2. 现状二：输入 / 期望 / 输出被渲染成多行 JSON

### 2.1 现状确认（代码层面）

展示格式化函数在 `OjPage.vue:208`：

```ts
const formatValue = (value: unknown): string => {
  if (value === undefined) return '—'
  return JSON.stringify(value, null, 2) ?? 'null'   // ← 2 空格缩进，必然多行
}
```

使用位置：

| 位置 | 代码 | 现象 |
|---|---|---|
| 运行结果 · 输入 | `OjPage.vue:264` `formatValue(item.args)` | `[[2,7,11,15],9]` 被展开成多行 |
| 运行结果 · 期望 | `OjPage.vue:265` | 同上 |
| 运行结果 · 实际 | `OjPage.vue:266` | 同上 |
| 自定义运行 · 返回值 | `OjPage.vue:277` | 同上 |
| 运行弹窗 · 示例预览 | `OjPage.vue:317-318` | `输入：…` 换行后是缩进 JSON，`期望：…` 同样 |

而题目本身的示例数据是单行、LeetCode 风格的：

`backend-rust/scripts/seed_dev.sql:19`

```json
{"input": "nums = [2, 7, 11, 15], target = 9", "output": "[0, 1]", ...}
```

所以同一个页面里，题面是 `nums = [2, 7, 11, 15], target = 9`，运行结果却是：

```
输入
[
  [
    2,
    7,
    11,
    15
  ],
  9
]
```

这就是用户说的「和 LeetCode 行为不一致」。

补充：`stdout` / `stderr` 是用户程序的原样输出（`OjPage.vue:267-268`、`:278-279`），必须保持原样，不能套 JSON 格式化；自定义输入弹窗里的 textarea 用 2 空格缩进是**编辑场景**，应当保留。

### 2.2 根因

- 没有区分「编辑用格式化」与「展示用格式化」，统一用了带缩进的 `JSON.stringify(value, null, 2)`；
- 容器是 `<pre>` 且 `white-space: pre-wrap`（`style.css:1276`、`:1440`），会原样保留这些换行；
- 没有把参数名和值配对展示，所以只能看到裸数组，而题面是「参数名 = 值」。

### 2.3 修复方案

#### 目标

与 LeetCode 和题面保持一致：

```
输入：nums = [2, 7, 11, 15], target = 9
期望：nums = [2, 7, 11, 15], target = 9      // 或只展示返回值时省略
预期结果：[0, 1]
```

具体：

- 左侧 label 与内容同一行（或 label 在上、值单行，二选一，推荐沿用现有 `.run-block` 的上下结构，值本身单行）；
- 数组/对象用紧凑 JSON，元素之间 `, ` 分隔；
- 参数按 `run_config.params` 展开为 `name = value`，对不上时退化为紧凑数组；
- 长数组允许自动折行（`white-space: pre-wrap`），但不再人为插入换行；
- 弹窗示例预览同样改为一组单行文本。

#### 新增展示用格式化函数

`OjPage.vue`：

```ts
// 展示用：紧凑、单行，元素间补一个空格，贴近 LeetCode / 题面风格
const formatInline = (value: unknown): string => {
  if (value === undefined) return '—'
  if (Array.isArray(value)) return `[${value.map(formatInline).join(', ')}]`
  if (value !== null && typeof value === 'object') {
    const entries = Object.entries(value as Record<string, unknown>)
    return `{${entries.map(([key, item]) => `${JSON.stringify(key)}: ${formatInline(item)}`).join(', ')}}`
  }
  return JSON.stringify(value) ?? 'null'
}

// 输入：按参数名展开，与题面一致
const formatArgs = (args: unknown[]): string => {
  const params = runConfig.value?.params ?? []
  if (params.length !== args.length) return formatInline(args)
  return args.map((arg, index) => `${params[index].name} = ${formatInline(arg)}`).join(', ')
}
```

> 不要用 `JSON.stringify(value).replaceAll(',', ', ')` 这种写法：会误伤字符串内容（例如 `"a,b"` 会变成 `"a, b"`）。上面的递归实现只处理结构分隔符。

#### 模板替换

| 位置 | 现在 | 改为 |
|---|---|---|
| `OjPage.vue:264` | `formatValue(item.args)` | `formatArgs(item.args)` |
| `OjPage.vue:265` | `formatValue(item.expected)` | `formatInline(item.expected)` |
| `OjPage.vue:266` | `formatValue(item.actual)` | `formatInline(item.actual)` |
| `OjPage.vue:277` | `formatValue(runCase.actual)` | `formatInline(runCase.actual)` |
| `OjPage.vue:317-318` | `formatValue(item.args)` / `formatValue(item.expected)` | `formatArgs(item.args)` / `formatInline(item.expected)` |

`OjPage.vue:121` 的 `openRunDialog` 里给 textarea 赋初值仍用 `JSON.stringify(args, null, 2)`，保持可编辑性，不改。

改完后 `formatValue` 只保留给「编辑场景」使用；如果之后没有别的调用点，可以重命名为 `formatInputForEditing`，避免再次混用。

#### 文案建议

LeetCode 用「输入 / 输出 / 预期结果」。当前是「输入 / 期望 / 实际」，语义清楚，可以保留；若要完全对齐 LeetCode，建议：

- 运行结果：`输入` / `预期结果` / `你的输出`；
- 运行弹窗：`输入` / `预期结果`。

文案属于产品口径，改不改都不影响本次布局修复，建议在实现时一并确定。

#### CSS

`.run-block pre` 与 `.example-preview pre` 保持 `white-space: pre-wrap; word-break: break-word;` 不变：

- 单行内容不会被截断；
- 超出容器宽度时自动折行，不会出现横向滚动条；
- `max-height: 180px` 仍然兜底超长输出。

#### 验收

- [ ] 运行结果里「输入 / 期望 / 实际」各占一行，例如 `输入：nums = [2, 7, 11, 15], target = 9`；
- [ ] 运行弹窗的示例预览也是单行，不再是缩进 JSON；
- [ ] 字符串参数正常显示为 `"abc"`，包含逗号/冒号的字符串不会被破坏；
- [ ] 长数组（如 1000 个元素）在容器内自动折行，不横向溢出；
- [ ] `stdout` / `stderr` 保持原样输出；
- [ ] 自定义输入的 textarea 仍是多行缩进 JSON；
- [ ] 与题面示例的格式风格一致。

## 3. 影响面与实施顺序

- 只改 `OjPage.vue` 与 `style.css`，不涉及 API、store、后端；
- 两处改动互不依赖，可以分两个提交：
  1. 可拖动分栏（结构 + 逻辑 + CSS）；
  2. 展示格式化（`formatInline` / `formatArgs` + 模板替换）；
- 回归重点：
  - 拖动后 Monaco 编辑器尺寸（依赖现有 `ResizeObserver`）；
  - 运行结果面板在窄宽度下的折行；
  - 移动端 / ≤ 768px 单列布局；
  - 深色主题下分隔条 hover 颜色使用 `var(--color-accent)`，两套主题都需确认对比度。

## 4. 待确认的产品口径

1. 拖动后的宽度是否需要在同一浏览器内跨页面记忆（本文方案默认记忆在 `localStorage`）；
2. 运行结果里的标签是否统一改成 LeetCode 的「输入 / 预期结果 / 你的输出」；
3. 输入是否要显示参数名（本文方案默认显示，与题面 `nums = ..., target = ...` 一致）。
