
# 前端进一步完善

## 一、改版目标

本轮优化聚焦题库筛选区和个人界面，解决信息密度过高、层级不清、操作入口不明显以及深色主题对比度不足的问题。目标是让用户能够快速完成筛选，明确当前筛选状态，并在个人界面优先看到最有价值的学习数据和下一步行动。

## 二、题库筛选区

### 2.1 筛选器结构

将“难度、标签、状态”从连续堆叠的标签行改为分组控件，避免三行标签挤在一起造成视觉负担。

- **难度**：保留单选按钮组，选项控制在“全部、简单、中等、困难”。
- **状态**：使用单选按钮组或下拉选择，选项控制在“全部、未开始、进行中、已完成”。
- **标签**：改为多选下拉（或可搜索的多选弹层），不在页面上默认展开全部标签。
- 标签选中后，在控件内显示“已选 N 项”；超过 2 项时不逐项铺开，避免筛选区再次变长。
- 多选弹层应支持关键词搜索、全选当前结果、清除当前分组和确认/取消操作。
- 标签按使用频率或业务分类排序，常用标签优先展示；分类较多时提供分组标题。

### 2.2 筛选状态和清空操作

- 筛选控件展示当前已选数量，例如“标签（3）”“筛选条件（5）”。没有选中项时不显示数量。
- 在筛选区下方增加“当前筛选：难度·中等 / 标签·3 项 / 状态·进行中”的摘要区域。
- 摘要中的每个条件可单独移除，并提供明显的“清空筛选”按钮。
- “清空筛选”放在筛选摘要右侧或筛选区底部，与筛选条件保持同一视觉层级；有筛选条件时使用强调色，无筛选条件时置灰并禁用。
- 点击“标签（N）”或“筛选条件（N）”展开详情；再次点击收起。展开状态需要保留，避免用户选择一个标签后上下文跳动。
- 筛选结果变化后显示加载状态和结果数量，例如“共 128 道题”，让用户确认操作已生效。

### 2.3 间距、布局和响应式

统一使用 4px 间距系统，常用间距只允许使用 **4px、8px、16px、24px、32px**：

- 控件内图标与文字：8px。
- 标签/选项之间：8px。
- 同一筛选分组内的垂直间距：8px。
- 不同筛选分组之间：16px。
- 筛选区与结果列表之间：24px。
- 筛选区内外边距：桌面端 24px，窄屏端 16px。

桌面端可采用“分组控件 + 标签多选下拉”的单行布局；较窄屏幕下分组换行，但每组保持完整，不允许标签溢出或挤压文字。控件高度、圆角和内边距保持一致。

### 2.4 视觉和交互反馈

- 标签按钮默认态使用清晰的边框和略高于背景的填充色，不能依赖白色文字区分状态。
- hover：边框和背景颜色明显变化，并补充轻微阴影或亮度变化。
- focus：提供 2px 高对比度 focus ring，支持键盘操作。
- selected：使用强调色背景、强调色边框和明确的勾选图标；不能只改变文字颜色。
- disabled：降低透明度并禁止 hover 反馈，但仍保持可读性。
- 所有状态变化应有 150–200ms 的颜色/背景过渡，避免突兀跳变。
- 搜索框、输入框和下拉控件使用可识别的边框（建议至少 1px，并确保与背景有足够对比度），focus 时加粗或改变边框颜色。
- 筛选标签的 hover、selected、focus、disabled 状态需在设计稿和组件规范中分别定义。

## 三、个人界面

### 3.1 页面信息层级

重新安排个人界面内容顺序：

1. 页面标题和用户基本信息。
2. 学习概览数据（学习天数、完成题数、正确率、连续学习等）。
3. 主要行动入口（继续学习、去题库、查看错题）。
4. 学习趋势或最近活动。
5. 次要快捷入口和设置。

“快捷入口”不再单独放在当前突兀的位置。将高频操作合并到学习概览下方的“下一步”区域，最多保留 3 个入口；低频功能移到页面底部或个人菜单中。

### 3.2 数据卡片

- 为数据卡片建立明确层级：核心指标使用更大数字和更强对比度，辅助说明使用较小字号和次级颜色。
- 第一张或最重要的卡片可使用强调色或更亮的背景，其余卡片使用统一的中性表面色，避免所有卡片权重相同。
- 卡片统一高度、内边距和间距；桌面端使用 4 列网格，窄屏端按 2 列或 1 列自适应。
- 卡片之间使用表面色、边框和间距建立分隔，不依赖厚重阴影。
- 重点数据必须有标签、数值、单位和时间范围，避免只显示一个大数字。

### 3.3 空状态文案

“还没有学习数据，去题库开始第一题”应作为学习数据区域的完整空状态展示，而不是贴在卡片边缘或页面角落：

- 在数据卡片区域居中显示简短说明、辅助解释和主按钮。
- 建议文案：**“还没有学习记录”**；辅助文案：**“完成第一道题后，这里会显示你的学习进度。”**；按钮：**“去题库”**。
- 按钮点击后直接进入题库，并保持合理的默认筛选。
- 空状态与已有数据状态使用同一容器高度，避免页面切换时布局大幅跳动。

## 四、深色主题和可读性

- 调整深蓝背景与深灰卡片的明度差，页面背景、容器表面、输入控件表面至少形成清晰的三层关系。
- 文字不再全部使用白色：标题使用高对比度主文字，正文使用次级文字，说明/时间使用弱化文字，禁用文字使用最低层级颜色。
- 颜色层级应同时满足明度和对比度要求；不能只通过降低透明度制造层级。
- 搜索框、输入框、下拉框和卡片边界均要有可见边框或表面差异。输入框 focus、错误和成功状态需使用不同颜色表达。
- 保留强调色用于选中、主要行动和关键数据，避免整页高亮导致重点失效。

## 五、建议的验收标准

- 筛选区默认不展示 15 个以上标签；用户可在 1 次点击内打开标签多选和搜索。
- 用户能在筛选区一眼看到已选条件数量，并能在 1 次点击内清空全部筛选。
- 筛选条件的默认、hover、focus、selected、disabled 状态可明显区分，键盘可访问。
- 筛选区在桌面端和窄屏端均无标签重叠、文字截断或布局跳动。
- 个人界面的快捷入口位于主要学习行动附近，数据卡片具备主次层级。
- 无学习数据时，空状态文案、说明和“去题库”按钮在数据区域内对齐且易于发现。
- 深色主题下标题、正文、辅助文字、输入框边框和卡片边界均清晰可辨。
- 统一间距只使用 4px、8px、16px、24px、32px 五档，除图标和特殊组件外不出现随意间距。

## 六、导航文案与社区页面构图

### 6.1 移除重复的导航文字

- 题库导航项点击后，页面标题不再重复显示“题库”二字；导航本身已说明当前所在位置。
- 校园墙页面不再在内容区重复显示“校园墙”标题。
- 排行榜、我的组织等页面同样移除与导航项完全重复的冗余标题。
- 保留必要的内容上下文，例如页面介绍、筛选条件、分区标题和空状态说明；只删除重复的页面名称，不删除具有操作或信息价值的文案。
- 页面切换后应仍有清晰的当前页提示，可通过导航选中态、面包屑（如需要）和页面内容结构表达，不依赖重复的大标题。

### 6.2 校园墙参考 LeetCode「讨论」重整构图

重新梳理校园墙页面的信息架构和内容密度，参考 LeetCode「讨论」页面以讨论内容为中心的组织方式。参考重点是信息层级、列表可扫描性和发帖入口位置，不要求照搬其配色或品牌视觉。

- 页面主体采用稳定的内容列表作为视觉中心，减少大块留白、分散的功能卡片和装饰性区域。
- 将“发帖/发布讨论”作为明确的主要操作，放在列表顶部附近；窄屏下保持容易触达，不遮挡帖子内容。
- 帖子列表每条信息按统一顺序呈现：标题、内容摘要、话题/题目关联、作者与发布时间、评论/点赞等互动数据。
- 标题和正文摘要建立清晰字号层级，元信息使用次级文字；长内容截断并保持列表行高一致。
- 提供清晰的排序或筛选入口（如最新、热门、我的关注/话题），并将其放在列表上方，与内容列表形成直接关系。
- 题目关联和话题标签作为辅助索引展示，控制数量与视觉权重，避免标签装饰压过帖子标题。
- 评论数、点赞数等互动信息靠近帖子元信息集中排列，使用一致的图标、间距和点击区域。
- 桌面端采用内容优先的主栏布局；若有侧栏，仅放置话题导航、热门内容等辅助信息，并控制宽度和权重。移动端改为单列，辅助信息收纳到筛选/菜单入口。
- 空状态应提供简洁说明和“发布第一条讨论”入口；加载、无结果和错误状态均需与列表结构一致。

### 6.3 验收标准

- 题库、校园墙、排行榜、我的组织等页面不出现与当前导航项重复的大标题。
- 页面当前所在位置仍能从导航选中态清楚识别。
- 校园墙首屏能优先看到发布入口、排序/筛选和至少一条完整可扫描的帖子信息（有数据时）。
- 帖子标题、摘要、话题/题目关联、作者时间和互动数据的层级明确，桌面与移动端均无拥挤或错位。
- 校园墙空状态、加载状态和无搜索结果状态均提供合理的下一步操作。

## 七、统一主题色板

前端统一使用以下蓝色系建立品牌和界面层级，不再在各页面自行选择相近颜色：

| 色值 | 语义 | 使用范围 |
| --- | --- | --- |
| `#0a2639` | 深色基底 | 页面背景、顶部导航、深色主题的主要容器背景 |
| `#196090` | 深蓝主色 | 主要按钮、选中状态、链接、重点导航和数据强调 |
| `#3498db` | 交互蓝 | hover、focus ring、次要按钮、进度和可点击状态 |
| `#8bc4ea` | 浅蓝辅助色 | 选中背景、提示块、图表辅助色、标签背景 |
| `#d4e9f7` | 极浅蓝表面色 | 浅色主题页面背景、输入框/卡片表面、空状态区域 |

### 7.1 使用规则

- `#0a2639` 作为深色主题基底，卡片和输入控件不能与其完全同色，应通过 `#196090`、`#3498db` 或边框形成可识别的表面层级。
- `#196090` 只用于主要操作和当前选中状态，避免所有按钮、卡片和文字同时使用主色。
- `#3498db` 用于 hover、focus 和可操作提示；focus ring 必须保持清晰可见，不得只依靠轻微颜色变化。
- `#8bc4ea` 和 `#d4e9f7` 用于背景和辅助信息，不作为深色背景上的小字号正文色，避免对比度不足。
- 正文、标题和辅助文字使用独立的中性文字色，并按主文字、次级文字、弱提示建立层级；蓝色只承担状态和品牌表达。
- 颜色状态应统一：默认、hover、focus、selected、disabled、错误和成功状态在所有按钮、标签、输入框、下拉框中保持一致。
- 透明度仅用于弱化装饰或禁用状态，不能用透明度代替边框、表面和文字层级。

### 7.2 组件映射建议

- 主要按钮：`#196090` 背景 + 高对比度文字；hover 使用 `#3498db`。
- 次要按钮：透明或 `#d4e9f7` 背景，使用 `#196090` 边框和文字。
- 选中标签：`#8bc4ea` 背景 + `#0a2639` 文字，并保留 `#196090` 边框。
- 输入框：深色主题使用 `#0a2639` 表面、`#3498db` focus 边框；浅色主题使用 `#d4e9f7` 表面和 `#196090` 边框。
- 链接和可点击文字：默认 `#3498db`，hover 使用更高对比度的 `#8bc4ea` 或加下划线。
- 主要数据和进度：使用 `#196090`；辅助数据和图表次要系列使用 `#8bc4ea`。

### 7.3 验收标准

- 颜色变量集中定义，组件中不直接散落重复的十六进制值。
- 题库筛选、个人界面、校园墙、排行榜和我的组织使用同一套颜色语义。
- 深色背景上的文字、边框、按钮和输入框均清晰可辨；hover、focus、selected 状态可以快速区分。
- 主题色用于强调交互和信息层级，不造成整页单一蓝色或所有元素同等突出的效果。
