# 竞赛收尾设计方案（赛季、年级范围、申诉与成绩导出）

> 日期：2026-10-30
> 状态：v1 已实现
> 关联：`2610281_实现多人竞赛匹配机制.md`、`2610291_竞赛ui的完善.md`、`2610303_审计中心设计方案.md`

## 1. 目标与范围

补齐竞赛遗留的三项能力：

1. **赛季与软重置**：用赛季划分段位分周期，赛季开始时按系数把上赛季段位压缩回 1000 附近，并提供赛季排行榜。
2. **年级范围**：用户维护年级，赛事可限定年级范围，报名与进入时校验。
3. **赛事申诉与成绩导出**：选手在比赛结束后提交一次申诉，管理员通过后撤销作弊判定、恢复信誉分并重新结算；管理员可导出赛事成绩 CSV。

不在本期范围：赛季结算奖励、赛季结束定时任务、跨赛季荣誉展示、AI 帧识别。

## 2. 数据库（迁移 `0027_contest_wrapup.sql`）

### 2.1 赛季

```sql
CREATE TABLE seasons (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    starts_at TIMESTAMPTZ NOT NULL,
    ends_at TIMESTAMPTZ NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'draft',      -- draft / published / cancelled
    soft_reset_ratio NUMERIC(4,3) NOT NULL DEFAULT 0.500,
    activated_at TIMESTAMPTZ,
    created_by INTEGER REFERENCES users(id) ON DELETE SET NULL,
    ...
    CHECK (ends_at > starts_at)
);

CREATE TABLE season_ratings (
    season_id INTEGER NOT NULL REFERENCES seasons(id) ON DELETE CASCADE,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    rating INTEGER NOT NULL,
    rating_start INTEGER NOT NULL,
    played  INTEGER NOT NULL DEFAULT 0,
    wins    INTEGER NOT NULL DEFAULT 0,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (season_id, user_id)
);

ALTER TABLE contests ADD COLUMN season_id INTEGER REFERENCES seasons(id) ON DELETE SET NULL;
```

### 2.2 年级

- `users.grade VARCHAR(20)`：自由文本，NULL 表示未填写。
- `official_events.grade_scope TEXT[] NOT NULL DEFAULT '{}'`：空数组表示不限年级，否则精确匹配。

不使用枚举，是因为中学/大学/机构对年级的命名差异很大，强行枚举会把业务写死。

### 2.3 申诉

```sql
CREATE TABLE contest_appeals (
    id BIGSERIAL PRIMARY KEY,
    contest_id INTEGER NOT NULL REFERENCES contests(id) ON DELETE CASCADE,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    proctor_event_id BIGINT REFERENCES contest_events(id) ON DELETE SET NULL,
    reason TEXT NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'pending',    -- pending / accepted / rejected
    handled_by INTEGER REFERENCES users(id) ON DELETE SET NULL,
    handle_note TEXT,
    handled_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE (contest_id, user_id)
);
```

`UNIQUE (contest_id, user_id)` 保证每场比赛每人只能申诉一次；`proctor_event_id` 只做线索，不参与恢复逻辑。

索引：`idx_seasons_status_time`、`idx_contests_season`、`idx_season_ratings_rank`、`idx_contest_appeals_status`、`idx_contest_appeals_user`。

## 3. 赛季激活与软重置

- 不引入后台定时任务。`ensure_active_season` 在竞赛首页、排位入队、排行榜与申诉列表等入口惰性触发。
- `activate_season` 在事务内 `SELECT ... FOR UPDATE` 锁赛季行，`activated_at` 非空即幂等返回。
- 软重置公式：

  `new = max(0, round(1000 + (old - 1000) × ratio))`

  默认 `ratio = 0.5`，例如 1400 → 1200，800 → 900。
- 激活时先把所有 `student` + `active` 用户的当前段位写入 `season_ratings`（`rating` 与 `rating_start` 同值），再把 `users.contest_rating` 切到赛季分。
- 同一时间只允许一个 `published` 赛季覆盖当前时间；创建/更新时做区间重叠检查。
- 已激活赛季禁止修改起止时间与软重置系数，只能改名、保持发布或取消。

### 3.1 比赛归属与结算

- `try_match` 创建排位比赛时写入 `contests.season_id = current_season_id`。
- 结算：
  - 只有赛季为空（历史数据）或等于当前赛季时，才同步更新 `users.contest_rating`，防止旧赛季延迟结算覆盖当前段位。
  - 有 `season_id` 时调用 `record_settlement` 写入 `season_ratings.rating / played / wins`。
- 取消资格重排：
  - 当前赛季或历史无赛季的比赛仍同步 `users.contest_rating` 差额。
  - 有 `season_id` 时调用 `record_rerank` 只叠加差额（多还少补），避免覆盖之后比赛的结算。
  - 重排后对该场所有参与者的 `wins` 做一次全量重算，因为取消资格可能移除已有的第一名。

### 3.2 排行榜

`GET /api/contests/rankings` 支持 `season_id`：

- 默认当前赛季；无赛季配置时回退到旧的全局 `users.contest_rating` 统计。
- 指定赛季时读取 `season_ratings`，`my_rank`、`total` 也在该赛季范围内计算。
- 响应包含 `season`（当前选中）与 `seasons`（可选列表）。

## 4. 年级范围

- 用户：`PUT /api/profile/grade`，`grade` 为 `null`/空字符串表示清除，最长 20 字符。
- 管理员赛事表单新增 `grade_scope`，服务端去空白、去重、单项 ≤ 20 字符、最多 20 项。
- 可见性：赛事卡片返回 `grade_scope`，并按「组织范围 + 年级范围」共同计算 `eligible` 与 `ineligible_reason`。
- 报名/加入与进入比赛时再次校验年级，避免通过旧页面绕过。
- 未填写年级的用户无法报名限定了年级的赛事，提示「仅限 XX 学生参加」。

## 5. 赛事申诉

### 5.1 提交

- 条件：比赛已结束（或已过 `ends_at`）、本人是参赛者、该场未提交过申诉。
- 每场限一次；提交成功发站内信。
- 学生接口：`GET /api/contests/appeals/mine`、`POST /api/contests/{id}/appeal`。

### 5.2 处理

- 管理员接口：`GET /api/admin/contest-appeals`、`POST /api/admin/contest-appeals/{id}/resolve`。
- 只允许处理 `pending` 记录，避免重复恢复。
- **通过**时：
  1. 汇总该场 `reputation_events.reason='paste_cheating'` 的负向扣分，按差额恢复信誉分（上限 100），写一条 `appeal_restored` 记录；
  2. 若因此从 `banned` 恢复且分数 ≥ 0，解除封禁并递增 `token_version`，删除自动封禁的邮箱黑名单；
  3. 清除 `contest_participants.disqualified_*`；
  4. 把该场该用户已确认的 `contest_event_reviews` 改为 `cleared`；
  5. 比赛已结束时执行 `rerank_contest`，恢复名次与段位分/赛季分。
- **驳回**时只记录状态与说明。
- 两种结果都发站内信，并写入 `contest.appeal_resolve` 审计日志。

## 6. 成绩导出

- `GET /api/admin/events/{id}/results/export`，仅管理员。
- 输出 UTF-8 BOM + CSV：排名、用户名、总分、通过题数、完成时间、是否取消资格。
- 字段按 RFC 4180 转义；响应头 `text/csv; charset=utf-8` 与 `Content-Disposition: attachment`。
- 每次导出写 `contest.results_export` 审计日志。

## 7. 前端

- 竞赛首页展示当前赛季名称与状态。
- 排行榜页支持赛季切换。
- 成绩页展示申诉状态；无申诉时可填写理由提交。
- 「我的申诉」页增加赛事申诉列表。
- 账号设置新增「年级」。
- 赛事管理表单新增年级范围，列表提供「导出成绩」。
- 新增管理页：`/admin/seasons`（赛季管理）、`/admin/contest-appeals`（申诉处理）。

## 10. 风险与后续

- 赛季激活依赖读请求触发；若长期无人访问，赛季分不会主动切换。当前规模可接受，后续可加定时任务。
- 旧比赛（`season_id IS NULL`）在跨赛季重排时仍会更新当前段位分，这是历史数据兼容的折中。
- 申诉恢复只针对粘贴作弊扣分；其他类型的信誉扣分需要单独扩展原因映射。
