# 学习专区：408 与面经设计方案

> 日期：2026-10-31
> 状态：v1 已实现（前端 + 后端 + 迁移）
> 关联：`2610312_商店与Plus申请设计方案.md`、`backend_api.md`

## 1. 目标

把顶部原「赛事」下拉菜单改名为「学习」，并在竞赛、排行榜之外提供两个内容栏目：

- **408**：计算机考研 408 知识整理与收集
- **面经**：各类面试题目与经验收集

两个栏目共用一套文章模型。Plus Theseus 用户可投稿，管理员审核通过后公开；正文仅 Plus 用户与管理员可读，非 Plus 用户可以浏览列表与摘要。

## 2. 权限规则

| 角色 | 浏览列表 / 摘要 | 阅读正文 | 投稿 / 编辑 | 审核 |
|---|---|---|---|---|
| 未登录 | 不可进入学习专区 | 不可 | 不可 | 不可 |
| 学生（非 Plus） | 可以 | 不可，显示开通入口 | 不可 | 不可 |
| 教师（非 Plus） | 可以 | 不可，显示开通入口 | 不可 | 不可 |
| 学生 / 教师（Plus） | 可以 | 可以 | 仅本人未通过或未审核的投稿 | 不可 |
| 管理员 | 可以 | 可以 | 不可 | 通过、退回、下架 |

- Plus 身份沿用 `plus_applications` 中 `status = 'approved'` 的记录，不新增会员字段。
- 学生与教师在投稿权限上完全一致。
- 管理员不显示「商店」入口，也不参与投稿，只负责审核。
- 非 Plus 用户仍可看到列表、摘要与标签，用于了解内容和引导开通。

## 3. 数据模型

`backend-rust/migrations/0029_knowledge_articles.sql` 新增 `knowledge_articles`：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `author_id` | 投稿用户，`ON DELETE SET NULL` |
| `category` | `408` 或 `interview` |
| `title` | 标题，最多 120 字 |
| `summary` | 摘要，最多 300 字；留空时截取正文开头 |
| `content` | Markdown 正文，最多 20000 字 |
| `tags` | `TEXT[]`，最多 8 个，每个最多 20 字 |
| `status` | `pending` / `approved` / `rejected` |
| `review_note` | 审核说明，最多 500 字 |
| `reviewed_by` | 审核管理员 |
| `reviewed_at` | 审核时间 |
| `created_at` / `updated_at` | 时间戳 |

索引：`(category, status, created_at DESC)`、`(author_id, created_at DESC)`、`(status, created_at DESC)`、标签 GIN。

## 4. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/knowledge` | 登录 | 已通过文章列表，支持 `category`、`tag`、`q`、`page`、`size`，返回 `is_plus` 与 `can_submit` |
| GET | `/api/knowledge/{id}` | 登录 | 文章详情；非 Plus 查看已通过文章时 `locked = true`、`content = null` |
| POST | `/api/knowledge` | Plus + 已验证邮箱 | 投稿，落库为 `pending` |
| PUT | `/api/knowledge/{id}` | 作者本人 | 仅 `pending` / `rejected` 可编辑；编辑后重新进入 `pending` |
| DELETE | `/api/knowledge/{id}` | 作者本人 / 管理员 | 作者只能删除未通过投稿；管理员可删除任意文章 |
| GET | `/api/knowledge/mine` | 登录 | 本人投稿，支持 `category`、`status` |
| GET | `/api/admin/knowledge` | 管理员 | 全部投稿，支持 `category`、`status`、`q` |
| POST | `/api/admin/knowledge/{id}/resolve` | 管理员 | `{"status":"approved"|"rejected","note"?}`；通过、退回或下架 |

### 4.1 详情响应

已通过文章对非 Plus 用户返回：

```json
{
  "id": 1,
  "category": "408",
  "title": "标题",
  "summary": "摘要",
  "tags": ["数据结构"],
  "author": "username",
  "status": "approved",
  "content": null,
  "locked": true,
  "is_mine": false,
  "can_edit": false,
  "created_at": "...",
  "updated_at": "...",
  "review_note": null,
  "reviewed_by": null,
  "reviewed_at": null
}
```

未通过或待审核文章只有作者本人与管理员可查看，其他人返回 404。

### 4.2 审核

- 管理员审核结果写入站内信，类型 `knowledge_review`，归入账号通知类别。
- 审计动作 `knowledge.resolve`，对象 `knowledge_article`，不记录正文。
- 已通过文章可被管理员再次处理为 `rejected`，用于下架；作者随后可以修改并重新提交。
- 审核通过后作者不能直接编辑或删除，需要管理员先退回或下架。

## 5. 前端

### 5.1 导航

顶部「赛事」改为「学习」，顺序为：竞赛、排行榜、408、面经。

- 竞赛：`/contests`
- 排行榜：`/contests/rankings`
- 408：`/knowledge/408`
- 面经：`/knowledge/interview`

「个人」菜单新增「我的投稿」；「管理」菜单新增「408 与面经」。

### 5.2 页面

| 路由 | 说明 |
|---|---|
| `/knowledge/408` | 408 列表、搜索、标签筛选、分页 |
| `/knowledge/interview` | 面经列表 |
| `/knowledge/:id` | 详情；非 Plus 显示开通提示，管理员和 Plus 用户显示正文 |
| `/knowledge/new?category=408` | 投稿表单，支持 Markdown 编辑与预览 |
| `/knowledge/:id/edit` | 编辑待审核或被退回的投稿 |
| `/personal/knowledge` | 我的投稿与状态筛选 |
| `/admin/knowledge` | 管理员审核、下架、搜索与状态筛选 |

### 5.3 文案

- 不使用中文句号「。」
- 多句分行
- 非 Plus 提示只保留「正文需要 Plus Theseus 才能阅读」和「去开通」

## 6. 验证

已完成：

- `cargo check`
- `cargo clippy --all-targets`
- `cargo fmt --check`
- `npm run build`

手工验证建议（本地）：

1. 未开通 Plus 的学生进入 `/knowledge/408`，能看到列表与摘要，打开详情显示开通提示。
2. 管理员在 `/admin/plus-applications` 通过该学生申请。
3. 学生进入 `/knowledge/408`，出现「投稿」，提交后状态为审核中。
4. 管理员在 `/admin/knowledge` 通过投稿，作者收到站内信。
5. 非 Plus 学生再次打开详情仍被锁定；管理员与 Plus 学生可读全文。
6. 管理员将已通过文章下架，作者可编辑并重新提交。
