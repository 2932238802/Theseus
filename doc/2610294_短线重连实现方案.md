# 断线重连实现方案

> 日期：2026-10-29
> 状态：已实现（后端心跳、断线宽限、全员断线取消、前端重连提示；`cargo check`、`cargo test` 与 `npm run build` 通过）

## 背景

竞赛现在通过 5 秒轮询 `GET /api/contests/{id}` 获取比赛状态，服务端没有记录选手是否在线。刷新页面可以回到进行中的比赛，但以下场景没有被处理：

- 选手关闭页面或网络中断后，服务端仍把他当作 `active`，比赛照常计时；
- 不知道选手断了多久，无法判断是否应该保留成绩、结束比赛或取消对局；
- 选手断线后页面继续显示旧倒计时，恢复网络时没有明确的“正在重连”状态；
- 全员断线时比赛会空转到结束时间，白占一场排位结算。

本方案在不引入 WebSocket 的前提下，用轻量心跳补齐「在线判定 → 重连宽限 → 超时结算 → 全员断线取消」闭环。

## 目标与非目标

**目标**

- 比赛期间服务端能判断选手是否在线，客户端每 10 秒上报一次心跳；
- 断线后保留 120 秒重连窗口，窗口内重新打开比赛页即可恢复作答；
- 超过 120 秒未重连，按断线前已提交的成绩参与结算，不能继续提交；
- 排位赛全员断线且宽限耗尽时取消对局，不改变段位分；
- 刷新、切标签页、短时断网后恢复时，页面状态与服务端一致；
- 所有判定以服务端时钟为准。

**非目标**

- 不做 WebSocket 实时推送，仍用轮询与心跳（后续再替换）；
- 不做跨设备在场判定，同一账号多台设备以最后心跳为准；
- 不在重连时重新申请摄像头或屏幕共享权限（浏览器限制与流程改动较大，留到监考方案一起做）；
- 不自动判定作弊，断线只作为比赛状态与后续证据，不直接处罚。

## 当前实现基线

- 比赛详情：`GET /api/contests/{id}`，前端每 5 秒轮询，`server_time` 用于校准倒计时；
- 当前比赛：`GET /api/contests/current`，竞赛首页发现 `state = contest` 时自动跳回比赛页；
- 主动离场：`POST /api/contests/{id}/finish`，把选手置为 `finished`，最后一名 active 选手离场后立即结算；
- 结算：后台每 5 秒执行 `settle_due_contests`，`ends_at + 20s` 后结算一次；
- 行为事件：`POST /api/contests/{id}/events` 已按 `contest_id + user_id + event_id` 幂等写入，带 `session_id`；
- 提交校验：`precheck_submission` 只允许 `active` 且未取消成绩的选手提交。

## 选手状态

`contest_participants.status` 在原有 `queued` / `active` / `finished` 基础上增加两个状态：

| 状态 | 含义 | 可提交 | 可重连 |
|---|---|---|---|
| `queued` | 赛事报名后尚未进入比赛 | 否 | 进入赛事时转为 `active` |
| `active` | 在线作答，心跳正常 | 是 | — |
| `disconnected` | 超过 30 秒没有心跳，处于重连宽限期 | 否 | 是，心跳后回到 `active` |
| `timed_out` | 宽限期耗尽，成绩冻结 | 否 | 否，等比赛结束查看结果 |
| `finished` | 主动离场或正常完成 | 否 | 否 |

`disqualified_at` 不为空的选手不参与在线判定，也不能通过心跳恢复成 `active`。

## 心跳接口

`POST /api/contests/{id}/heartbeat`

- 鉴权：登录用户且邮箱已验证；
- 请求体为空；
- 仅当比赛为 `running` 且本人状态为 `active` / `disconnected` 时更新在线时间；
- 状态为 `disconnected` 时恢复为 `active` 并清空 `disconnected_at`；
- 其他状态只读返回，不修改数据。

响应：

```json
{
  "contest_id": 42,
  "status": "running",
  "my_status": "active",
  "ends_at": "2026-10-29T12:00:00Z",
  "disconnected_at": null,
  "reconnect_grace_seconds": 120,
  "server_time": "2026-10-29T11:20:00Z"
}
```

错误：

- `404`：不是该场比赛的选手；
- `409`：比赛已结束或已取消（前端按详情状态处理）。

## 在线判定

新增后台任务，随结算循环每 5 秒执行一次 `sweep_contest_presence`。

### 断线

`status = 'active'` 且 `last_seen_at` 早于当前时间 30 秒：

- 置为 `disconnected`，记录 `disconnected_at`；
- 保留在比赛中，倒计时与其他选手继续。

### 超时

`status = 'disconnected'` 且 `last_seen_at` 早于当前时间 120 秒：

- 置为 `timed_out`，记录 `timed_out_at`；
- 写入站内信「比赛断线超时」，说明成绩按断线时已提交内容结算；
- 不再允许提交；比赛对其他人继续。

宽限期以最后一次心跳时间计算，因此从最后一次心跳到成绩冻结正好 120 秒，不受 30 秒断线判定误差影响。

### 全员断线

排位赛在宽限耗尽后，如果所有选手都处于 `timed_out`：

- 比赛置为 `cancelled`，`finished_at` 记录取消时间；
- 不计算排名与段位分，不写 `rating_history`；
- 给所有参赛者写站内信「比赛已取消」。

赛事比赛（`official_event_id` 非空）不执行全员断线取消，结束时间固定，未超时的选手仍可进入。

### 提前结算

排位赛没有 `active`、没有 `disconnected`，且至少有一名 `finished` 时，立即调用结算，不再等到 `ends_at + 20s`。

## 结算口径

- 参与结算的状态扩展为 `active`、`finished`、`disconnected`、`timed_out`；
- `timed_out` 选手的 `finished_at` 保持为空，不使用断线时间参与并列排序，避免断线者因“更早完成”在并列时占优；
- `timed_out` 之前已提交的记录正常计分，之后无法再提交；
- 取消的比赛不进入结算，成绩页不可用，比赛页显示「已取消」。

## 前端

### 心跳

`ContestPage.vue` 在比赛 `running` 且本人状态不是 `finished` / `timed_out` 时启动心跳：

- 每 10 秒调用一次 `POST /api/contests/{id}/heartbeat`；
- 进入页面、从后台标签页恢复、轮询发现比赛仍在进行时立即补一次心跳；
- 页面卸载时停止心跳，不调用 `finish`，关闭页面等同于断线；
- 主动离场后停止心跳。

### 连接状态

页面维护 `online` / `reconnecting` / `timedOut` 三种展示状态：

- 心跳失败：显示「网络中断，正在重连」，保留最后已知的倒计时与题目，不弹全屏错误；
- 后续心跳成功：自动清除提示，不需要用户操作；
- 心跳返回 `my_status = timed_out`：显示「断线超过 120 秒，成绩按断线时结算」，停止心跳，保留题目只读；
- 心跳返回比赛 `cancelled`：停止轮询并显示「比赛已取消」。

### 恢复路径

1. 刷新比赛页：`GET /api/contests/{id}` 拿到详情后立即心跳，服务端在宽限内把状态恢复为 `active`；
2. 回到竞赛首页：`GET /api/contests/current` 返回进行中的比赛，自动跳回比赛页；
3. 从其他页面点击比赛链接：与刷新一致。

### 文案

- 重连提示：`网络中断，正在重连`
- 超时提示：`断线超过 120 秒，成绩按断线时结算`
- 取消提示：`比赛已取消`
- 不展示剩余宽限秒数，避免持续变化的干扰信息

## 数据库

新增迁移 `0024_contest_presence.sql`：

```sql
ALTER TABLE contest_participants
    ADD COLUMN IF NOT EXISTS last_seen_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    ADD COLUMN IF NOT EXISTS disconnected_at TIMESTAMPTZ,
    ADD COLUMN IF NOT EXISTS timed_out_at TIMESTAMPTZ;

ALTER TABLE contest_participants
    DROP CONSTRAINT IF EXISTS contest_participants_status_check;
ALTER TABLE contest_participants
    ADD CONSTRAINT contest_participants_status_check
    CHECK (status IN ('queued', 'active', 'disconnected', 'finished', 'timed_out'));

CREATE INDEX IF NOT EXISTS idx_contest_participants_presence
    ON contest_participants (contest_id, status, last_seen_at);
```

迁移时已有 `active` 选手的 `last_seen_at` 取迁移时间，部署后 30 秒内不会误判断线。

## 边界与已知限制

- 浏览器后台标签页会节流定时器，切走超过 30 秒会被判为断线；这符合“离开比赛页即断线”的预期，切回后心跳可恢复；
- 多标签页同时打开同一场比赛时，任一标签页心跳都会保持在线；关闭其中一个不会断线，符合用户预期；
- 同一账号在不同设备之间切换，以最后一次心跳为准，服务端不区分设备；
- 网络抖动导致单次心跳失败不会立即断线，30 秒判定容忍两次失败；
- 重连不会重新申请屏幕共享，浏览器刷新后原有共享流已失效，监考能力留待后续方案；
- 事件上报队列在断线期间保留，恢复后继续补发，不因心跳失败丢弃。

## 验收标准

1. 正常比赛每 10 秒有一次心跳，`last_seen_at` 持续更新；
2. 关闭页面 30 秒后选手变为 `disconnected`，其他人比赛不受影响；
3. 100 秒内重新打开比赛页，心跳成功，状态恢复 `active`，可继续提交；
4. 超过 120 秒未重连，状态变为 `timed_out`，提交返回冲突提示，已提交成绩保留；
5. 排位赛全员断线并超过宽限，比赛变为 `cancelled`，段位分不变，参赛者收到站内信；
6. 赛事比赛全员断线不会被取消，结束时间不变；
7. 主动离场仍立即生效，不触发断线逻辑；
8. 刷新页面、切标签页、短时断网后，倒计时与服务端一致，重连提示自动消失；
9. `cargo check` 与 `npm run build` 通过，赛事冒烟脚本覆盖心跳接口。
