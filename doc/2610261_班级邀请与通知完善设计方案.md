# Theseus 组织邀请与通知完善设计方案

> 版本：v1.0  
> 日期：2026-10-26  
> 状态：已实现并通过前后端构建与接口冒烟测试  
> 关联文档：`doc/2610259_班级与作业设计方案.md`、`doc/2610257_论坛功能设计方案.md`  
> 范围：教师搜索学生并发送组织邀请、学生确认入班、教师/管理员发送自定义站内通知

---

## 0. 结论速览

| 决策项 | 本期选择 |
|---|---|
| 主动加人 | 教师按用户名/邮箱搜索学生，批量勾选后发送邀请 |
| 入班方式 | 学生必须确认邀请后才成为组织成员；前端移除“直接添加成员” |
| 邀请有效期 | 7 天；重复邀请复用同一条 `pending` 记录并顺延有效期 |
| 邀请入口 | 学生可在通知中心和“我的组织”页处理 |
| 邀请结果 | 学生接受/拒绝后生成教师回执通知 |
| 教师通知范围 | 本班全体在读学生，或勾选本班部分学生 |
| 管理员通知范围 | 指定学生/教师、按角色群发（学生或教师）、全站所有用户 |
| 通知内容 | 标题（≤100 字）+ Markdown 正文（≤5000 字）+ 可选站内链接 |
| 通知管理 | 新增管理员“通知管理”页；不做发送历史与撤回 |
| 接收人约束 | 管理员单次定点最多 500 人；教师只能发给本班学生 |

**一句话总结：** 新增 `class_invitations` 表承载“教师发起、学生确认”的入班流程；复用 `notifications` 表新增 `class_invite`、`class_invite_accepted`、`class_invite_declined`、`system_notice` 四类通知，让学生入班与全员/定向通知都走同一个通知中心。

## 1. 目标与非目标

### 1.1 目标

1. 教师不能直接修改组织成员关系，只能发出邀请；学生确认后才写入 `class_members`。
2. 邀请可以批量发送，也可以搜索单个学生；搜索不到或角色不符时给出可读原因。
3. 待处理邀请 7 天后自动过期，重复邀请复用原记录并顺延有效期。
4. 学生接受邀请时校验邀请状态、有效期和组织归档状态，防止重复接受或接受过期邀请。
5. 教师可以收到接受/拒绝回执，学生通知中心可对待处理邀请直接操作。
6. 教师可以给本班全体或指定学生发送 Markdown 通知。
7. 管理员可以给指定用户、某一角色或全站发送 Markdown 通知。
8. 自定义通知只允许站内路径链接，避免把通知中心当成外链跳板。
9. 所有接口做服务端资源归属校验，禁止越权查看组织邀请或向非本班学生发通知。

### 1.2 非目标

- 邀请邮件、短信、站外推送；
- 邀请撤销接口和教师端邀请历史；
- 通知发送历史、撤回、定时发送；
- 管理员通过“指定用户”或“按角色”向管理员发送通知（“全站”范围仍会包含其他管理员，但不会发给发送者自己）；
- 学生之间互发通知；
- 富文本编辑器（正文使用 Markdown 文本域 + 预览）；
- 通知模板管理。

> 当前实现（2026-10-29）：通知邮件已按类别偏好接入，组织邀请等站内通知在用户开启对应类别且邮箱已验证时也会发送邮件；短信、站外推送和撤销接口仍未实现。详见 `总体设计.md` v1.11。

## 2. 数据模型

### 2.1 `class_invitations`

```sql
CREATE TABLE class_invitations (
    id            BIGSERIAL PRIMARY KEY,
    class_id      INTEGER NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
    inviter_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    invitee_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    status        TEXT NOT NULL DEFAULT 'pending'
                  CHECK (status IN ('pending','accepted','declined','cancelled','expired')),
    expires_at    TIMESTAMPTZ NOT NULL,
    responded_at  TIMESTAMPTZ,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

关键约束：

- 部分唯一索引 `(class_id, invitee_id) WHERE status = 'pending'`，同一学生同一组织最多一条待处理邀请；
- 邀请有效期 7 天，读取和响应时惰性更新过期记录；
- 接受邀请时对组织行和邀请行加锁，使用 `INSERT ... ON CONFLICT` 维护 `class_members`；
- 拒绝后允许再次邀请，生成新的邀请记录。

### 2.2 `notifications` 复用

沿用现有字段：

| 字段 | 邀请通知 | 自定义通知 |
|---|---|---|
| `type` | `class_invite` / `class_invite_accepted` / `class_invite_declined` | `system_notice` |
| `actor_id` | 邀请教师 / 学生 | 发送通知的教师或管理员 |
| `title` / `body` / `link` | 邀请文案；链接指向 `/classes` | 自定义 Markdown 与站内链接 |
| `related_type` | `class_invitation` | 空 |
| `related_id` | 邀请 ID | 空 |

通知列表额外返回 `related_type`、`related_id` 和 `invitation_status`（通过关联子查询实时读取邀请状态），前端据此渲染“接受/拒绝”按钮并在处理后同步状态。

| 操作 | 学生 | 教师 | 管理员 |

| 发送组织邀请 | — | 仅自己拥有的组织 | — |

## 4. 接口

### 4.1 组织邀请

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/classes/{id}/invite-candidates?q=` | 按用户名/邮箱模糊搜索学生，返回是否已在班、是否有待处理邀请 |
| POST | `/api/classes/{id}/invitations` | 批量发送邀请，请求体 `{user_ids:[...]}`，最多 200 人 |
| GET | `/api/classes/{id}/invitations` | owner 查看待处理邀请 |
| GET | `/api/invitations` | 学生查看自己的待处理邀请 |
| POST | `/api/invitations/{id}/accept` | 学生接受邀请 |
| POST | `/api/invitations/{id}/decline` | 学生拒绝邀请 |

发送邀请时返回：

```json
{
  "invited_count": 1,
  "skipped": [
    { "user_id": 7, "username": "alice", "reason": "already_member" }
  ],
  "message": "已发送 1 份邀请"
}
```

跳过原因包括 `not_student`、`already_member`、`already_invited`。其中 `already_invited` 表示已有待处理邀请，服务端会顺延有效期而不是重复插入。

### 4.2 自定义通知

`POST /api/notifications/send`

教师：

```json
{
  "class_id": 12,
  "title": "作业提醒",
  "body": "**周五**截止，请及时提交。",
  "link": "/assignments/34",
  "user_ids": [21, 22]
}
```

- `user_ids` 省略时发给本班全体在读学生；
- 指定 `user_ids` 时，所有人必须都是本班在读学生。

管理员（三选一）：

```json
{ "user_ids": [21, 22], "title": "...", "body": "..." }
{ "role": "student", "title": "...", "body": "..." }
{ "all": true, "title": "...", "body": "..." }
```

返回 `{ "recipient_count": 2, "message": "已发送给 2 位用户" }`。

## 5. 前端

### 5.1 组织详情页（教师）

- 移除“用户名或邮箱直接添加成员”表单，保留移除成员；
- 新增“邀请学生”：搜索、勾选、批量发送，展示候选人的“已加入/已邀请”状态；
- 展示待确认邀请及到期时间；
- 新增“给本班学生发通知”：全班/指定学生、标题、Markdown 正文、可选站内链接、正文预览。

### 5.2 我的组织页（学生）

- 顶部展示待处理组织邀请，可直接接受/拒绝；
- 接受后刷新组织列表；仍保留邀请码加入入口。

### 5.3 通知中心

- `system_notice` 使用 `MarkdownBody` 渲染正文；
- `class_invite` 且邀请状态为 `pending` 时展示“接受邀请/拒绝”；
- 处理完成后通知标记已读，并就地更新邀请状态；
- 有链接的通知提供“查看详情”按钮。

### 5.4 管理员通知管理页

- 路由 `/admin/notifications`，导航栏“管理 → 通知管理”；
- 接收范围：指定用户（分页搜索、多选，管理员账号不可选）、按角色、全站；
- 标题、Markdown 正文、站内链接、正文预览；
- 群发前二次确认，发送后展示实际接收人数。

## 6. 校验与边界

| 项 | 限制 |
|---|---|
| 邀请有效期 | 7 天 |
| 单次邀请人数 | 200 |
| 候选搜索关键词 | 100 字符 |
| 候选返回数量 | 默认 20，最大 50 |
| 通知标题 | 100 字符 |
| 通知正文 | 5000 字符 |
| 通知链接 | 500 字符，必须以单个 `/` 开头，拒绝 `//`、`\`、`://` |
| 管理员定点接收人 | 500 |
| 教师通知接收人 | 本班在读学生 |
| 搜索匹配 | 用户名/邮箱 `ILIKE`，转义 `%`、`_`、`\`，用户名完全匹配优先 |

服务端统一使用事务和行锁处理接受邀请与发送邀请，避免并发下重复入班或重复待处理记录。
