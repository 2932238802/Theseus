## 0. 目标与范围

### 0.1 目标

将现有前端从“深色/衬线体/大标语/网格装饰”的展示型视觉，改造为**黑白蓝灰、简约、功能优先**的工具型界面。

核心原则：

1. 功能优先，弱化宣传。
2. 干净背景，去除渐变与几何装饰。
3. 统一间距、对齐与字号层级。
4. 移动端可用。
5. 去除 AI 生成痕迹与 Vite 模板痕迹。

### 0.2 本次范围

- 全局设计令牌（颜色、字体、间距、圆角、阴影、动效）。
- 登录/注册页重构为居中单列。
- 首页去除 Hero 大标语、网格、编号、深色统计块。
- 题库、题目详情、编辑器、个人中心、排行榜、404 的视觉统一。
- 导航栏简化。
- 响应式与可访问性补齐。
- 不改变业务逻辑与接口调用方式。

### 0.3 不在本次范围

- 后端接口开发。
- 真实代码评测器。
- 管理端界面。
- 新功能（收藏、题解、排行榜接口）。
- 引入 Tailwind、组件库或新图标库。
- 业务数据结构调整。

> 数据接入、Mock 删除、预设业务数据清理以 CR-003 为准；本文只负责视觉与布局。两文档存在文件重叠，执行顺序见第 9 节。

## 1. 设计规范

### 1.1 配色

主视觉严格限定为**黑、白、蓝、灰**。

| 令牌 | 色值 | 用途 |
|---|---|---|
| `--color-primary` | `#0f172a` | 主文字、深色主色、Logo |
| `--color-primary-ink` | `#1a1a1a` | 备用深黑 |
| `--color-accent` | `#3b82f6` | 主按钮、链接、选中态 |
| `--color-accent-hover` | `#2563eb` | 主按钮 hover |
| `--color-accent-soft` | `#eff6ff` | 选中标签浅蓝底 |
| `--color-bg` | `#f8fafc` | 页面背景 |
| `--color-surface` | `#ffffff` | 卡片、导航、输入框 |
| `--color-text` | `#0f172a` | 正文主色 |
| `--color-text-secondary` | `#64748b` | 次要文字、说明 |
| `--color-text-muted` | `#94a3b8` | 占位符、辅助信息 |
| `--color-border` | `#e2e8f0` | 边框、分割线 |
| `--color-border-strong` | `#cbd5e1` | 输入框 hover、强调边框 |

**语义色例外**：难度与评测结果需要可辨识语义。允许使用低饱和语义色，但**仅限状态文本与状态标签**，不得用于装饰：

| 令牌 | 色值 | 用途 |
|---|---|---|
| `--color-success` | `#16a34a` | 通过、Accepted |
| `--color-warning` | `#d97706` | 中等难度、评测中 |
| `--color-danger` | `#dc2626` | 错误、失败 |

若坚持绝对黑白蓝灰，可退化为：简单/通过用 `#64748b`，中等用 `#3b82f6`，困难/失败用 `#0f172a`。需用户确认（见第 10 节）。

**禁止**：

- 任何线性/径向/重复渐变。
- 大面积深色块、彩色块。
- 渐变文字、渐变按钮。
- 非状态用途的红/绿/黄装饰。

### 1.2 字体

移除当前 Google Fonts 引入（`Manrope`、`Noto Serif SC`、`IBM Plex Mono`、`DM Mono`），避免外部请求、字体闪烁和“设计感过重”。

```css
--font-sans: Inter, -apple-system, BlinkMacSystemFont, "Segoe UI",
             "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: "JetBrains Mono", Consolas, "SFMono-Regular", monospace;
```

| 元素 | 字号 | 字重 | 行高 |
|---|---|---|---|
| 页面主标题 | 28px（移动端 24px） | 600 | 1.3 |
| 登录/注册标题 | 24px | 600 | 1.3 |
| 区块标题 | 20px | 600 | 1.4 |
| 卡片标题 | 16px | 500 | 1.5 |
| 正文 | 14–16px | 400 | 1.6 |
| 辅助文字 | 13px | 400 | 1.5 |
| 标签/说明 | 12px | 400/500 | 1.4 |
| 代码 | 13–14px | 400 | 1.6 |

要求：

- 标题不再使用衬线体。
- 字重最高 600，不使用 800/900。
- 标题字距使用 `-0.01em` 左右，禁止 `-4px`、`-5px` 这类夸张负字距。
- 正文不得小于 14px；注释/时间等辅助信息可用 12px。

### 1.3 间距系统（4 的倍数）

```css
--space-xs: 4px;
--space-sm: 8px;
--space-md: 16px;
--space-lg: 24px;
--space-xl: 32px;
--space-2xl: 48px;
```

使用规则：

- 页面主内容区上下留白：`48px` 或以上。
- 卡片内边距：`24px`（移动端 `16px`）。
- 表单字段间距：`16px`。
- 标题与内容间距：`16px`。
- 标签间距：`8px`。
- 禁止出现 `13px`、`17px`、`27px` 等非 4 倍数间距（字号除外）。

### 1.4 圆角、描边、阴影、动效

```css
--radius-sm: 8px;
--radius-md: 10px;
--radius-lg: 12px;
--shadow-sm: 0 1px 2px rgba(15, 23, 42, 0.04);
--duration: 150ms;
```

- 卡片、输入框、按钮统一 8–12px 圆角。
- 卡片使用 `1px solid #e2e8f0`，不使用重阴影。
- 阴影仅用于下拉菜单、弹窗，使用 `--shadow-sm`。
- 删除按钮 hover 位移、硬阴影、发光等效果。
- 仅保留必要的 background/color/border 过渡，时长 150ms。
- 保留 Loading spinner 与骨架屏，但骨架屏改为纯色透明度动画，不使用渐变。
- 支持 `prefers-reduced-motion: reduce`，关闭非必要动画。

### 1.5 按钮与链接

| 类型 | 样式 | 用途 |
|---|---|---|
| 主按钮 | 蓝底白字 `#3b82f6`，hover `#2563eb`，圆角 8px，高度 40–44px | 登录、注册、提交代码、搜索 |
| 次按钮 | 白底、1px `#e2e8f0` 边框、深色文字，hover 浅灰底 | 重置、运行、取消 |
| 文本按钮 | 蓝字或灰字，无边框，hover 下划线 | 切换登录/注册、清空筛选 |
| 危险文本 | `#dc2626` 文字，无背景 | 删除类操作 |

禁止：

- 主按钮使用渐变、阴影堆叠、超大箭头。
- 同级出现两个蓝色主按钮。
- 按钮宽度不一致导致视觉错位。

### 1.6 布局与响应式

| 场景 | 规范 |
|---|---|
| 内容最大宽度 | `1200px`（题库/首页），阅读区 `760px`–`820px` |
| 导航高度 | `64px` |
| 导航边框 | 底部 `1px solid #e2e8f0`，白色背景 |
| 登录页内容宽度 | `420px`，最大 `450px` |
| 卡片 | 白底 + 1px 边框 + 8–12px 圆角 |
| 断点 | `1024px`、`768px`、`480px` |
| 移动端页面边距 | `16px` |
| 触控目标 | 不小于 `40×40px`（主按钮 44px 高） |

响应式要求：

- 登录页：单列居中，移动端上下留白 `32px`。
- 首页：Hero 取消，内容单列；卡片纵向堆叠。
- 题库：表格在窄屏允许横向滚动，或改为卡片列表；筛选区纵向排列。
- OJ：桌面左右分栏；`768px` 以下改为上下布局，编辑器固定合理高度。
- 个人中心统计：4 列 -> 2 列 -> 1 列。
- 导航：窄屏保留核心入口，隐藏非核心入口，不使用横向溢出。

### 1.7 允许与禁止清单

**禁止使用**

- 渐变背景（线性、径向、重复）。
- 几何装饰图案（斜线、网格、多边形、旋转方块纹理）。
- 长篇宣传文案、口号、引用框、引言。
- 大面积彩色或深色色块。
- 过度阴影、发光、硬阴影。
- 装饰性数字编号（`01`、`02`、`OCT 15`）。
- 非功能性图标堆砌。
- 复杂动画（位移、缩放、视差）。
- 非对齐元素、绝对定位装饰字。

**允许使用**

- 1px 实线分割。
- 浅色 hover（背景变浅灰/浅蓝）。
- 8–12px 轻微圆角。
- 功能性图标（搜索、主题切换、返回、关闭）。
- 小标签（浅色背景 + 深色文字）。
- 微交互（按钮按下、输入框聚焦边框变蓝）。

## 3. 页面改造方案

### 3.1 登录/注册页（P0）

**模板调整**：

1. 删除 `.auth-intro` 整个左栏，包括品牌区、宣传标题、说明、引用、迷宫装饰。
2. 页面改为单列居中：

```text
main.auth-page
  └── section.auth-card
        ├── RouterLink.brand（居中）
        ├── header（标题 + 一句说明）
        ├── tabs（登录 / 注册）
        ├── form（必要字段）
        ├── 主按钮
        └── footnote
```

3. 保留“显示/隐藏密码”“记住我”“确认密码”等已有功能。
4. Logo 字号 24–28px，居中，顶部间距 32–48px。
5. 标题 24px；说明 14px `#64748b`。
6. 表单标签 13px，输入框高 44px，圆角 8px，聚焦边框 `#3b82f6`。
7. 主按钮全宽 44px，蓝底白字。
8. 底部提示 12–13px `#64748b`。
9. 移动端左右边距 16px，上下 32px。

**验收**：375px 宽度下无横向滚动；页面无任何渐变、网格、引用、宣传语。

## 4. 实施策略

### 4.1 不改技术栈

- 继续使用 Vue 3 + 原生 CSS。
- **不引入 Tailwind**。用户给出的 Tailwind 示例仅用于说明视觉方向，不作为技术选型。
- 不引入 Element Plus、Ant Design 等组件库。
- 图标继续使用现有内联 SVG；如需新增，优先内联 Lucide/Heroicons 路径，不新增依赖。

### 4.2 CSS 组织

当前 `src/style.css` 为单行压缩式写法，不利于维护。建议：

1. 保留现有类名，减少模板大改。
2. 重写 `src/style.css`，按以下顺序组织：
   - reset/base
   - design tokens
   - layout（header/page-shell）
   - components（button/input/card/tag/table）
   - pages（home/auth/problems/oj/profile/rankings/404）
   - responsive
3. 删除不再使用的类（`.hero-grid`、`.hero-number`、`.auth-intro`、`.maze-lines`、`.stats-band`、`.ranking-podium` 等）。
4. 所有颜色、间距、圆角、阴影必须引用令牌，禁止散落硬编码。
5. 单个选择器保持可读，不强制压缩为一行。

### 4.3 明暗模式

v1 要求支持深色模式，建议保留，但改为中性色板：

```css
:root[data-theme='dark'] {
  --color-bg: #0f172a;
  --color-surface: #1e293b;
  --color-text: #f1f5f9;
  --color-text-secondary: #94a3b8;
  --color-border: #334155;
  --color-accent: #60a5fa;
  --color-accent-hover: #3b82f6;
  --color-accent-soft: #1e3a5f;
}
```

- 深色模式同样禁止渐变和装饰。
- 编辑器深色主题仅限代码区域。
- 若用户决定移除深色模式，需同时移除导航主题切换与 `main.ts` 中的主题初始化。

### 4.4 与 CR-003 的协作

两篇文档都会修改 `views` 与 `style.css`，必须约定顺序：

**推荐顺序：先执行 CR-003（数据接入与预设清理），再执行 CR-004（视觉重构），最后由 CR-005 接入真实运行代码。**

> “运行代码”的真实执行链路、`run_config`、弹窗与结果 Tab 以 [运行代码功能设计方案](./2610241_运行代码功能设计方案.md) 为准；本文只保留运行按钮的视觉位置与样式。

理由：

- CR-003 会删除 Mock、重写视图数据绑定，模板结构会变化。
- CR-004 在稳定的模板上做纯视觉改造，冲突更少。
- CR-003 会删除排行榜假数据、首页假统计、模拟评测提示，正好减少 CR-004 的清理工作。

若必须并行：

- CR-003 负责 `api/`、`store/`、`types/`、数据绑定。
- CR-004 负责 `style.css`、`components/NavBar.vue`、纯展示模板。
- 同一文件同一区域禁止双方同时修改；以 CR-003 的数据结构为准。

## 8. 风险与回滚

| 风险 | 等级 | 缓解 |
|---|---|---|
| 与 CR-003 修改同一视图导致冲突 | 高 | 先 CR-003 后 CR-004；或按文件分工 |
| 删除外部字体后布局跳动 | 中 | 统一行高与字号；多视口检查 |
| 语义色缺失导致状态难辨识 | 中 | 使用状态标签 + 文字，不只依赖颜色 |
| 深色模式与新浅色令牌冲突 | 中 | 同步定义 dark tokens；或经确认移除深色模式 |
| 表格在移动端溢出 | 中 | 横向滚动容器或卡片化 |
| 过度删减导致功能入口不明显 | 中 | 保留主操作按钮与清晰导航，不做“极简到不可用” |
| 样式重写引入未使用选择器 | 低 | 按页面清理；构建后检查 |
| 无自动化视觉测试 | 低 | 手工多视口验收 + 截图留档 |

回滚：

- 每个 UI 任务独立提交，可按任务 `git revert`。
- `style.css` 重写作为单独提交，回滚即恢复旧样式。
- 不涉及数据库与后端，回滚无数据风险。
- 若仅单个页面异常，回滚该页面模板/CSS 片段，不回滚全局令牌。
