## 1. 阶段 1：需求理解

### 1.1 业务目标

Theseus 是在线编程训练平台。本次 CR 的目标不是新增业务，而是：

1. 把前端从 Mock 数据切换到真实后端 API，打通登录、题库、题目详情、代码提交、提交结果查询、个人提交记录。
2. 删除前端所有预设/占位/假数据，避免演示数据被误认为真实数据。
3. 形成可供工作 Agent 独立执行、独立验证的任务清单。

### 1.2 用户角色

| 角色 | 能力 | 本次范围 |
|---|---|---|
| 游客 | 浏览题库、题目详情、首页 | 是 |
| 登录用户 | 提交代码、查看自己的提交记录与状态、提交自定义题目 | 是 |
| 管理员 | 创建/修改/删除题目、审核自定义题目 | 后端已具备，前端管理界面**不在本次范围** |

### 1.3 主流程

```text
注册/登录
  -> 首页（题库统计/推荐）
  -> 题库列表（分页、难度/标签/状态筛选、搜索、排序）
  -> 题目详情（描述、示例、代码模板）
  -> 编辑代码
  -> 提交代码（POST /api/submissions）
  -> 轮询提交结果（GET /api/submissions/:id）
  -> 结果展示（状态、通过用例数、耗时、内存、错误信息）
  -> 个人中心（最近提交、通过数）
```

### 1.4 异常流程

| 场景 | 期望行为 |
|---|---|
| 未登录访问需要鉴权的操作 | 后端 401，前端清理登录态并跳转登录页 |
| Token 过期 | 同上，且不出现无限跳转 |
| 登录失败 | 展示“用户名或密码错误”，不能展示“请先登录” |
| 注册用户名/邮箱重复 | 后端 409，前端展示冲突提示 |
| 题库为空 | 展示空态，不回退到 Mock 数据 |
| 题目不存在/已下架 | 后端 404，题目页展示错误态 |
| 筛选无结果 | 展示空态，不报错 |
| 提交空代码/非法语言 | 后端 400，前端拦截并提示 |
| 评测服务未配置 | 提交最终状态为 `runtime_error`，展示真实错误信息，不伪造 `accepted` |
| 网络超时/后端不可用 | 展示可重试错误，不静默失败 |
| 重复点击提交 | 按钮禁用，避免重复创建提交记录 |

### 2.2 后端模块与调用关系

```text
main.rs
  -> Config::from_env
  -> create_pool
  -> db::migrate (sqlx::migrate!("./migrations"))
  -> routes::router(AppState)
        -> auth_handler       -> auth_service -> utils(jwt/password) -> users
        -> problem_handler    -> middleware(auth/admin) -> problems / user_problem_status
        -> submission_handler -> middleware(auth) -> submissions / problems / user_problem_status
                              -> tokio::spawn(JudgeService)
```

关键文件：

- `backend-rust/src/routes/mod.rs`：全部路由注册、CORS、Trace。
- `backend-rust/src/common/response.rs`：统一响应 `{success,data,error}`。
- `backend-rust/src/common/error.rs`：`AppError` 到 HTTP 状态码映射。
- `backend-rust/src/handlers/problem_handler.rs`：题库查询、筛选、自定义题、审核、增删改。
- `backend-rust/src/handlers/submission_handler.rs`：创建提交、异步评测、详情、列表。
- `backend-rust/src/services/judge_service.rs`：当前仅实现 `pending -> judging -> runtime_error`。
- `backend-rust/src/middleware/auth.rs`：`authenticate` / `optional_authenticate` / `require_admin`。

### 2.4 前端模块与调用关系

```text
main.ts -> router + pinia
router/index.ts -> views
views
  -> components/NavBar
  -> store/auth        -> api/mock   (问题点)
  -> store/problems    -> api/mock   (问题点)
  -> store/submissions -> api/mock   (问题点)
```

关键事实：

- `src/api/http.ts` 已有 Axios 实例与 401 拦截器，但全项目没有其他文件引用它。
- `src/store/auth.ts:3`、`src/store/problems.ts:3`、`src/store/submissions.ts:3` 均 `import { mockApi } from '../api/mock'`。
- 题库筛选、搜索、排序、分页全部在前端 `computed` 中完成（`store/problems.ts`），因此即使只替换数据源，也无法与后端分页语义一致。

- `http.ts` 的 401 跳转使用 `window.location.hash = '#/login'`，但路由是 `createWebHistory()`，该跳转不会生效。

## 3. 阶段 3：方案设计

### 3.1 方案对比

| 方案 | 内容 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 前端适配后端契约（推荐） | 新增 API 层与适配器，删除 Mock，后端做少量契约补丁 | 改动集中、风险低、保持后端统一响应 | 前端需要字段映射 | **采用** |
| B. 保留 Mock 开关 | 用环境变量在 Mock/真实间切换 | 可离线开发 | 容易误用、预设内容无法真正清空、验收不真实 | 拒绝 |
| C. 后端改为前端现有字段 | 后端返回 `acceptance/inputDescription/...` | 前端改动小 | 契约混乱、影响后续管理端、与 v1 文档不一致 | 拒绝 |

### 3.2 最小改动清单

#### 3.2.1 前端

1. 新增 `frontend-vue/.env.example`，定义 `VITE_API_BASE_URL=/api`。
2. 修改 `vite.config.ts`，开发代理 `/api -> http://127.0.0.1:3000`。
3. 新增 `src/api/client.ts`：
   - 复用 `http.ts`；
   - 解包 `{success,data,error}`；
   - `success=false` 时抛出带后端 `error` 文案的错误；
   - 401 跳转改用 `window.location.assign('/login')` 或 router 实例。
4. 新增 `src/api/auth.ts`、`src/api/problems.ts`、`src/api/submissions.ts`、`src/api/stats.ts`（若 Q6 采纳）。
5. 新增 `src/api/adapters.ts`：后端 DTO -> 前端 ViewModel 映射。
6. 改造 `store/auth.ts`：调用真实登录/注册；注册后自动登录。
7. 改造 `store/problems.ts`：
   - `loadProblems` 从服务端分页；
   - 筛选/搜索触发重新请求；
   - 服务端排序（若 Q7 采纳）；
   - `tags` 来自标签接口或当前返回集合。
8. 改造 `store/submissions.ts`：
   - 提交调用真实接口；
   - 轮询详情直到非 `pending/judging`；
   - 列表来自 `GET /api/submissions`；
   - 删除 localStorage 提交缓存。
9. 改造视图字段映射：
   - `ProblemsPage` 使用 `acceptance_rate`、`status`；
   - `OjPage` 使用 `code_template`、`examples`、真实提交状态；
   - `ProfilePage` 使用真实提交列表；
   - `IndexPage` 使用真实统计/推荐。
10. 删除预设内容（见 0.2 表）。
11. `index.html`、`README.md`、favicon 替换。

#### 3.2.2 后端

1. 登录支持用户名或邮箱（若 Q5 采纳）：`WHERE username = $1 OR email = $1`。
2. 新增 `AppError::InvalidCredentials`，登录失败返回 401 + `用户名或密码错误`。
3. 题库列表新增白名单排序参数 `sort=id|difficulty|acceptance_rate`、`order=asc|desc`（若 Q7 采纳）。
4. 新增 `GET /api/problems/tags`：返回已审核题目的去重标签。
5. 新增 `GET /api/stats`：返回题目总数、提交总数、通过提交数（若 Q6 采纳）。
6. 新增开发种子 SQL（若 Q8 采纳），仅用于本地/测试环境。
7. 仓库卫生与安全：
   - 根 `.gitignore` 增加 `backend-rust/target/`、`backend-rust/.env`；
   - `git rm -r --cached backend-rust/target backend-rust/.env`；
   - 轮换 `JWT_SECRET`；
   - 保留 `backend-rust/.env.example`。

> 后端改动均为**增量**，不涉及数据库迁移，不改既有表结构。

### 3.3 契约映射设计

| 功能 | 后端请求 | 前端适配 |
|---|---|---|
| 登录 | `POST /api/auth/login {username,password}` | 直接使用；若后端支持邮箱则同一字段 |
| 注册 | `POST /api/auth/register {username,email,password}` | 成功后立即调用登录 |
| 题库列表 | `GET /api/problems?page&size&difficulty&tag&status&search&sort&order` | 查询参数由 store 维护；响应 `total` 驱动分页 |
| 题目详情 | `GET /api/problems/{id}` | `acceptance_rate -> acceptance`；`code_template` 取代 `DEFAULT_CODE` |
| 提交 | `POST /api/submissions {problem_id,language,code}` | `submission_id` 用于轮询 |
| 提交详情 | `GET /api/submissions/{id}` | 状态映射 + 数值格式化 |
| 提交列表 | `GET /api/submissions?page&size&problem_id` | 个人中心使用 |

状态映射建议：

```text
pending             -> Running
judging             -> Running
accepted            -> Accepted
wrong_answer        -> Wrong Answer
time_limit_exceeded -> Time Limit Exceeded
memory_limit_exceeded -> Memory Limit Exceeded
runtime_error       -> Runtime Error
compile_error       -> Compile Error
```

### 3.5 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 前端直接对接后题库为空 | 高 | 提供开发 seed；或用管理员接口创建；验收前确认数据 |
| 评测器未接入，所有提交都是 `runtime_error` | 高 | 明确不在本次范围；验收只验证生命周期与真实错误展示 |
| 注册契约不一致导致登录态丢失 | 中 | 注册后自动登录；补测试 |
| 分页/筛选从前端改服务端后行为回退 | 中 | 逐项验收查询参数；保留 URL 筛选同步 |
| 提交轮询造成请求过多 | 中 | 间隔 1s、超时上限、页面卸载停止 |
| 重复提交创建多条记录 | 中 | 提交按钮禁用；轮询期间不可重复提交 |
| 排序参数注入 | 低 | 白名单枚举，禁止拼接原始字符串 |
| 删除 Mock 后无离线开发能力 | 低 | 使用真实后端或后续单独提供 mock server，不在生产代码内保留 |
| `.env` 已入库、JWT secret 泄露 | 高 | 立即移出索引并轮换 secret |
| `target/` 已入库导致仓库膨胀 | 中 | 移出索引，历史清理另行评估 |
| CORS 当前 `permissive` | 中 | 开发可保留；上线前按域名收紧 |
