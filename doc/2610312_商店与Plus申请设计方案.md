# 商店与 Plus Theseus 申请设计

> 日期：2026-10-31
> 状态：v2 已实现（新增会员有效期与权益）
> 关联：`总体设计.md` 4.4、`2610303_审计中心设计方案.md`、`2610313_面经板块设计方案.md`

## 1. 目标

在顶部导航为学生与教师提供「商店」入口，商店的第一个栏目是「升级为 Plus Theseus」。

本期范围：

1. 顶部「商店」下拉菜单，仅学生与教师可见；管理员不显示该入口；
2. `/shop` 商店页，展示 Plus Theseus 介绍、当前开通状态与申请表单；
3. 学生/教师提交开通申请，管理员在管理端审核通过或驳回；
4. 审核结果写入站内信，并写入审计日志；
5. 管理员审核通过时填写开通天数，写入 `plus_memberships`；
6. 到期后 `is_plus` 自动变为 false，用户可以重新申请。

Plus 权益 v1：

- 面经板块的列表、详情、评论、点赞、收藏与发帖权限；
- 导航用户菜单与论坛帖子、评论作者旁的 Plus 标识。

有效期由管理员在审核时填写（1–3650 天）。同一用户只有一段当前会员期，续期在原记录上顺延；到期不自动续费，需要重新申请。

## 2. 数据模型

新增迁移 `0028_plus_applications.sql`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGSERIAL | 主键 |
| `user_id` | INTEGER | 申请人，外键 `users(id)`，随用户删除级联 |
| `reason` | TEXT | 申请说明，最多 500 字 |
| `status` | VARCHAR(16) | `pending` / `approved` / `rejected` |
| `review_note` | TEXT | 审核说明，可选 |
| `reviewed_by` | INTEGER | 审核管理员，外键 `users(id)`，删除后置空 |
| `reviewed_at` | TIMESTAMPTZ | 审核时间 |
| `created_at` | TIMESTAMPTZ | 提交时间 |

约束与索引：

- `CHECK (status IN ('pending','approved','rejected'))`；
- `(user_id, created_at DESC)` 与 `(status, created_at DESC)` 普通索引；
- `UNIQUE (user_id) WHERE status = 'pending'`：同一用户同时只能有一条待审核申请，驳回后可重新提交。

新增迁移 `0033_plus_memberships.sql`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `user_id` | INTEGER | 主键，外键 `users(id)`，随用户删除级联 |
| `application_id` | BIGINT | 本次开通对应的申请，申请删除后置空 |
| `started_at` | TIMESTAMPTZ | 当前会员期开始时间 |
| `expires_at` | TIMESTAMPTZ | 到期时间，`expires_at > CURRENT_TIMESTAMP` 时才算 Plus |
| `updated_at` | TIMESTAMPTZ | 最近续期时间 |

- 一个用户只有一行，续期时用 `GREATEST(expires_at, CURRENT_TIMESTAMP) + days` 顺延；
- `0033` 为历史已通过申请补 30 天，从迁移时刻开始计算；
- 是否 Plus 不再看申请状态，只查 `plus_memberships`。

## 3. 后端接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/shop/plus` | 登录 | 当前是否开通 + 当前会员期 + 最近一条申请 |
| POST | `/api/shop/plus/apply` | 学生/教师，邮箱已验证 | 提交开通申请 |
| GET | `/api/admin/plus-applications` | 管理员 | 按状态分页查询申请，附带用户当前到期时间 |
| POST | `/api/admin/plus-applications/{id}/resolve` | 管理员 | 通过或驳回；通过时必填 `days` |

规则：

- 管理员调用申请接口返回 403「管理员无需申请 Plus Theseus」；
- 当前会员期有效时不可再次申请；已有 `pending` 申请时返回 409；
- 已过期的 `approved` 申请不再阻止重新申请；
- 审核只接受 `approved` / `rejected`，且只能处理 `pending` 状态的申请；
- `approved` 时 `days` 必填，范围 1–3650；`rejected` 忽略 `days`；
- 审核在事务内更新申请、写入或顺延 `plus_memberships`，并写 `plus_application` 站内信，通知正文包含到期日期；
- 审核成功后写入审计日志：动作 `plus.application_resolve`，对象 `plus_application`，服务端记录状态、审核说明与开通天数。

## 4. 前端实现

### 4.1 导航

`frontend-vue/src/components/NavBar.vue` 在「个人」之后、「管理」之前插入「商店」下拉菜单，显示条件复用 `canBrowseAssignments`（学生或教师）。下拉菜单当前只有一项「升级为 Plus Theseus」，跳转 `/shop`。学生与教师登录后读取 `/api/shop/plus`，已开通时在用户菜单用户名旁显示 Plus 标识。

管理端「管理」菜单新增「Plus 申请」，跳转 `/admin/plus-applications`。

### 4.2 商店页

`frontend-vue/src/views/ShopPage.vue`：

- 标题「商店」，第一个栏目为 Plus Theseus 卡片；
- 展示当前状态：审核中 / 已开通 / 已过期 / 未通过；
- 展示权益清单：面经板块完整权限、Plus 专属标识；
- 已开通或已过期时展示开通时间、有效期与剩余天数；
- 已提交过申请时展示申请说明、提交时间、审核时间与审核说明；
- 可申请状态下展示 500 字以内的申请说明输入框与提交按钮；已过期时按钮文案为「重新开通」；
- 申请成功后原地刷新状态，并提示「申请已提交，请等待管理员审核」。

样式新增 `frontend-vue/src/styles/shop.css`，沿用 `--color-warning-soft`、`--color-success-soft`、`--color-danger-soft` 等既有 token，暗色主题自动适配。

### 4.3 管理端

`frontend-vue/src/views/AdminPlusApplicationsPage.vue`：

- 状态筛选：全部 / 待处理 / 已通过 / 未通过，默认待处理；
- 表格展示用户、申请说明、状态、提交与审核信息，已开通用户显示当前有效期；
- 待处理申请可填写开通天数（默认 30，范围 1–3650）与审核说明，再「通过」或「驳回」；
- 复用赛事申诉页的表格与操作样式。
