# 面经板块设计方案

> 日期：2026-10-31
> 状态：v3 已实现（并入论坛板块）；原 v1 独立学习专区已下线
> 关联：`2610312_商店与Plus申请设计方案.md`、`backend_api.md`

## 1. 目标

面经不再是独立的学习专区，而是论坛的一个板块：

- 面经是 `forum_posts.board = 'interview'` 的帖子
- 列表、详情、评论、点赞、收藏、举报、审核全部复用论坛能力
- 题目写在正文，答案写在评论区，用户可以在评论区补充思路与代码
- 面经板块只对 Plus Theseus、管理员和帖子作者开放

原独立面经模块的列表页、投稿页、审核页与 `/api/knowledge*` 接口已删除，旧链接重定向到论坛。

## 2. 权限规则

| 角色 | 面经列表 | 面经详情与评论 | 发面经 | 评论 / 点赞 / 收藏 / 举报 |
|---|---|---|---|---|
| 未登录 | 不可，403 | 不可，403 | 不可 | 不可 |
| 学生 / 教师（非 Plus） | 不可，提示开通 | 不可，提示开通 | 不可 | 不可 |
| 学生 / 教师（Plus） | 可以 | 可以 | 可以 | 可以 |
| 面经作者（即使未开通） | 可以 | 可以 | 可以 | 可以 |
| 管理员 | 可以 | 可以 | 可以 | 可以 |

- Plus 身份沿用 `plus_memberships`：`expires_at` 晚于当前时间才算开通，到期后立即失去面经权限
- 权限判断集中在 `forum_service::ensure_board_access`
- 无权限返回 `403`，错误文案「需要开通 Plus Theseus 才能查看面经」；前端据此显示开通入口
- 综合板块 `board = 'general'` 的权限与原来的论坛完全一致

## 3. 数据模型

`0032_forum_interview_board.sql` 修改 `forum_posts`：

| 字段 | 说明 |
|---|---|
| `board` | `general` / `interview`，默认 `general`，有 CHECK 约束 |
| `interview_date` | 面试时间，`YYYY-MM`，可空，有格式约束 |
| `company` | 公司，≤40 字，可空（`0034`） |
| `role` | 岗位，≤40 字，可空（`0034`） |
| `view_count` | 阅读数，非负整数，详情页每次打开 +1（`0034`） |

- 标签约束放宽为 `cardinality(tags) BETWEEN 1 AND 8`
- 综合板块由服务层限制为 3 个已知标签
- 面经板块允许 1–8 个自由标签，每个最多 20 字
- 新增索引 `(board, status, is_pinned DESC, created_at DESC)` 支撑板块列表
- `0034` 为面经新增 `company`、`role` 与 `view_count`，并为公司与岗位建立部分索引
- 历史帖子的公司与岗位在重新导入后补齐；阅读数从 0 开始累计

### 3.1 历史数据迁移

迁移会把 `knowledge_articles` 中 `status = 'approved'` 的文章复制为面经帖子：

- `board = 'interview'`
- `body_md` 取原文 `content`
- `tags` 取原标签，超过 8 个截断；没有标签时使用 `['面经']`
- `author_id` 为空时归到最早的管理员，没有管理员则跳过
- 按 `board = 'interview' AND title` 去重，可重复执行
- `knowledge_articles` 表保留作为历史数据，不再有写入接口

## 4. 接口

面经复用论坛接口，通过 `board` 参数区分板块。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/forum/posts?board=interview` | Plus / 管理员 / 作者 | 面经列表，支持 `tag`、`company`、`role`、`q`、`sort`、`mine` |
| GET | `/api/forum/interview/facets` | Plus / 管理员 | 返回已发布面经的可选公司与岗位，供筛选器使用 |
| POST | `/api/forum/posts` | Plus / 管理员 | 请求带 `board:"interview"`、`interview_date`、`tags` |
| GET | `/api/forum/posts/{id}` | Plus / 管理员 / 作者 | 面经详情，无权限返回 403 |
| PUT | `/api/forum/posts/{id}` | 作者 | 编辑标题、正文、标签、面试时间、公司与岗位 |
| GET | `/api/forum/posts/{id}/comments` | Plus / 管理员 / 作者 | 评论区，答案放在这里 |
| POST | `/api/forum/posts/{id}/comments` | Plus / 管理员 / 作者 | 发表答案或追问 |
| POST/DELETE | `/api/forum/posts/{id}/like` | Plus / 管理员 / 作者 | 点赞或取消 |
| POST/DELETE | `/api/forum/posts/{id}/favorite` | Plus / 管理员 / 作者 | 收藏或取消 |
| POST | `/api/forum/reports` | Plus / 管理员 / 作者 | 举报面经或评论 |
| GET | `/api/admin/forum/posts?board=interview` | 管理员 | 管理端按板块筛选，不受 Plus 限制 |

### 4.1 请求字段

创建或编辑面经：

```json
{
  "board": "interview",
  "title": "百度后端 · 二面（2026-10）",
  "body_md": "## 面试流程\n\n## 题目\n\n...",
  "tags": ["百度", "后端", "场景题"],
  "interview_date": "2026-10",
  "company": "百度",
  "role": "后端",
  "problem_id": null,
  "is_anonymous": false
}
```

- `board` 只接受 `general` / `interview`，缺省为 `general`
- `interview_date` 只接受 `YYYY-MM` 或空
- `company`、`role` 去掉首尾空白后 ≤40 字，空值写 `null`；只对 `interview` 板块生效
- 面经标签 1–8 个，每个 ≤20 字
- 综合板块标签仍只接受 `general` / `help` / `solution` / `discussion` / `announcement`，最多 3 个
- 编辑时板块不可切换

### 4.2 列表响应

`ForumPostSummary` 新增：

```json
{
  "board": "interview",
  "interview_date": "2026-10",
  "company": "百度",
  "role": "后端",
  "view_count": 42
}
```

前端在卡片和详情优先显示「面试 2026-10」，没有面试时间时回退到发布时间；公司与岗位显示为结构化标签，标签列表不再重复公司；卡片与详情显示阅读数。

## 5. 前端

| 路由 | 说明 |
|---|---|
| `/forum` | 综合板块列表 |
| `/forum?board=interview` | 面经板块列表；非 Plus 显示开通提示 |
| `/forum/new?board=interview` | 发布面经，仅 Plus / 管理员可选面经板块 |
| `/forum/{id}` | 面经详情与评论区 |

- 导航「学习 → 面经」指向 `/forum?board=interview`
- 旧路由 `/knowledge/*`、`/personal/knowledge` 重定向到论坛
- 旧管理页 `/admin/knowledge` 重定向到 `/admin/forum`
- 管理端内容管理新增板块筛选，面经卡片带「面经」标记
- 发面经时标签使用自由输入，支持回车或逗号添加、点击移除，最多 8 个
- 面经列表提供公司、岗位下拉筛选，选项来自 `/api/forum/interview/facets`
- 发面经与编辑面经时可填写公司与岗位，草稿会一并保存

## 6. Markdown 归档与导入

`doc/interview` 仍是面经的原始来源：

- 每个文件一场面试，包含 frontmatter、`## 面试流程`、`## 题目`、`## 复盘`
- `scripts/import_interview.sh` 从 Markdown 批量导入面经板块
- 标题取一级标题并作为去重键
- 标签取 frontmatter 的 `tags`，并自动加入公司，最多 8 个
- 面试时间取 frontmatter 的 `date`
- 公司与岗位取 frontmatter 的 `company`、`role`，缺省时回退到目录名，各 ≤40 字
- 写库时直接发布为 `interview` 板块，必须用 `--author` 指定作者
- `--update` 覆盖已存在标题的正文、标签、面试时间、公司与岗位
- `--no-answers` 只保留题目与 `**题目**` / `**题意**` 描述；面试流程、复盘、待补充与答案都不导入

## 7. 已知限制

- 阅读数按详情页打开次数累计，同一用户重复打开会重复计数，暂未做去重
- 公司/岗位筛选为精确匹配，暂不支持多选与组合统计
- 面经与综合帖子共用论坛的发帖频率、评论频率与举报阈值
- 历史 `knowledge_articles` 表保留，但不再提供读写接口
