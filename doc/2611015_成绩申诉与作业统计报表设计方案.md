# 成绩申诉与作业统计报表设计方案

> 日期：2026-11-01
> 状态：v1 已实现
> 关联：`2610271_作业策略的实现.md`、`2610302_教学数据导入导出设计方案.md`、`2610303_审计中心设计方案.md`、`2610301_防作弊代码相似度设计方案.md`、`backend_api.md`

## 1. 背景

教学闭环已经覆盖「布置作业 → 提交 → 判题 → 批改 → 发布成绩 → 站内通知」，但成绩发布后学生没有正式的复核入口，教师也缺少可交给教务或存档的统计报表。成绩异议只能私下沟通，处理过程没有留痕；组织统计只在页面内展示，无法导出。

本期补齐两件事：

- 成绩申诉：学生在成绩发布后对整份作业提交一次申诉，教师受理或驳回并填写说明，结果写站内信，处理动作写审计。
- 统计报表：教师可导出 CSV，包含概况、逐题统计与未提交名单；页面上的逐题统计补充「未提交人数」。

不新增独立的申诉工作台，入口放在学生侧作业详情与教师侧批改台，避免再扩一套导航。

## 2. 目标与非目标

### 2.1 目标

- 成绩可见后，学生每份作业可提交一次申诉，理由必填、上限 2000 字。
- 教师只处理自己组织作业的申诉；受理与驳回都要可追溯。
- 申诉结论不直接改分，改分仍走批改台与既有 `grade.*` 审计，避免出现两套改分路径。
- 教师可导出统计 CSV（UTF-8 BOM），Excel 可直接打开。
- 统计口径与批改台一致：复用 `compute_gradebook` 的结果，不重新计算分数。
- 不改变现有判题、计分、成绩可见性与发布流程。

### 2.2 非目标

- 多轮申诉、申诉撤回、申诉时效限制。
- 学生选择到具体题目的申诉（v1 按整份作业申诉，理由里可写题号）。
- 申诉与改分放在同一次提交里（避免绕开批改台的分数校验与审计）。
- 学生查看未提交名单（仅教师导出包含）。
- 统计图表与 Excel 多工作表；v1 只做 CSV。

## 3. 数据模型

新增迁移 `0040_assignment_grade_appeals.sql`：

```sql
CREATE TABLE assignment_grade_appeals (
    id BIGSERIAL PRIMARY KEY,
    assignment_id INTEGER NOT NULL REFERENCES assignments(id) ON DELETE CASCADE,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    reason TEXT NOT NULL CHECK (length(btrim(reason)) > 0),
    status VARCHAR(20) NOT NULL DEFAULT 'pending'
        CHECK (status IN ('pending', 'accepted', 'rejected')),
    handled_by INTEGER REFERENCES users(id) ON DELETE SET NULL,
    handle_note TEXT,
    handled_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE (assignment_id, user_id)
);
```

- `UNIQUE (assignment_id, user_id)` 保证每份作业每人一条，重复提交返回 409。
- 索引 `(assignment_id, status, created_at DESC)` 供教师按状态筛选，`(user_id, created_at DESC)` 供学生查询。
- 状态机：`pending → accepted` 或 `pending → rejected`，处理后再调用返回 409。
- `handle_note` 上限 500 字，处理人存 `handled_by`，用户注销时置空，申诉记录保留。

## 4. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/assignments/{id}/grade-appeals` | 学生 | 提交申诉 `{reason}`，返回 `{id,status,message}` |
| GET | `/api/assignments/{id}/grade-appeals/mine` | 学生 | 返回本人的申诉或 `null` |
| GET | `/api/assignments/{id}/grade-appeals` | 作业所属教师 | 列表，可选 `status=pending\|accepted\|rejected` |
| POST | `/api/assignments/{id}/grade-appeals/{appeal_id}/resolve` | 作业所属教师 | 处理 `{decision,note}`，`decision` 为 `accepted`/`rejected` |
| GET | `/api/assignments/{id}/statistics/export` | 作业所属教师 | 导出统计 CSV，UTF-8 BOM |

### 4.1 提交条件

学生提交时依次校验：

1. 当前用户必须是学生，且是该组织 `active` 成员。
2. 作业状态为 `published`；草稿与已归档不可申诉。
3. `grades_published_at` 非空，且 `score_visibility` 已满足可见条件。
4. 理由去空白后非空、不超过 2000 字。
5. `ON CONFLICT DO NOTHING` 保证唯一；重复提交返回 409「该作业已提交过申诉」。

提交成功后给作业所属教师写站内信 `grade_appeal_created`，链接指向批改台 `/assignments/{id}/grade`。

### 4.2 处理

- 教师校验 `accepted`/`rejected` 与备注长度后，事务内 `SELECT ... FOR UPDATE` 锁定申诉。
- 申诉不存在或不属于该作业返回 404；已处理返回 409。
- 更新状态、处理人、备注与时间，并给学生写站内信 `grade_appeal_resolved`，标题为「成绩申诉已受理」或「成绩申诉已驳回」，正文附教师说明。
- 受理文案提示「成绩如有调整以批改台最新结果为准」，避免学生误以为受理即自动改分。
- 受理与驳回都不改动 `assignment_problem_grades` 与 `assignment_results`。

### 4.3 审计

- 提交：`grade.appeal_submit`，对象 `assignment`，`after` 记录申诉 ID 与状态。
- 处理：`grade.appeal_resolve`，对象 `assignment`，`after` 记录申诉 ID 与最终状态。
- 改分仍由 `grade.problem_update` / `grade.overall_update` 记录，审计中心可按动作区分「申诉」与「改分」。

## 5. 统计报表

### 5.1 接口结构

`GET /api/assignments/{id}/statistics` 的逐题统计新增 `not_submitted_count`：未做任何提交且未被免修的学生数。学生可见的匿名字段保持只有计数，不包含名单。

导出仅作业所属教师可调用，文件名 `assignment-{id}-statistics.csv`，内容分三段：

```text
作业统计,<标题>
学生数,20
已提交学生数,15
未提交学生数,5
平均分,78.5

题目 ID,题目,分值,通过人数,通过率,平均分,免修人数,未提交人数
7,两数之和,100,12,60%,82.5,0,4

未提交名单
用户名,邮箱
...
```

- 口径与 `statistics` 共用 `problem_stats`：通过人数按 `accepted`，通过率分母为组织学生总数，平均分只统计 `included_in_total` 的单元格。
- 未提交名单为整份作业没有任何提交的学生，与 `submitted_student_count` 互补。
- 使用 `csv_field` 转义逗号、引号与换行，文件以 UTF-8 BOM 开头。
- 导出不写审计日志：只读操作，且教师本就有批改台权限。

## 6. 前端

### 6.1 学生侧

`AssignmentDetailPage.vue`：

- 成绩已发布且学生能看到分数时，加载 `GET /grade-appeals/mine`。
- 新增「成绩申诉」面板：未申诉时显示「提交申诉」，打开弹窗填写理由；已有申诉时显示状态徽标、提交时间、理由与教师说明，不再提供再次提交。
- 状态徽标：待处理、已受理、已驳回，复用 `teaching-badge` 样式。
- 提交成功后重新拉取本人申诉，面板即时更新。

### 6.2 教师侧

`AssignmentDetailPage.vue` 顶部「导出统计报表」按钮下载 CSV；逐题统计显示「未提交 N」。

`GradebookPage.vue`：

- 顶部新增「成绩申诉」按钮，打开弹窗，默认只列待处理，可切换到全部。
- 每条申诉展示学生、状态、提交时间、理由与已处理说明。
- 待处理条目提供「受理」「驳回」与可选处理说明；驳回二次确认。
- 弹窗提示「受理后请在批改台按需调整分数 改分仍写入审计」，教师关闭弹窗后照常点击单元格改分。

### 6.3 通知与审计页面

- 通知类型新增 `grade_appeal_created`、`grade_appeal_resolved`，前端标签「成绩申诉」「申诉结果」，图标分别为 📝 与 ⚖。
- 审计中心动作标签新增「提交成绩申诉」「处理成绩申诉」。

## 7. 权限与边界

| 场景 | 处理 |
|---|---|
| 教师提交申诉 | 403「只有学生可以提交成绩申诉」 |
| 非成员学生访问 | 404，不泄露作业存在性 |
| 成绩未发布 | 409「成绩尚未发布」 |
| 草稿或归档作业申诉 | 409「作业当前状态不能申诉」 |
| 重复提交 | 409「该作业已提交过申诉」 |
| 非 owner 教师查看或处理 | 404 |
| 已处理申诉再次处理 | 409「该申诉已处理」 |
| 学生被移出组织 | 无法提交；已有申诉仍可在列表保留，由教师处理 |
| 受理后未改分 | 申诉状态为已受理，分数保持原样，需教师手动调整 |
| 教师注销 | `handled_by` 置空，历史说明保留 |
| 组织归档 | 作业不可见不可申诉；已提交申诉仍可由教师处理 |

- `cargo fmt --all --check`

- `npm run build`
- `bash backend-rust/scripts/smoke_grade_appeals.sh`：真实 API 校验提交、重复提交、列表筛选、受理与重复处理、越权与统计导出。
- 手工验证：
  - 学生发布成绩后提交申诉，教师收到站内信；重复提交返回 409。
  - 教师受理与驳回，学生收到结果站内信，页面状态同步。
  - 教师改分后导出成绩与统计，CSV 在 Excel 中中文正常、未提交名单正确。
  - 学生只能看到申诉入口与自己的一条记录，看不到其他学生。
  - 审计中心可检索两类申诉动作，改分仍显示原动作。
