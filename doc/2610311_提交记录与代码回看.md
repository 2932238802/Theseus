# 题目页提交记录与代码回看设计

> 日期：2026-10-31
> 状态：v1 已实现（前端）
> 关联：`总体设计.md` 4.4、`2610253_前端现状及其修复方案.md`

## 1. 目标

个人中心此前只有全站提交列表，题目页只能看到「最近一次提交」的结果。做题时无法比较历史提交、找回之前写过的代码，也无法判断某次改动是否有效。

本期在题目页补齐：

1. 本题提交记录分页列表：状态、编号、语言、通过用例、耗时、提交时间；
2. 点击查看完整提交详情：代码、编译输出、失败用例输入/期望/实际/stdout/stderr；
3. 一键把历史代码载入编辑器（语言随提交切换），可继续修改或重新提交；
4. 与当前编辑器代码做逐行对比。

不新增后端接口，也不改变判题与提交逻辑。

## 2. 后端复用

已有接口即可满足：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/submissions?problem_id=&page=&size=` | 当前用户提交列表；列表不返回源码 |
| GET | `/api/submissions/{id}` | 当前用户或管理员查看详情，含源码与失败用例 |

`SubmissionSummary` 明确不携带 `code`，避免列表页传输整份源码。前端列表使用摘要，打开详情时再请求完整记录。

权限沿用现有服务层：`user_id` 参数只能等于当前用户，非本人详情返回 403。

## 3. 前端实现

### 3.1 入口

`frontend-vue/src/views/OjPage.vue` 底部结果面板新增第三个 Tab「提交记录」，与「运行结果」「提交结果」并列。

- 首次切到该 Tab 时才请求第 1 页，避免进入题目就发请求；
- 每页 10 条，支持上一页/下一页与手动刷新；
- 未登录时显示登录引导，不发请求；
- 当前题目切换（路由 `id` 变化）时清空列表并让在途请求失效。

提交完成后，如果提交记录 Tab 已经加载过，自动刷新到第 1 页，保证新记录立即出现。

### 3.2 详情与载入编辑器

点击列表项弹出详情对话框（复用 `run-dialog` / `run-record-dialog` 样式）：

- 元信息：状态、通过用例、执行用时、内存、提交时间；
- 编译输出与首个失败用例；
- 完整源码；
- 「对比当前代码」逐行并排对比；
- 「载入编辑器」：若编辑器当前内容与历史代码不同，先确认覆盖；随后切换语言、写入代码、保存草稿并聚焦编辑器。

载入时先修改 `language`，等 `nextTick` 后再写 `code`。这样语言切换 watcher 的草稿恢复与云端草稿读取不会覆盖刚载入的代码；`code` watcher 随后照常把内容写回本机草稿并延迟同步服务端。

### 3.3 逐行对比

新增 `frontend-vue/src/utils/lineDiff.ts`：

- 以最长公共子序列对齐两份代码，输出 `equal` / `removed` / `added` 行，左右行号独立递增；
- 使用 `Uint32Array` 存储动态规划表；
- 当 `左行数 × 右行数 > 4,000,000` 时返回 `null`，前端提示「代码较长，已跳过逐行对比」，不阻塞详情展示；
- 对比左侧固定为历史代码，右侧为当前编辑器代码。

### 3.4 样式

`frontend-vue/src/styles/workspace.css` 新增提交记录列表、分页、详情代码块与对比表格样式；颜色沿用 `--color-success-soft`、`--color-danger-soft` 等既有 token，暗色主题自动适配。

## 4. 验证

- `npm run build`（vue-tsc + vite）通过；
- 手工验证：同一题多次提交 → 打开「提交记录」→ 翻页 → 查看详情 → 载入编辑器 → 修改后重新提交 → 列表自动刷新；切换题目后列表不串数据；未登录时显示登录引导。

## 5. 后续

- 提交记录支持按语言/状态筛选；
- 两次提交之间直接对比（当前是历史 vs 编辑器）；
- 管理员在审计或作弊复核页面查看学生提交代码时复用同一详情组件。
