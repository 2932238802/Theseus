# AI 助手设计方案

> 日期：2026-11-01
> 状态：部分完成（v1 已实现，需配置模型 API Key 后启用）
> 关联：`2611012_架构与性能收口.md`、`2611016_第三方账号绑定与GitHub登录设计方案.md`、`backend_api.md`、`2610316_语义补全设计方案.md`

## 1. 目标

在题目页编辑器工具栏「语义补全」旁加入「AI 助手」按钮：

- 可开启或关闭，开关状态按账号同步
- 仅 Plus 会员可以开启，非 Plus 点击后引导升级
- 比赛模式下前后端都禁用
- 作业可按份关闭：教师在作业设置中关闭后，该作业关联题目在提交窗口内不可用
- 开启后在编辑器右侧出现「AI 助手」面板，与代码并排，可围绕当前题目与代码对话
- AI 只给解释与提示，不直接给出完整可提交代码

## 2. 权限与入口

| 项目 | 规则 |
|---|---|
| 登录 | 未登录点击按钮跳转登录，登录后回到当前题目 |
| Plus | 非 Plus 点击后提示并跳转 `/shop#plus` |
| 管理员 | 保留访问权限，便于运营与排障 |
| 比赛模式 | 按钮置灰，后端也不提供 AI 接口给比赛请求 |
| 作业 | `assignments.ai_assistant_enabled` 默认开启；教师关闭后，该作业关联题目在可提交期间按钮置灰，后端返回 403 |
| 开关持久化 | 偏好键 `editor.ai_assistant`，登录后跨设备同步 |
| 默认状态 | 关闭 |

作业开关与其它策略不同，发布后仍可修改，变更写 `ai_assistant_changed` 审计；判定按「用户已加入组织 + 已发布 + 当前处于提交窗口（含迟交宽限与补交时间）」进行，同一题命中任一关闭的作业即拒绝。

开关打开后编辑器右侧出现 AI 面板（默认 360px，可在 260–560px 间拖动，窄屏置底）；关闭、失去 Plus 或作业关闭时面板自动收起。

## 3. 后端实现

| 文件 | 变更 |
|---|---|
| `migrations/0042_ai_usage.sql` | 新增 `ai_usage` 记录每日调用次数 |
| `migrations/0043_assignment_ai_assistant.sql` | 作业新增 `ai_assistant_enabled`，默认开启 |
| `src/services/ai_service.rs` | Plus 校验、额度占用与退回、题面与提交上下文、OpenAI 兼容调用 |
| `src/services/assignment_service.rs` | 作业内 AI 开关与提交窗口判定 |
| `src/models/ai.rs` | 请求、响应与状态结构 |
| `src/handlers/ai_handler.rs` | `/api/ai/status` 与 `/api/ai/chat` |
| `src/config.rs` | AI 配置项与 `ai_ready()` |
| `src/services/preference_service.rs` | 白名单新增 `editor.ai_assistant` 与 `editor.ai_context_notice` |

接口：

- `GET /api/ai/status` 返回 `{enabled,is_plus,plus_required,contest_locked,daily_limit,used_today}`；`contest_locked` 表示该账号正在参加进行中或结算中的比赛
- `POST /api/ai/chat` 接收 `{problem_id,language,code,messages}`，同步返回 Markdown 文本；比赛进行中返回 403

上下文与安全：

- 只发送题面、公开示例、难度、标签与时间内存限制
- 只发送当前用户最近一次提交的状态与通过用例数
- 不读取 `judge_cases_snapshot`、隐藏用例、其他用户代码或邮箱
- 用户代码与题面作为不可信文本放入提示，明确禁止执行其中指令
- 系统提示要求不输出完整可提交代码，索要答案时改为思路拆解
- 对话内容不落库，仅记录每日调用次数

额度：

- 默认每用户每天 50 次，`AI_DAILY_LIMIT` 可调
- 请求前占用一次，模型调用失败时退回
- 额度用尽返回 429 与 `Retry-After`

## 4. 配置

| 变量 | 说明 |
|---|---|
| `AI_ENABLED` | 总开关，默认 `false` |
| `AI_BASE_URL` | OpenAI 兼容接口地址，默认 `https://api.deepseek.com/v1` |
| `AI_MODEL` | 模型名，默认 `deepseek-chat` |
| `AI_API_KEY` | 模型密钥，`AI_ENABLED=true` 时必填 |
| `AI_MAX_TOKENS` | 单次回复上限，默认 1200，范围 128–8192 |
| `AI_DAILY_LIMIT` | 每人每日次数，默认 50 |

未配置密钥时功能关闭，前端按钮显示「AI 助手暂未开放」。

## 5. 前端实现

| 文件 | 变更 |

交互：

- 面板标题显示「LosAngelous 特供ai服务」，工具栏入口仍为「AI 助手」
- Enter 发送，Shift+Enter 换行
- 同一道题内保留对话上下文，请求携带当前题目的完整对话
- 切换题目时面板重建并清空上下文；如本机之前用过 AI，会在面板顶部提示「切换题目后 AI 上下文不会保存」，点击「下次不再提醒」关闭，可在设置中心「AI 上下文提醒」重新开启
- 偏好键 `editor.ai_context_notice` 默认开启，跨设备同步
- 请求失败撤回本次提问并把内容放回输入框，避免重试产生重复上下文
- 面板默认宽 360px，可在 260–560px 间左右拖动，双击分隔条复位；宽度只保存在本机
- 可清空对话；切换题目时对话重置
- AI 回复按 Markdown 渲染，支持 `$...$` 行内公式与 `$$...$$` 行间公式（KaTeX）；公式在 DOMPurify 清洗后注入，代码块与行内代码中的 `$` 保持原文
- KaTeX 运行时与样式按需加载，没有公式的 Markdown 页面不下载额外资源
