# 安全与限流收口设计方案

> 日期：2026-11-01
> 状态：v1 已实现
> 关联：`2611031_服务器部署方案.md`、`2611012_架构与性能收口.md`、`backend_api.md`

## 1. 背景

认证接口此前没有频率限制：登录、注册、找回密码都可以被脚本反复调用，存在撞库与批量建号风险。跨域使用 `CorsLayer::permissive()`，任何站点都能携带浏览器请求访问 API；Nginx 没有安全响应头；CI 只做编译与测试，不检查依赖漏洞。

本次收口不新增数据表，全部改动在代码、配置与部署文件内，服务器按常规 `git pull` 后重建 API 与前端镜像即可生效。

## 2. 限流与失败锁定

新增 `backend-rust/src/utils/rate_limit.rs`，只依赖标准库：

- 固定窗口计数：`Rule { max, period }`，`check(scope, subject, rule)` 超过上限时返回剩余等待时长。
- 失败锁定：`register_failure` 累计失败次数，达到阈值后锁定一段时间；`lockout_remaining` 查询剩余锁定；`clear_failures` 在成功后清零。
- 过期条目每 60 秒惰性清理一次，避免长期运行内存增长。
- 客户端地址取自 `X-Real-IP`，其次取 `X-Forwarded-For` 第一段，都没有时回退 `unknown`。Nginx 反代已写入这两个头。
- 计数保存在 API 进程内存，重启清零。当前是单实例部署；扩展到多实例时需要换成 Redis 计数，否则每个实例各放行一份配额。

在 `backend-rust/src/handlers/auth_handler.rs` 应用：

| 范围 | 维度 | 配额 |
|---|---|---|
| 注册 | IP | 60 次 / 小时 |
| 登录 | IP | 300 次 / 5 分钟 |
| 登录 | 用户名或邮箱（小写） | 15 次 / 5 分钟 |
| 登录失败 | 用户名或邮箱（小写） | 8 次 / 15 分钟，锁定 15 分钟 |
| 找回密码 | IP / 邮箱 | 20 次 / 小时、3 次 / 小时 |
| 验证邮箱 | IP | 30 次 / 10 分钟 |
| 重发验证邮件 | 用户 | 3 次 / 小时 |
| 重置密码 | IP | 20 次 / 10 分钟 |

要点：

- 校园网常见多人共用一个出口 IP，注册与登录按 IP 的配额都放得较宽，避免学期初集中注册或登录被误伤；真正防撞库的是同一账号连续失败 8 次后的锁定。
- 用户名与邮箱统一转小写作为锁定键，避免用大小写变换绕过。
- 只有 `InvalidCredentials` 计入失败次数，数据库错误等不会误伤账号；登录成功后清零。
- 超限统一返回 `429`，`Retry-After` 为剩余秒数，文案为 `请求过于频繁，请稍后再试`；锁定状态文案为 `登录失败次数过多，请 N 分钟后再试`。
- 重发验证邮件保留原有的 60 秒数据库冷却，内存限流是第二道约束。

## 3. CORS 白名单

- 新增 `CORS_ALLOWED_ORIGINS`，逗号分隔，配置在 `Config.cors_allowed_origins`；拒绝 `*`、缺少协议前缀和含空白字符的值，末尾 `/` 自动去掉。
- 留空时 `routes::cors_layer` 返回空 `CorsLayer`，即不发送任何 CORS 响应头，浏览器只允许同源请求。开发环境的 Vite 代理与生产环境的 Nginx 反代都是同源，默认配置不受影响。
- 配置白名单后只放开列出的站点，允许方法为 GET / POST / PUT / DELETE / PATCH / OPTIONS，允许头为 `Authorization` 与 `Content-Type`，预检缓存 10 分钟。

## 4. Nginx 安全响应头

`frontend-vue/nginx.conf` 增加：

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: SAMEORIGIN`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(), microphone=(), geolocation=()`

未启用 CSP：Monaco 编辑器依赖 blob: worker 与内联样式，收紧后编辑器无法运行，后续需要单独评估。

nginx 的 `add_header` 只在当前层级没有 `add_header` 时才继承父级，而 `/uploads/`、`/assets/` 与 `/` 都有自己的缓存头，因此这几个 location 重复声明了同样的安全头，文件中已注释说明。

## 5. CI 依赖审计

`.github/workflows/ci.yml`：

- 后端 job 在测试之后安装 `cargo-audit`（`taiki-e/install-action`）并执行审计，发现未豁免的 RUSTSEC 漏洞时失败。
- 2026-11-07：锁文件升级 `rustls-webpki` 至 `0.103.16`、`webpki-roots` 至 `1.0.10`，修复 RUSTSEC-2026-0382 与 RUSTSEC-2026-0381。
- SQLx 关闭默认特性，显式启用 PostgreSQL、迁移与宏等所需特性。其可选 MySQL 依赖仍会把 `rsa` 保留在锁文件，但 `cargo tree --locked --target all --invert rsa --prefix none` 确认所有目标平台的实际依赖图均未启用它。
- RUSTSEC-2023-0071 暂无修复版本，仅对此条使用 `cargo audit --ignore RUSTSEC-2023-0071`；这不代表 RSA 漏洞已修复。CI 在审计前检查上述全目标依赖图，若出现 RSA 依赖路径则失败，要求移除例外并重新评估。其他漏洞仍照常阻止 CI。
- 前端 job 在构建之后执行 `npm audit --omit=dev --audit-level=high`，审计生产依赖，高危及以上失败。
- 2026-11-07：`follow-redirects` 升级至 `1.16.2`；保留 Monaco `0.57.0`，通过定向 `overrides` 将其固定的 DOMPurify `3.4.15` 替换为项目直接依赖的安全版本 `3.4.17`，不使用 `npm audit fix --force` 降级编辑器。官方 npm 源生产依赖审计为 0 个漏洞，类型检查与生产构建通过。本地镜像源不支持审计接口时使用 `--registry=https://registry.npmjs.org`。
